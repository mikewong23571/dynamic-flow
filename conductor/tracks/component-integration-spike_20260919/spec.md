# 组件接入摩擦 Spike

类型：Chore / Technical Spike。

## 授权与范围

用户要求先评估选型摩擦，安装依赖，以非常简单的 example 进行一轮 Spike，并把结果作为 track 输出。此指示包含建立与执行 track；不再重复初始化访谈。

本轮为选型实验，不是产品实现。实验安装不自动代表所有候选正式入选。

## 要回答的问题

1. assistant-ui 如何接入 Pi 的消息、工具事件与取消；有哪些需要手写的衔接？
2. React/Vite、基础控件、可调整分栏、树、图、表格、编辑器及结果呈现是否能共同安装、编译、运行？
3. 样本选择在排序、过滤、视图切换后能否稳定；哪些组件需要显式身份映射？
4. Monaco 编辑与 Diff 在动态容器中是否正常，如何配置本地 worker？
5. 哪些能力适合直接采用，哪些属于业务组合，哪些暂不值得引入？

## 实验设计

- 一个独立 example 页面，少量 fixture，不创建正式产品模块或通用框架。
- 使用真实 npm 包及锁文件；记录准确版本、安装/类型/构建/浏览器问题及解决办法。
- 首选实验组合：React + Vite + TypeScript；shadcn 风格基础控件；assistant-ui；react-resizable-panels；React Arborist；React Flow；TanStack Table；Monaco；Markdown/JSON 呈现。
- 后端只为接入实验提供最小 Pi 会话和 HTTP/SSE；允许在模型 provider 边界使用确定性响应。若 SDK 接入不成立，保留具体失败证据，不能仅以模拟前端宣布通过。
- Chat 演示流式文本、工具内容及取消；固定选中的样本上下文。
- Work Map 以目录和关系图两个小例子比较，不实现 AST 分析。
- 表格演示稳定多选、筛选、排序；Spike 只演示结果对齐与两个独立采用动作。
- 不主动读取已有用户凭据；不以真实模型质量为本轮验收条件。

## 验收与交付

- 可通过文档中的实际命令安装、启动、类型检查、构建和复跑实验。
- 浏览器操作覆盖主要接入点，保存截图和结构化检查证据。
- 针对有状态的事件适配及选择身份设计少量有意义的测试，不为静态布局堆测试。
- 输出 results.md：每个选型的结论、摩擦级别、实际问题、所需业务代码、未验证项及推荐组合。
- 区分文档判断、模拟数据验证、真实 SDK 执行和真实模型调用。
- 技术状态同步到 conductor；最终产品界面和正式版本定案留给后续讨论。

## 不做

完整 Workbench、通用运行框架、完整持久化、任意程序解析、模型质量评测、安全/权限/隔离、部署、多租户、完整设计系统。不会为了比较候选搭建两套完整应用。
