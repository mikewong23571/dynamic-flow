# 筛选与搜索的注意力分配及空间合同

用户要求以持续推进工作的价值安排注意力，确认采用状态左、搜索右，并明确各自占用空间。本次取代上一轮toolbar-followup的“就近排布”取舍；此前防止状态无限拉伸的修正保留。

## 已实现合同

- 左侧状态宽160px；右侧搜索区总宽320px，包括输入框和提交按钮；两者高28px。
- 筛选左边缘、搜索右边缘分别对齐工具栏内容边缘，中间剩余空间留白。宽度来自Management.css组件内的--toolbar-filter-width / --toolbar-search-width；调用方通过NativeSelect公开包装class引用，字段默认fill不变。
- 760px及以下分两行：筛选仍160px，搜索区占满容器宽；更复杂子项筛选空间不足时也自然换行，不挤压搜索。删除子项的独立520px/grid/右对齐例外，统一由共享工具栏安排。
- 清除搜索属于搜索框，使用输入框内的具名图标按钮，出现时不挤压输入宽度，清除后焦点回输入。DOM顺序与视觉一致：筛选、搜索输入、清除、提交。
- 仅改共享列表工具栏、工作项调用/局部布局和控件指南，未改查询/API/业务状态逻辑。

## 本轮验证

旧实现新尺寸/排列检查失败，状态实际118px，非新合同160px，证据red.txt。改后5条浏览器通过（roots两尺寸、列表呈现两尺寸、流水线搜索/归档1），其中roots加入两端对齐、160/320/28尺寸、760分行满宽无溢出、清除按钮归属/草稿宽度稳定/焦点验证，现有真实搜索/状态/分页与子项操作保留。

typecheck:app、check:styles、build、变更文件Prettier和diff检查通过。实际查看1440/1024/760截图以及4336独立合成预览的搜索激活截图；手动检查320/160宽及清除焦点通过。所有交互测试使用独立fixture或独立4336预览，没有修改托管用户数据。证据见evidence/toolbar-placement。

本轮是当前产品布局选择，不声称“筛选左、搜索右”为所有设计系统的硬性要求。组件README记录实际尺寸与响应式合同，方便后续复用。
