# 当前原型合并与4320切换评估

2026-10-29。只做审查、临时数据验证；没有合并、提交、部署或操作flowcraft.service。

## 判断

可作为下一版原型的合入候选；当前不能宣称可无感替换4320。需要区分数据读取、业务续做与正在执行任务的切换。最后导航增量是39个源码/测试文件；整个独立原型对托管目录的比较为164个差异（包含指南、测试和依赖），不是仅合导航补丁。

托管服务WorkingDirectory为主目录，ExecStart为pnpm dev，前后端watch会加载主目录源码修改。往主目录写入代码本身就可能上线，不能把复制/合并当成无影响操作。当前仍为独立工作区未提交成果，主目录已有未提交改动需对账保留。

## 实际旧数据读取检查

在临时目录复制work.json/definitions、工作项和批次记录；未调用createApplication、onServerStart、recover、模型或任何业务命令。原始托管data未改。

- 数据采样时有10个方法、16个定义版本、1117个旧工作项；1112个有workflowId，451个有运行历史，1089个有receivedInputs；均无compositionWorkId和新交付绑定。
- 16个定义都能读取；新旧checkDefinition结果完全相同。1个已有文件节点未选择文件，旧版也报告同一问题。
- 抽查旧根项和带接续输入的旧子项，workflowId/运行/receivedInputs保留，workspace可读；work/uiPlan/deliveries均为空，未自动变成新工作空间。
- 保存状态中有2条running运行及1个running自动批次。本次未判断其是否仍在实际推进，切换前需对账。启动代码仍将运行中记录标interrupted；batch recover仍会调度running批次，不能承诺不停任务切换。

需要完整前后端与锁文件依赖（json-render/lang-core等）一同准备；只复制前端或只替换端口不足以交付新工作项。
