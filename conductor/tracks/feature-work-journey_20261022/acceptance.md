# 以页面操作与实际输入验收

状态：五个故事的确定性页面路线1440/1024、真实模型反馈主线、最终两尺寸独立实看已通过。CVE额外合同调整/对象接收及scope节点实际完成已验证；未执行完整影响调查，业务仍open。按钮名称表达操作意图，可按设计微调；入口和能力不能只存在于 API。以下五个故事连起来执行，不把十几个独立弹窗截图当作闭环。

## 固定的简单材料

工作目标：整理客户反馈，分类并输出有原文依据的改进建议。

| 材料 | 输入正文 |
| --- | --- |
| F1 | 界面很顺手，但导出报告经常失败，影响交付。 |
| F2 | 希望支持批量导出，逐条操作太慢。 |
| F3 | 搜索比以前快很多，团队很满意。 |

完成条件：已分析本次明确选择的反馈；报告引用对应原文并说明未覆盖范围。本次故意只选择 F1/F3，F2 留存但不处理，便于判断是否把累计材料全部带入了执行。

方法 A：逐条分类，输出保留原文与分类的对象，后接“汇总建议”步骤。方法 B：读取明确选中的分类对象，生成报告。它们是测试数据，不是产品内建类型；同一路线再用材料调查／影响分析进行真实业务复核。

## 故事 1：我只有目标和材料，也能开始并得到做法

| 页面／动作 | 用户输入或选择 | 可观察结果 |
| --- | --- | --- |
| 工作项列表 → 新建 | 填标题／目标，添加 F1/F2/F3；暂不选流水线 | 能保存并进入这件事，页面有明确的开始处理入口；不自动选第一条方法或启动运行 |
| 工作项 → 生成做法 | 描述“逐条分类，再汇总；每条结果保留原文依据” | 进入带当前事情上下文的现有 Assistant／画布；实际生成可修改的方法 A，不要求再次粘贴材料 |
| 查看／修改步骤 → 返回工作项 | 检查材料入口、分类和汇总，选择保存的版本 | 返回原工作项，方法选择可见，目标与材料保留；未保存草稿有明确处理入口 |

断言：生成失败保留事情和输入，可重试；真实模型生成与确定性 fixture 的验收分别记录。用户可直接选择现有方法而跳过生成，不必走另一套复杂向导。

## 故事 2：我明确选择这次处理什么

| 页面／动作 | 用户输入或选择 | 可观察结果 |
| --- | --- | --- |
| 工作项 → 运行流水线 | 选择 A 的版本；勾 F1/F3，取消 F2；查看已选正文 | 执行前能看见方法、版本、两条输入和正式处理身份 |
| 启动 → 查看运行 | 无需再去“更换方法”修改工作项 | 新运行归属当前工作项；固定输入只有 F1/F3，结果能回到对应原文 |
| 运行中补材料／修改草稿 | 增加 F4 或改下一版做法 | 原运行输入、版本不变；不能把新材料悄悄塞进本轮 |

断言：既检查页面“输入与依据”，也记录 NodeExecution 的实际上下文；F2 不得从 workItem.materials 或方法样例材料旁路进入。启动错误保留选择，不产生虚假的成功运行。实际停止／失败可查看已完成内容并找到下一步。

## 故事 3：我从具体问题试验改法，再用选中的结果完成汇总

| 页面／动作 | 用户输入或选择 | 可观察结果 |
| --- | --- | --- |
| 分类成果 → 从此结果改进 | 对 F1 提出“同时有赞扬和问题时归为问题，保留两方面依据” | 定位对应方法版本与步骤，已有草稿不静默覆盖 |
| 试运行／比较 | 固定 F1/F3 同输入 | 当前与候选可对照；试验不改业务进展；真实模型已正确时可以围绕更明确要求试验，不伪造错误 |
| 选择可用成果 → 用这些输入处理 | 选候选 F1 与旧 F3；选择 A 中“汇总建议”，明确正式处理 | 只执行该汇总步骤，分类不重跑；真实输入恰为两条所选成果，来源版本可查 |
| 查看报告 → 返回 | 阅读、追溯 F1/F3、返回 | 新运行明确标示“单步骤正式处理”；其成功不冒充整个 A 重新执行，也不自动结项 |

断言：可不采用候选而使用它的结果。若选了旧 F1 和候选 F1，页面提示版本重复并允许改选；不阻止两个正常不同输出只因共享上游材料而被误判。单步骤正式处理是新增明确动作，旧单节点试运行／重试继续为 preview。

范围取舍：本轮不做任意后续子图自动续跑。要继续多个步骤，选择或编辑一条明确的完整方法；不能把单步骤动作命名为“自动完成余下流程”。

## 故事 4：我把成果交给另一种方法，仍在同一件事中工作

| 页面／动作 | 用户输入或选择 | 可观察结果 |
| --- | --- | --- |
| 工作项成果 → 用于下一次处理 | 选择上述分类成果；选方法 B 和版本 | 同一启动入口预填成果，显示实际值与来源；无需“先补充为证据”或复制 ID |
| 检查输入 → 启动 | 明确输出端口／输出项，确认 B 接收对象 | B 得到原对象，不是偷偷转成 JSON 字符串；启动成功后产生属于当前工作项的新 Run |
| 查看报告 → 查看来源 → 返回 | 无额外业务输入 | 从 B 回到 A 的实际结果，再回到原报告；两次运行历史均保留 |
| 方法 B 的运行记录 | 打开对应运行 | 能找到这次执行及关联工作项；无工作项试运行也有自然的行，不伪装成业务工作项 |

断言：如果 B 只收字符串，则启动前明确拒绝对象输入并保留选择；用户可通过现有 Assistant／配置修改 B 的合同与消费步骤再运行。不新增自动类型转换平台。CVE 现成 B 确实存在这一不匹配，真实验收必须展示处理过程，不能改测试为“字符串也算结构化交接”。

## 故事 5：我按依据完成事情，下次仍能找回

| 页面／动作 | 用户输入或选择 | 可观察结果 |
| --- | --- | --- |

| 新证据 → 重开 | 填重开原因、补充材料 | 保留此前结项依据，再按故事 2 选择新一轮输入 |

断言：另一个工作项复用 A/B 时不串业务材料。独立“直接输入”和方法试验仍可在不建工作项的情况下使用。

## 必须保留的短回归路线

- 等待事件：配置等待→显示原因→发送匹配事件→同 Run 继续；中断恢复和新一轮执行分开，不按报告中的“缺材料”文字假造等待。
- 使用来源不可读／输入不兼容／调用失败：展示真实错误，保留当前选择和已完成成果；不增加无限重试或假成功。
- 两个入口打开同一成果与过程，查看的是同一固定 Run；返回保留选择和阅读位置。无重复面包屑和成片介绍文案。
- 1440×900、1024×768 实看；现有大结果按需渲染与切换性能不退化。分别记录首开和回访，不比较不同终点的耗时。

## 证据标准

每条故事记录：页面入口、用户实际输入／选择、发出的动作、固定输入／真实节点调用、可见结果、来源和截图。临时隔离数据可由 fixture 准备方法与材料，但被验收的选择、修改、启动和交接必须从页面操作；不得用 HTTP 预先完成关键步骤后只截图。

确定性模型 fixture 验证交互与数据边界；真实模型单独验证生成、修改、执行。真实业务调查未决是允许结果，不能为“故事通过”编造结论。现有本地用户数据只读调研，未来写入验收使用独立目录和私有 HTTP 服务；真实模型用明确测试工作项，保留证据，不清理用户数据。
