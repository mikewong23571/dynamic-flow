# 工作项内明确执行、成果交接与持续完成

## 目标

用户在页面完成[五个连贯故事](acceptance.md)：带目标和材料开始／形成做法→明确方法与输入运行→试验改法并用所选成果汇总→交给另一方法→按依据完成与重开。每个故事以页面实际提供的操作、用户输入与执行实际收到的内容为验收条件。

本 track 的范围是这些操作的贯通，不是重新实现已存在的画布、运行器或重新设计所有管理页面。支持一般文本／结构化输出，不根据 CVE、客户反馈字段或方法 ID 分支。

### 本轮具体取舍

1. 一个直接的“准备本次执行”组合界面，工作项启动与成果续做复用它；包含方法／版本、整条方法或指定单步骤、分端口输入选择及预览。单入口只有一份输入列表，多入口按已有端口列出；不造 schema 表单语言／可视化转换器。
2. 本次材料与成果显式选择，成果保留实际类型与来源。累计材料是候选，不自动全部进入下一轮；目标等必要业务上下文明确保留。
3. 正式续做首版只支持完整方法或一个明确的静态普通处理步骤（Agent／Function）。既有 scope 已能表达，不增加任意子图模式；后者明确显示“单步骤正式处理”，不自动执行下游。动态生成子步骤、等待／里程碑的直接单步正式调用不纳入本次新增入口，原有完整流程能力保留。
4. 单步骤正式处理需要有真实、显式工作项身份和本次输入；普通试运行／比较／重试保持 preview。允许被正式调用的普通 Agent 报告本次进展，仍不自动确认条件或结项；相应 full/commit 守卫按实际语义同步，不只改一个字段。
5. 创建可以暂未选择方法；复用已有 Assistant／画布形成做法，保留业务上下文。编号自动生成并允许提供外部编号；完成条件可以后补，结项仍要求明确条件及依据。
6. 结果属于原 Run；工作项记录执行归属与明确的使用。为工作项执行不代表所有输出已被认可。当前工作项的历史成果（含跨方法和试验成果）是首版可选范围；不建设跨工作项搜索和成果库，但引用结构不把来源业务身份当成目标业务身份。
7. 成果名称独立表达内容，优先使用明确输出标签；缺省给出可理解的输出名及来源步骤，不猜测业务含义。实际节点配置仍使用动作名称；不硬编码材料／报告二分法。

## 非目标

- 不引入流程市场、制品中心、通用对象仓库、事件总线、权限与生产治理、自动选择业务下一步。
- 不做任意子图截取／依赖重算／隐式缓存续跑；本次单步骤汇总足以完成连续故事，多步骤用明确完整方法。
- 不增加自动 JSON／文本转换器；类型不兼容保留输入、指出合同问题，用户通过既有编辑路径调整方法。
- 不改写旧 Run、旧结项历史、真实模型结果，不批量清空或修复用户数据。
- 不把 preview 成果自动升级成正式执行，不把 Run 完成当作业务完成；不增加新模型框架、MCP 实现或新依赖。
- 用户已授权全部闭环；未完成任务保留待办，不以局部通过宣称五个故事贯通。

## 影响域与验收

以 acceptance.md 为用户验收规格，research.md 为事实与取舍依据，plan.md 为实施待办。创建、输入选择、成果续做必须前后端同步；正式单步影响 runs、assistant、work-items 的报告校验，不得局部放开。

启动最小输入：目标工作项（正式处理必填）、目标方法和保存版本、范围 full 或明确 node、按入口排列的材料／成果选择。输出：真实 Run 引用及冻结版本／输入／业务归属；错误：输入不匹配、来源不可读、未决运行、不可运行版本时保留表单并给出可修正反馈。用户无须输入内部 ID；引用由页面与服务端完成。

旧无参数 item.run 的兼容行为显式保留用于旧调用方（当前方法、累计材料），新页面始终提交明确选择；不可让新字段改变旧历史。缺省 workflowId 的旧外部读者需检查可选性；新建无方法工作项不制造空字符串伪方法。

采用渐进交付：每次完成一个可用的小操作，逐步接近完整故事；不要求一次覆盖整个阶段。验证按实际影响选取，先检查本次行为及直接相邻模块；页面变更实际操作，涉及共享布局再覆盖两尺寸，涉及执行语义再扩大相关回归。整条故事与真实模型在相应路线接通后验收，不作为每次增量的统一门槛。模型耗时和业务资料不足不算 UI 失败，但不能用 fixture 冒充模型真实完成。


## 增量1A冻结接口

`POST /api/items/:id/actions` 的 `run` 可携带 `{definitionId, materialIds}`：当前方法已保存版本和当前工作项材料身份。服务端在原launch串行路径解析材料，拒绝空选/重复/缺失引用，按显式请求顺序生成冻结WorkItemInput；原HTTP接线从该范围生成Run.inputs，运行器已有上下文路径同步获得相同材料。无参数旧调用仍使用当前方法及累计材料。

页面为当前方法单入口提供准备执行，短材料行按需查看正文；新增材料不自动加入、版本固定为打开时显示的保存ID，失败保留选择。1A不提供更换方法、多入口分配或成果输入，留给后续增量。

### 实施反例修订：从成果改进时保留原始试验输入

输入：从工作项生成的方法没有 Work 样例材料，用户从一次分类结果进入候选改进，随后选原始反馈比较。原“从此结果改进”只切版本／节点，未交接该运行的原始样本与业务快照，因此无法试验。

纳入最小范围：client state 的候选起点与样本选择、既有试验／比较 HTTP/trials 接线。使用所选结果对应的冻结节点输入和明确来源 Run；不得用分类输出冒充分类原输入，不覆盖方法样例。服务端从真实来源读取业务上下文，试运行和比较保持 preview。验证故事3从页面选择原始样本比较并正式使用候选产物，不增加样本库或新试验模型。

## 当前实现合同（完整路线）

- 输入：`WorkItemRunSelection` 明确 workflowId/definitionId/scope 与按端口的 inputSelections；每项为材料ID或 workId/runId/resultId/port/index。旧materialIds与无参数run兼容，不能两套选择同时提交。
- 解析：`work-items/run-inputs.ts` 只读真实输出/原文并保留JSON类型，校验端口、输入合同、重复引用与同实例不同版本。`work/run-samples.ts` 供试运行/比较解析真实 result.input，区别于成果输出。
- 输出：Run固定inputs、workItem材料、inputSources及必要sampleSource，启动成功后才关联本次方法；失败保留页面选择、不创建虚假Run。
- 作者：显式createMethod/prepareAuthor/authorFromResult固定当前authorContext/authorInputs，不改Work样例；inputContracts进入作者工具schema；共享方法再次编辑使用当前明确业务上下文。
- 正式单步：仅工作项入口为静态Agent/Function内部设置commitScope=node。普通旧node、retry和comparison保持preview；report_progress允许真实正式同节点，里程碑full/commit不变。
- 条件：可补充/改文字，定义变化清空旧确认与引用；CriterionReference保存精确来源，旧结项快照不变。
- 页面：方法结果按Run列行，业务身份为关联；成果按声明输出逐端口/项呈现真实单值，名称与来源步骤分开。列表/成果/过程复用原返回和缓存，没有额外面包屑或通用表格平台。
