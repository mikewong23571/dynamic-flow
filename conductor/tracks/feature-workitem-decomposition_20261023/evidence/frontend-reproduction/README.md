# 从前端原文到子项的真实复现

2026-10-23，用户明确要求通过前端复现。当前应用4320，使用本地Playwright浏览器操作；以下所有创建/保存/模型提交/运行/建项均由UI触发，直接HTTP只用于读取和核对最终冻结输入。未修改应用源码。

## 入口与结果

- 工作项：`DEMO-UI-SPLIT`，标题“示例 · 从原始反馈开始拆分”。
- 流水线：“示例 · 原始反馈拆分”，由页面Assistant真实生成并采用，使用GLM high。
- 原始输入是一条材料：客户甲反馈导出月报失败，客户乙反馈订单搜索无结果。无预置received候选。
- 真实运行生成两条候选；运行成功时尚未建项。页面打开“建立子项”，将标题加“示例”标记，点击“建立所选子项”后实际保存两个子项，各带对应原文及完成条件。
- 打开子项材料可读，返回并刷新后两个子项仍存在。两项调查尚未完成，没有伪造调查结论或业务结项。

## 用户复现步骤

1. 工作项→新建工作项，填标题、目标和初始证据，暂不选方法。
2. 初始证据作为同一条材料粘贴：

   客户甲反馈：导出月报时页面提示失败，无法取得报表。客户乙反馈：按已知订单编号搜索没有结果，但订单列表能找到该订单。

3. 保存后进入证据材料→拆分工作→生成拆分方法；处理要求填“将所选客户反馈拆成可独立调查的问题；每项保留对应原文，给出目标和完成条件。只整理问题，不调查原因。方法应适用于后续新反馈。”。
4. 进入Assistant→发送修改→等待真实生成→采用做法→返回工作项。
5. 运行流水线，确认本次仅选原始材料→开始处理1项输入。
6. 完成后在成果与过程点击建立子项，检查/修改/勾选候选→建立所选子项。
7. 子项页查看新项，进入证据材料检查对应原文。

已有方法复用：第1步直接选择“示例 · 原始反馈拆分”，然后从第5步开始，不必每次生成一条新方法。

## 证据与限制

- `01`到`11`截图对应创建、拆分入口、生成要求、Assistant、方法保存、实际输入、真实候选、确认窗口、创建回执、子项列表、子项材料。
- `frontend-reproduction.webm`为此次实际浏览器录像，包含模型等待；`ui-writes.json`记录浏览器发出的业务动作，`result.json`保存真实输入/输出、模型high和子项来源。
- 本轮是浏览器实际操作验收，不是项目自动测试套件的新一轮全量回归。已查看确认窗口及子项列表截图。
- 页面“下一步”仍展示此前Agent报告的等待审核建议；创建子项后该文本未自动改写。真实子项身份、材料及回执以子项列表/固定输出为准，此处保留观察，不把报告文字当作当前动作事实。
- 示例按用户授权留在正式应用，全部新工作项/方法标题标记示例。此前DEMO-FEEDBACK仅为已保存清单建项演示，与本次从原文开始的路线区分。
