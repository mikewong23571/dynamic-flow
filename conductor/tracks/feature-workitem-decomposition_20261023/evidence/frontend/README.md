## 实际页面路径

- 创建工作项不选择类型。可以添加子项，勾选父项材料或已收到的结构化输入；父子返回保留条件草稿、历史运行焦点、页签、列表筛选和读位，不常驻所有详情。
- 子项默认入口根据实际子项存在与否决定；用户主动选择后不会被后台数据切换。有子项而无独立条件时显示子项完成数，进入整体确认，不显示0/0条件。
- 候选清单由固定成果或自动节点保存输入读取。服务端分页，仅当页挂载编辑控件；用户编辑目标/范围，批量建立或搜索同父已有项关联。目标冲突需明确关联，成功回执持久；从已有项显式补充本次候选材料，重复请求不会重复追加。
- 拆分和汇总保留各自业务意图，明确选方法或通过原 Assistant 生成，避免把父项当前拆分方法误用于汇总。用户无需编写候选 JSON 协议。
- 准备输入默认接续明确的值。声明的仓库/分支等标量字段可直接修订；新 received ID 代替本次选择，原来源和旧 Run 不变。打开期间新增材料可见但不自动勾选。
- 多产物先选具体 port/index，再引用条件或继续处理；跨项既有结果可直接用于确认。来源返回展开对应产物。
- `create-items` 复用画布创建/连接/配置，固定输入问题清单、建立到当前工作项、输出真实回执；试验不写工作项。回执入口为“查看子项”，普通成果使用“拆分工作”。
- 子项列表提供直属/范围待办/全部/排除、查询、分页、稳定轮询行序；批次准备只要求修补缺口。启动窗口2按持久状态与在途请求计数，等待/中断释放；暂停不取消已有运行。批次状态与已提交标记随当前工作项浏览状态保留。
