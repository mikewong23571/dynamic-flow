# 工作项方案校验

## 目标

1. Agent 的 check_flow/check_ui_plan 能接收未完成草案，返回紧凑、可定位诊断，不在工具协议层回显整份草案。保存仍严格。
2. check_workspace 只读联合检查当前或候选定义、真实已选输入、界面/动作、指定实际 Run 与发布数据；分别报告 canExecute/canPublish 和未验证项，绑定当前修订/定义/计划。
3. 与页面使用同一校验与输入解析，补足根输入样本形状反馈；无真实输出时不宣称交付已验证，不运行模型或业务动作。
4. 薄桥接现有直属子项阶段成果发现、预览与明确选择，使缺输入时 Agent 可修正；不自动选择最新成果。
5. 临时数据/真实模型验证检查—反馈—修正—再检查；在独立实例完成后部署4320。

## 非目标

不建第二运行器、通用规划/迁移平台或 CVE 特判；不自动恢复旧批次、重跑真实研究、确认条件或结项。方案校验不判断业务事实和最终审计是否成立。

## 改动点

- src/server/work-items：只读方案联合检查，复用输入/流程/UI/交付检查；明确子项输入桥接。
- src/server/assistant/workitem.ts：草案工具参数、check_workspace 与子项成果工具、反馈协议及调用指引。
- src/shared/workitem-composition.ts：实际 HTTP/工具共用的检查回执类型。
- src/server/index.ts：同源只读检查和子项来源选择动作。
- tests：真实文件/HTTP及工具回路的失败、只读、修订与固定来源用例。

## 影响域

工作项作者、流程校验、来源解析、界面声明、执行/发布前置合同。保留原保存/执行/发布防线。用户已明确同意提供校验工具；沿用仓库现有 tracks/metadata 与已授权独立工作区，不迁移Conductor骨架。
