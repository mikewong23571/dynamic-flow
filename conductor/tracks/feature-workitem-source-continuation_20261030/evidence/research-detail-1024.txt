    uid=21_105 StaticText "事实：CVE-2019-20636 是 Linux 内核 input 核心的越界写（CWE-787），影响 drivers/input/input.c，官方描述为“5.4.12 之前”。成因是 input_default_setkeycode() 把驱动键码表中读出的旧键码 *old_keycode 直接当作位偏移做 __clear_bit/__set_bit(dev->keybit)，input_set_keycode() 又用它对 dev->key 做 __test_and_clear_bit；当表中含大于 KEY_MAX(0x2ff) 的非法值时位偏移越出位图，破坏 input_dev 内外相邻内存。修复提交 cb222aed03d7（"Input: add safety guards to input_set_keycode()"），已确认被回移到 5.4.12（commit 39f711b69799，同批还含配套的 "HID: hid-input: clear unmapped usages"）。受影响区间按 NVD CPE：<3.16.83、3.17–<4.4.210、4.5–<4.9.210、4.10–<4.14.165、4.15–<4.19.96、4.20–<5.4.12；Debian 修复版本为 3.16.84-1/4.9.210-1/4.19.98-1/5.4.13-1。触发条件：受影响版本内核 + 某个 input 设备键码表已含 >KEY_MAX 的旧值（典型为畸形 HID report descriptor 造成的非法 usage）+ 本地对 /dev/input/eventX 有写权限者用 EVIOCSKEYCODE(_V2) 覆盖该表项；因此 CVSS 3.1 为 6.7 MEDIUM（AV:L/PR:H），与扫描原值一致，不可远程触发。版本核对：扫描组件 linux-v6.13.4 远高于 5.4.12，且已直接读取 gregkh/linux v6.13.4 的 drivers/input/input.c，其中同时存在 ke->keycode > KEY_MAX 的入口校验、old_keycode > KEY_MAX 的 dev_warn 分支和 *old_keycode <= KEY_MAX 守卫（v6.13 与 v5.5-rc6 交叉核对一致），故该命中在代码层面不成立，判定为版本匹配误报（前提是该源码确为上游 6.13.4 的 input.c）。建议：无需为 CVE-2019-20636 升级内核；若要闭环，在项目实际源码中 grep "got too big old keycode"/"*old_keycode <= KEY_MAX" 确认守卫存在，并核对组件版本号来源。未知：扫描件仅有 basename "input.c"，未提供仓库路径与真实源码副本，无法确认其即上游 input.c 或确为 6.13.4；扫描给出的 v5.5-rc6 与官方 before 5.4.12 的口径差异及其来源未澄清；NVD 4.19 上界（<4.19.96）与 Debian（4.19.98-1）不一致，未逐发行版核实；项目是否实际启用 input/evdev、是否存在可触达的非法键码表设备与业务暴露面均无证据，故不将“存在该包”等同于可利用。"
