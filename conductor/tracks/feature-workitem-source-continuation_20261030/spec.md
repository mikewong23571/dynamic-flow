# 工作项来源接续与方案修复

## 目标

修复用户已确认的四项审查问题：批次真实成果与待办承接；事实采用有歧义时显式处理；记录身份不因相同业务键冲突；核查条件不足形成可见缺口。应用仅补足通用来源发现与明确选择能力，具体业务方案由实际工作项Assistant保存。

## 非目标

不自动采用最新结果、不改旧Run、不重跑已有队列、不增加CVE特判、不建设增量调度或另一个执行器；不改变完成条件和人工审计口径。

## 改动点

- 工作项来源范围：默认直属，显式descendants时沿父链检查有效范围；保存精确来源，排除祖先分支、跨根、循环和失效来源均拒绝。
- Assistant：复用阶段成果发现/预览/选择，暴露明确后代范围及分页业务状态；输入包装保持{item,outputs}。
- 当前业务方案：修正事实匹配、身份与可见缺口，沿用正式固定研究/核查方法与develop约定。

## 影响域

共享输入选择合同、work-items来源解析、HTTP与Assistant同源工具；相邻阶段交接和方案检查。最小输入为当前根项、明确范围及固定OutputReference，输出为只读候选/已绑定来源；无效范围/来源明确报错。例：根→分组→研究项，只有显式descendants可绑定研究项成果；排除分组后不得继续使用其来源。
