## 真实反例推动的修正

1. 真实供应商拒绝复杂 tuple/Record 工具 schema：保持同一 IR，以供应商支持的对象/数组工具定义接入；实际作者成功后才计入闭环。
2. 作者曾保存非法输入/输出节点，污染候选起点：作者保存前做完整语义校验；非法提案可检查但不成为草稿；人的未完成编辑仍可保存并清楚阻止执行。
3. 报告期望 string，但提示强制 JSON：按输出类型分别要求 Markdown 或结构化 JSON；不把对象悄悄转字符串。真实失败保留，修复后只重试所需输入成功。
4. 材料 UUID 不便阅读：新材料工作内顺序 M01…，旧引用保持，追加和并发编号有测试。
5. 逐字依据为字符串/嵌套对象时继承原材料身份；跨材料错误引用拒绝，不能只检查任意材料中出现过该句。
6. 画布自动 fit 让字过小：新布局默认可读缩放、折行布局，旧保存视图尊重用户；提供平移缩放。实际手调不改语义。
7. 结果 Markdown 表格显示原始管道符：复用 remark-gfm，表格容器水平滚动，保留报告复制。
8. 历史结果起候选不应无条件要求替换：仅与已有未采用候选不同源时要求明确选择。
9. Assistant 工具细节、保存状态与上下文区分；固定请求范围、真实失败重试、停止和已保存卡片，避免仅靠最终文字宣布变更。
10. 未保存修改仍显示比较有效：将本地 dirty 纳入过期状态，禁用未保存试验，并提供放弃未保存修改。
11. 工作库重开同一 ID 清空了 snapshot、却不触发加载 effect：保留同工作快照与本地修改，主动刷新元数据；专项真实浏览器回归覆盖。
12. 验收期间热更新改变 hook 结构曾出现开发态空页；刷新恢复，最终用稳定代码/构建和重开检查。一次回归正逢 API 重启取空响应，未删断言，稳定服务重跑通过。

## 边界

有限无环工作流、单工作同时一条执行/比较链；逐项目前顺序执行。支持文本材料、只读 JS 定义、明确结果续做；没有任意代码编辑、无限循环、跨工作模板或进程中断自动续跑。数据和工作区模型设置在被 Git 忽略的 data/ 中。模型输出语义仍须人检查，比较不自动宣称候选更好。

大型数据量、跨供应商所有模型参数组合以及视觉偏好不是本轮证据能够保证的范围。没有使用 mock 把真实模型不可用伪装为成功。
