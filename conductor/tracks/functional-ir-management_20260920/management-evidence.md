# 管理页交付证据

## 实现

- 接入官方 shadcn new-york-v4 Radix 源码；修正正式组件别名、Tailwind 入口、主题 token，旧 Spike 独立 TypeScript 配置。Button / Badge / Dialog 的原有业务 API 使用兼容层，无第二份交互实现。
- 工作项 / 流水线入口明确，流水线归档状态不再使用“进行中”。流水线展示名称、真实节点数、定义状态、修改时间，重命名/归档位于 DropdownMenu。
- 页头、搜索提交、分页、表格、载入状态一致；工作项名称优先，编号次之，去除同义阶段与完成套话，执行异常仍单独突出。
- 工作项轮询不重排行、不抢搜索焦点；递归 timeout 避免请求重叠，卸载后忽略迟到结果。列表客户端分页，搜索/筛选重取顺序。
- 长表格内容独立滚动，分页区不覆盖末行。1024×768 / 1440×900 检查。

## 已验证

1. `same-work-reopen.spec.ts` 和 `work-library.spec.ts`：2/2，通过真实 API 验证重命名、搜索、分页、归档恢复、重新打开后未保存编辑与材料保持。
2. `workitems.spec.ts`：1440/1024 两条均通过真实 API 登记、等待、事件推进、条件依据结项、重开与筛选。
3. `management-presentation.spec.ts`：1440/1024 两条通过。12条混合状态 **呈现 fixture** 由浏览器 route 返回，仅证明信息层级、截断、客户端分页和更新行为，不冒充运行器/持久化验收。服务端返回逆序后行序不变、未提交搜索与焦点保留、Tabs 左右键、菜单 Enter/Escape 和关闭后焦点恢复。
4. 正式应用 typecheck 和生产 build 通过；bundle 大小警告仍存在（最终总体验收可能有其它并行改动）。

截图见 `artifacts/management-items-{1440,1024}.png`（12项呈现 fixture）和 `artifacts/management-flows-{1440,1024}.png`（真实 API 库）。已人工检查截图。根任务另做最终全产品验收。

## 过程中发现并修正

- 旧全局 `.empty` 与定义状态类名碰撞导致 Badge 高180px，已使用明确 `definition-*` 类名。
- 原生控件排除 data-slot 后 specificity 变高，意外覆盖页面按钮；改用低优先级 `:where()` 约束。
- 原 Modal transform 与 Tailwind translate 重复，移除旧定位，Dialog 掌握位置与焦点。
- 根任务发现长流水线列表盖住footer，改为内容区独立滚动，并对工作项同样处理。
- 第一轮重开用例因按钮 accessible name 包含节点数失败，改为名称 aria-label 后通过；并行测试共享 artifacts 产生 ENOENT，分配独立输出目录后通过。初次分页失败发生于热更新实施期间，固定代码后完整用例通过。

本轮两组早期管理验收流水线（前缀 `自动验收列表mu8ukm38`、`自动验收列表mu8uie7v`，共24条）已通过归档动作清理，可恢复；测试已增加 finally 归档。未删除用户数据。工作项生命周期回归生成的两项由根任务统一归档备份管理。

## 边界

尚未把整个画布/详情中的每一个原生表单控件迁移；本轮只对有真实重复的管理页及共享基础控件落地。未建设通用 CRUD、额外权限或生产治理。用户对最终视觉的评价不能由测试代替。
