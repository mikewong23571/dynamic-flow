# 规格：直接输入（invoke 表单与调用留痕展示）

## 背景与定位

长尾定位下，「用现成办法处理新来的一件小事」是最高频动作；当前唯一运行路径是「选材料 → 运行流程」，进入流水线即编辑姿态。输入契约与 invoke 触发面（input-contract-invoke_20260921）已提供后端地基：裸值输入服务端包装、按端口契约校验、`interpret` 修复环、`loose` 调用级豁免，`Run.invocation` 留痕。本 track 补上前端入口与留痕展示，属于渐进形式化主轴的「入口宽容、出口显形」环节。

## 功能需求

1. **入口**：工作区头部「运行流程」旁加次级按钮「直接输入」，打开调用对话框；存在可运行定义（adopted 或 draft）时可用。运行结果页空态提供同一入口。
2. **表单**：按端口组织，每端口可添加多条条目。
   - 声明了契约的端口：按 `item` schema 渲染（string→文本框、number→数字、boolean→勾选、object/复杂→JSON 文本域），`required` 端口标注必填，本地预校验给出中文提示。
   - 未声明契约的端口：自由文本/JSON（宽松现状语义）。
3. **做法版本**：跟随头部现有「运行使用的做法」选择（adopted/draft），对话框内不重复造版本选择器。
4. **提交与等待**：默认 `wait: true`；200 终态后选中该 Run 并切到运行结果；202（超时）显示「仍在运行」并同样跳转跟踪；错误（违约 / 修复失败 / 无采用版本）如实显示在对话框内，不关闭表单、不丢已填内容。
5. **loose 逃生通道**：不做预勾选。契约违约被拒后，错误下方出现显式按钮「豁免契约重试（会留痕）」，点击才以 `mode: 'loose'` 重发。
6. **留痕展示**：运行记录行与运行详情中，`invocation.loose` 显示「宽松调用」标记，`repairedPorts` 显示「端口 X 经自动修复」；输入来源处 `materialIds` 为空时明确显示「直接输入」而不是裸 sampleId。

## 验收

- 浏览器真实操作：无契约定义走自由输入跑通出结果；带契约定义违约被拒 → 错误可读 → 豁免重试成功 → 留痕标记出现。
- interpret 修复路径在结果处显示修复端口（替身契约定义验证 UI；真实模型修复环归 input-contract-invoke track）。
- `pnpm typecheck:app`、相关模块测试与既有浏览器回归通过；1440×900 与 1024×768 截图。

## 非目标

助手唤起调用；契约编辑 UI；任意历史版本选择 UI；webhook/cron；invoke 后端语义与工作项里程碑语义变更。
