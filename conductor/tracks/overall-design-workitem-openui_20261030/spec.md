# 唯一工作项流程与业务推进可见性

2026-10-30，overall-design。用户已授权闭环实施、清理、验证与交付，无需再次审核。

用户决定优先：原型以唯一、简单的业务模型为目标；淘汰方式的代码、接口、持久数据和测试可以删除，不要求兼容；OpenUI 是正式第三方界面框架；处理中间的业务流程必须可见。上一轮“删除 json-render 后完全手写 React 解释 ItemUiPlan”的建议被本决定替代。

## 当前追加决定：先纠正工作界面的组织

用户明确否定当前呈现。数据真实与控件可用不足以交付；需先按具体业务组织阅读和操作，再回接Assistant动态生成。根因、资料核对的连续路径、组件及外壳责任见[工作界面重做](work-surface-redesign.md)，其优先级高于此前按功能补齐即验收收口的顺序。当前整体不通过；不再扩大功能或验收范围。

部署事实：上一版已切换托管并清理授权旧数据，见deployment；下文“暂停发布/未实施”描述的是此前检查点，不代表当前现场。

## 2026-10-30 用户指正后的问题定义

Assistant能够编排工作项，但用户无法感知具体工作的推进：当前业务阶段、子项及统计、已取得的阶段成果、阻碍、需要补充和下一步。单项也有同样问题。流水线解决聚焦的处理需求，节点状态不能代表跨运行、跨子项的业务进度。应用无法预先穷举各业务关心的数据、名称、呈现与操作；Assistant必须能为当前工作安排读取真实事实的界面，贯穿处理中与最终交付。OpenUI只是实现细节，assistant-ui仅为聊天组件。

上一批实现不足：主要把动态界面绑定到已发布Delivery，处理中依靠固定RunInspector；新增通用文本/页面，却漏掉字段标签等已有语义。用静态说明填补业务可见性，运行后再让模型改状态文字，不满足目标。已有测试/真实运行通过不代表该目标完成；暂停发布和实际数据清理。

本次由主代理独立重做，不再派发子代理。保留唯一数据/命令及真实来源机制，不新增业务平台。最小能力为：读取本项真实业务状态、现有子项分页/统计、明确运行的阶段输出和固定交付；用数据绑定的字段、统计和表格组织业务内容，复用输入及动作。业务字段/标签/分组/呈现由Assistant声明，应用不写具体领域判断。文字可解释内容，不能作为可变业务状态的副本。

## 目标

| 编号 | 可验证结果 |
| --- | --- |
| U1 | 目标/材料→Assistant共编→明确输入/版本→执行→检查过程/成果→续做→依据结项构成唯一主线；各入口使用同一准备/启动服务。 |
| U2 | 一个工作项只有一个当前处理工作区、一份输入绑定、一组交付。Run保存固定定义、输入、实例、等待和来源，不代表业务结项。 |
| U3 | 正式使用OpenUI Lang、组件库、Renderer、交互/状态能力与具名增量编辑；淘汰json-render、自建界面解释器和ItemUiPlan可写副本。 |
| U4 | 动态业务界面在交付前即可观察本项阶段/阻碍/下一步、子项与统计及真实阶段成果；随事实更新而不重新生成文案。固定过程入口补充检查Run/内部步骤/来源，无界面时仍可用。 |
| U5 | 人、Assistant、OpenUI和批次通过同一组服务端业务命令写入；界面保存、输入修订、执行、发布及条件确认分别有真实回执。 |
| U6 | 单步正式处理、preview/比较、批量和成果接续继续可用；等待/停止/恢复按真实执行事实，成功实例不因界面刷新重跑。 |
| U7 | 删除退役字段、操作、组件、依赖、夹具和相关业务数据，默认使用干净数据启动，不开发兼容/迁移平台。 |
| U8 | 本轮审查的输入双轨、先写后验、猜字段证据校验、编译缓存、草稿基线、会话归属和更新接纳问题得到机制性解决。 |

唯一流程见[正式设计](../../../docs/workitem-openui-flow.md)，验证见[acceptance](acceptance.md)，删除见[cleanup](cleanup.md)。

## 非目标

- 不更换React/Vite、Pi、Hono、React Flow或文件持久化底座，不增加数据库、流程引擎、命令总线或插件平台。
- OpenUI不执行业务图或管理长时等待；浏览器状态不成为工作项、Run或成果事实。
- Run成功、Assistant回复、界面生成和动作可用不自动确认条件或结项。
- 不为旧演示、旧格式及旧测试保留双轨。历史归档仅标注被替代，不改写原验收事实。
- 不把开发调试并入托管实例。实现/浏览器使用独立源码和临时数据；最终维护切换与已授权业务数据清理在验收后执行。
