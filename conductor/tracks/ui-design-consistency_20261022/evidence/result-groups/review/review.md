# 独立信息设计审查 · 2026-10-22

审查对象是当前本地 `http://127.0.0.1:4320` 的真实页面；只读导航，没有创建数据、改业务状态或重启服务。使用本地 Playwright，1440×900 / 1024×768 截图均实际查看。以下是用户任务导向的设计问题，不是组件清单。此文件记录修改前观察，后续复看另记。

## 1. 成果与实例缺乏可区分身份（优先）

- 页面：仓库漏洞核查 → 运行结果；查看过程 → 执行实例。
- 用户任务：选择一个目标的核查结果，或看整批汇总。
- 现状：同一行两个 `checks` + `报告`；过程下拉为 `1 · M01、M02、M03 · 已完成` 与 `2 · M01、M02、M03 · 已完成`。数字和相同材料号不能告诉用户目标是谁。
- 影响：必须逐个打开、阅读原始字段后才能知道选中了什么。数量与身份两个问题同时出现。
- 最小设计：表格按显式输出分组，显示名称与数量；组内成员明确标识。过程实例选择复用相同的身份显示，不能只在列表解决。名称来自配置/实际值，不推断漏洞结论，也不做 CVE 专用 UI。
- 证据：[结果1440](results1440.png)、[结果1024](results1024.png)、[过程1440](process1440.png)、[过程1024](process1024.png)。

## 2. 工作项概览用旁白代替下一步操作（优先）

- 页面：工作项详情所有标签页上方。
- 用户任务：看结果后决定继续推进还是确认条件并结项。
- 现状：已有“待推进 / 当前执行已完成 / 完成条件0/2”，又常驻“当前执行已结束，工作项尚未结项”“请检查本轮结果，确认完成条件并补充依据。”；0/2本身不是入口。详情身份与概览、辅助行、轮次和步骤占到约570px，1024高首屏仅能看到产物最前两行。
- 影响：重复文字和层级让用户先阅读页面说明，而不是直接看到结果与可做的决策。“下一步”没有承接成动作。
- 最小设计：删除通用兜底旁白，把完成条件进度做成进入确认任务的动作；状态使用已有图标/短标签。真实等待原因、失败、业务输入的阻碍与下一步保持可见，不一刀切删除真实信息。布局压缩的是重复层级，不是把全部间距缩小。
- 证据：[工作项1440](item1440.png)、[工作项1024](item1024.png)、[条件1024](criteria1024.png)。
- 对应代码：`WorkItemProgress.tsx` 中的默认executionOutcome/nextAction文本。

## 3. 完成条件页首先邀请编辑定义，而非确认业务完成（后续明确故事）

- 页面：工作项 → 完成条件，直接进入时未预选成果。
- 用户任务：把已经产生的成果作为依据，确认条件。
- 现状：主体是可编辑条件输入框、空依据大文本框和“删除/添加完成条件”；没有就地选择成果入口。“引用所选成果”仅在用户先到别页选择成果之后出现。
- 影响：用户被要求知道一条隐藏的跨页顺序，界面看起来像要重新撰写条件和证据；此时加一段操作说明只会继续让页面成为说明书。
- 最小设计：条件默认以可阅读条目+确认状态呈现，给每项明确“引用成果”入口；编辑条件定义作为次要动作。复用现有成果选择，不增加自动判定或新的业务模型。本轮若只治理结果分组，可保留为独立待办。
- 证据：[条件1440](criteria1440.png)、[条件1024](criteria1024.png)。
- 对应代码：`WorkItemCriteria.tsx` 的artifact条件分支、默认Input/Textarea布局。

## 4. 独立成果阅读的工具区抢占阅读空间（较低优先）

- 页面：运行结果 → 报告。
- 用户任务：读取报告、使用成果，需要时追查过程。
- 现状：方法编辑顶栏、返回行、成果标题/来源、操作行、显示模式行逐层堆叠，正文从约360px开始。1024下结论表只露出表头和第一行。
- 最小设计：合并成果标题/来源/操作为一个紧凑页头，把低频动作收纳，保留明确返回和查看过程。无需新增说明文本，也无需从Markdown推断结论制作领域卡片。
- 证据：[报告1440](report1440.png)、[报告1024](report1024.png)。

## 不能误伤的内容

报告中的范围说明、漏洞触发条件、源码证据和遗留事项是 Agent 真实产物，不是前端额外插入的旁白。本轮不应擅自删改报告或把所有文字换图标。错误、等待原因、引用来源和关键业务状态需要明确文字；图形承担分组、层级、选中与状态辨识，不能代替业务事实。当前报告排版本身已有行宽和段落，问题主要在阅读入口与前置工具区。
