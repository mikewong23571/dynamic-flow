# 工作项结果页：操作归位与内容优先

本轮输入是用户指出的真实工作项页面：相同对象先后被面包屑、状态解释、下一步兜底、摘要折叠、四轮导航卡和步骤卡重复描述。用户真正需要读取结果、选择历史、继续处理或确认条件。

## 本轮设计

- 页头保留身份与执行操作；阶段、当前执行和条件进度用一行表达。条件数字直接打开确认页；条件与目标方法使用既有边界按钮和语义图标，让动作区别于静态状态；删除默认下一步与执行完成旁白，真实业务 nextAction、blocker、错误和等待仍可见。
- 目标与方法进入按需弹窗。当前摘要由业务记录承接；遇到摘要没有对应历史记录的真实旧数据，在记录页保留当前摘要，不更改或丢弃业务内容。
- 历史轮次改为既有 NativeSelect，一项包含轮次、方法和状态。保留运行日期与短“打开流水线”；固定输入修订已有“输入与依据”入口。
- 成果旁保留“继续处理”，引用菜单区分“完成条件”和“证据材料”。“加入比较”明确表达先收集，已选比较条位于正文之前；不让比较入口埋在长报告后。
- 结项移到完成条件页，紧邻保存，原校验保持。条件页增加“选择成果”，从成果返回保留未保存输入。定义表单本轮不重构，结项仍由用户确认。

## 真实页面实看（只读）

使用本地 Playwright，在 1440×900 和 1024×768 操作真实 CVE 工作项；`check-live.cjs`、`checks.json`记录检查。没有调用工作项写入 API，没有创建测试业务对象，没有修改模型报告。

修改前：[1440](before-1440.png)、[1024](before-1024.png)。修改后：[1440](after-1440.png)、[1024](after-1024.png)。两尺寸均实际查看；截图包含独立review后补的条件/目标方法按钮可点性。

1024 下，多实例成果内容面由约 571px 提前到约 328px；真实结果的 commit、conclusion、evidence、reason、repository 和 requestedRef 在首屏可见。最终报告内容面约 288px、正文约 403px，见 [报告1024](report-1024.png)、[报告1440](report-1440.png)。这些是同次本地浏览器布局观察，不作为跨环境像素断言。

实际交互：历史轮次切换；引用菜单两目的；从条件选成果后返回保留依据草稿；结项校验禁用；目标与方法弹窗；业务记录保留未收录摘要；继续处理打开准备执行。两尺寸无页面横向溢出。补充 [比较检查](compare.json) 与 [比较1024](compare-1024.png) 确认加入两份成果后可在正文前发起比较。

条件页：[1024](criteria-1024.png)、[1440](criteria-1440.png)。直接选择成果和保存/结项位置已调整，条件默认编辑表单仍存在；这轮没有引入新的条件编辑模式。

## 验证范围

定向浏览器回归使用现有临时目录/私有 HTTP fixture，覆盖进度、错误/等待、轮询、条件保存、结项/重开、跨方法准备与来源。模型是明确替身；不冒充真实模型验收。本轮 12 项全部通过（1.6m），见 [browser-regression.log](browser-regression.log)。最后按钮边界/图标与方法Dialog关闭属低影响修正，另用两尺寸真实入口补验；未为视觉修改重跑全部12项。统一构建与类型检查由 results 实施者执行，根任务统一收口。

方法Dialog跨入口也已实测：目标与方法 → 打开当前方法 → 返回工作项，弹窗关闭且原工作项可见。
