# 工作项调用节点中的流水线引用（N历史，内嵌卡片已被否定）

用户澄清针对的是工作项自身流程图中的节点，不是成果Tab或交付来源。实际Definition已保存call，但WorkflowNode只显示node.label，business模式隐藏版本，CompositionStep仅打印ID，无流水线入口。

最小构图：

```text
┌ 调用方法 ────────────────────┐
│ 本项步骤名称/职责             │
│ ┌ 流水线         固定版 abc123 ┐│
│ │ 实际引用的流水线名称      ↗ ││
│ └──────────────────────────┘│
│ 真实输入 → 此调用 → 业务输出   │
└─────────────────────────────┘
```

名称从实际方法目录按workId+definitionId读取，不用node.label冒充目标流水线。点击引用用现有Modal及WorkflowCanvas查看该definitionId的保存定义，不以draft/adopted/latest替代。查看不保存定义、不启动Run；如进入流水线编辑，明确为当前编辑工作空间，不自动改变工作项固定引用。缺失方法/定义如实呈现。

画布只新增可选显示数据和回调，不将UI元数据写回Definition，不复制运行语义。工作项流程保持薄call。两尺寸检查节点密度、可读版号与入口、连线及预览图，随后验证固定旧版和页面状态。

## 当前实施与审阅

CompositionFlow以workId+definitionId从实际目录解析目标，把名称和查看回调传入共享WorkflowCanvas/WorkflowNode；节点本身显示流水线引用块，业务模式保留版号。步骤详情中的原纯ID也改为同一固定版入口。MethodPreview复用Modal及WorkflowCanvas查看目录里对应的不可变定义；本地布局不写业务数据。进入流水线编辑复用原onMethod，返回工作项仍在流程Tab。缺精确版本则显示错误，不用其它保存版。未增加持久字段、后端合同或运行逻辑。

已实际查看1440/1024节点及固定定义画面：引用块和真实连线可见，预览完整显示3个节点，脚本等待布局结束并检查所有节点在各自画布边界内。新块使短桌面节点缩得太小，按实际画面压缩业务节点标题留白和概览端口行高；保持原Handle、端口与ELK连接语义。初次截图位于整理动画中，最终截图等待真实布局/fit完成，不以临时裁切当作当前通过。
