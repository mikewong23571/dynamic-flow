# 实施取舍与当前设计决定

2026-10-28。用户要求“小而美、页面能完成事情”，原型按真实需要收敛。

## 执行与原语

复用现有 map/flatMap、顺序 reduce、collect、join、DAG 就绪与检查点；新增固定版本多端口 call 与 groupBy。设计中 barrier 所要求的明确收口由现有调度能够承担的部分直接实现，不为了术语新建调度抽象。

调用内部仍使用同一执行底座，保留根血缘、效果模式、实际来源及停止。业务子项不等于调用实例。

## 成果声明

首版保存 table/report 两种有限声明，包含 output、标题、rowKey、columns。前端通过有限 registry 确定性呈现，不另存一份任意 UI 树 DSL。

提供通用“选择记录继续”和“补充材料”动作。具体字段表单从方法真实 inputContract 生成；不增加任意 actions/表单脚本语言。CVE 业务列、标题和分类由方法产物与 Assistant 声明给出。

## 最先验证的用户价值

创建工作项并提供材料后，用户可以在当前页通过 Assistant 形成流程、执行、检查成果、处理缺口和选记录继续。用户无需处理技术 ID、端口或 JSON。方法提取复用在这条路线完成后验证。

## 起点与现场

独立 worktree 包含当前源码的1881文件快照和独立 node_modules 副本。基线 `pnpm typecheck:app` 已通过。默认 4330/4331 在启动前检查为空闲；托管服务未操作。

原工作区的已有修改不作为本轮增量提交。当前阶段未提交/push；各模块在独立工作区修改并分别记录证据。

## 设计重置后的当前决定

- 用户先要求完善track，随后明确“落地”解除编码冻结；按业务/可见设计→代表实施→视觉修正→功能验证推进，只由主代理执行，不使用子代理。
- 默认工作台首页是设计起点，以开始/继续工作项为主；流水线是明确进入的方法目录，不能继续默认落入编辑器。
- 工作项与流水线统一实际骨架和面板行为。此前“仅沿用视觉节奏、无需共用外壳/拖拽”的内部取舍撤销。
- 先交出完整可见设计并审阅，再实现代表页面、修正视觉，最后验证功能。此前内部看图与9条浏览器通过不等于用户认可。
- 默认工具堆积、子项空态满载、记录重复属于信息架构问题，不能仅改尺寸/文案或批量挪到菜单。
- 既有backend/runtime技术成果继续保留；新增抽象须由当前业务样例证明必要，不为重做界面再次重写底座。

当本节与上文首轮记录冲突时，以本节及当前spec/workflow/plan为准。

## 业务界面与薄工作项

首轮仅table/report与统一“继续处理”的取舍不足以交付元应用主线，已撤销该限制。恢复六种有限组件及continue/input/review声明，但不增加阶段引擎或动作DSL。当前方案放WorkItem保证业务保存原子性，Work只携带复用模板。实际业务规则与输入规范化放流水线，工作项代表路径一个call。视图按逻辑output维持，真实交付仍固定Run与新ID；页签稳定不意味着改写旧成果。
