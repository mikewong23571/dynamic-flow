# 业务界面与薄工作项的最终审阅

2026-10-29，主代理独立设计、实施与审阅。本节取代以九步骤图作为主线完成的旧结论。

## 从用户目标确定职责

用户需要看清整批输入的去向、哪些对象受影响、哪些实施仓库要改、剩余什么必须由人补充。工作项保存业务身份、材料/输入选择、有限方法衔接、当前交付和人工完成依据。拆分、归一化、逐范围判断、flatMap、归并和审计覆盖检查都属于流水线；它们继续由同一Definition/Run执行。

| 模块 | 最小职责 | 本轮明确不加入 |
| --- | --- | --- |
| WorkItem / composition | 材料、精确输入引用、当前交付、必要固定call、条件与历史 | 阶段调度器、第二套业务算子 |
| 公用Work / Definition / Run | 固定合同、处理规则与具名输出；一次真实执行 | 用界面状态代替处理结果 |
| composition-ui | 检查声明、绑定真实输出、按声明调用原服务 | 领域判断、任意动作脚本、通用UI平台 |
| Assistant | 发现真实方法和模板，保存处理安排及用户操作面 | 聊天代替保存、自动代签 |
| client / json-render | 六种有限组件、只读数据、选择/草稿与明确操作 | CVE字段解释、第二套控件 |

当前演示工作项根节点始终只有一个固定call；batch流水线内部仍可检查。方法模板复用保留界面安排，新工作项重新绑定自己的材料，不能复用前项业务数据。

## 一致性与具体失败

有限schema、动作前提与输入修订判断由shared共用；保存检查实际方法版本和输入合同，绑定检查实际字段/唯一编号，命令重读交付与选中记录。页面只提交ID和声明字段。多视图一次绑定，任一失败都不保存前缀；新计划和旧交付不匹配时人工核对受阻。表单固定打开时修订，错误保留草稿/选择，不能用晚到响应覆盖别人保存。

实际发现并修正：输入修订后缺少重处理提示；未分层modal字段规则导致表单间距过大；绑定换ID时页签可能在按下/释放之间被替换。前两项有实际两尺寸画面，后一项增加真实HTTP响应等待和鼠标按下/释放的浏览器回归；业务页签现按逻辑输出保持，交付数据仍按新ID重建。一次浏览器取图碰到独立API重载的暂时读取错误，保留startup-interruption截图；待API就绪后重新实际取图，无错误提示，未隐藏或伪造错误。

## 可见推进与结果

执行前已有安排的业务视图和合同输入；执行后成果提供分组/表格/报告，选择动作位于表格工具栏。补依据与确认例外直接进入带对象范围的业务表单，不让用户填端口/JSON或回聊天索要下一步。失败在原表单显示，旧成果值不被补输入改写。结项仍在既有人工条件任务。

真实模型两轮分别约61.3秒、43.8秒，保存一个固定call、四个视图及固定动作，再明确执行并一次绑定成功Run。随后真实页面提交明确虚构的核查依据和例外确认，原8条告警从6条有依据变为8条，未决为0；改动安排保留api两分支、platform-images上游和worker采用关系。工作项仍open，两项条件未确认。独立临时浏览器夹具另外验证了人明确保存条件后结项。

最终实际画面在evidence/interface-model/final-*-1440.png及1024.png；表单在model-evidence-form/model-exception-form。分组记录为主体、详情按需进入，1024默认真实Composer停靠，既有Assistant可展开。完成检查的空列表明确显示“无”。主代理已看图修正；用户审美接受不在此结论内。

## 边界

演示的判断、变更、验证材料均虚构，不证明真实漏洞排除或整改。当前配方只覆盖一告警一个范围；一告警多范围的总验收和真实仓库扫描未验证。字段仍限顶层，动作只绑定固定单输入方法；复杂输入/规则需封装到流水线。大型批次上下文交接未做优化。没有新增兼容层或生产治理抽象。
