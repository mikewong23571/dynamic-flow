# 工作台入口与工作项内从需求到交付

2026-10-29 修订。当前阶段：T任务访问合同已交付，导航实施/验收见feature-task-navigation_20261029；S及此前独立原型结果见delivery.md。由主代理独立执行，不使用子代理；按设计→代表实现→视觉修正→功能验证推进。

## 用户价值与范围

用户打开应用，首先知道在哪里开始一件事、在哪里继续已有事情。进入工作项后，提供需求与材料，与 Assistant 一起形成可检查的处理流程，使用真实成果推进业务；成熟做法再沉淀为可复用流水线。应用优先小而美、可理解、可修改。

主攻 CVE 批处理，最终交付回答：哪些仓库/ref 受到哪些漏洞影响，哪些仓库需要实际改动，每条原告警如何修复或有证据排除，哪些例外仍待明确确认。影响目标与改动目标可以不同。缺判断、缺验证及未确认例外保持未决。CVE 业务规则在方法与输入中，通用 src 不增加 CVE 字段推断、分类或专用页面。

## 本次必须补齐的产品设计

### 1. 稳定入口作为应用基础

默认入口为工作台首页，以开始和继续工作项为主，复用已有工作项列表与创建能力承载内容；流水线作为可复用方法目录进入。首页与工作项列表不重复建设两套内容相同的管理页。

先确定全局导航、首页内容层级、页面容器和详情进入/返回关系，再设计工作项与流水线工作区。根入口不能因上次打开过方法就自动落入流水线编辑器；恢复方法草稿属于用户明确进入方法之后的行为。

首页必须覆盖首次进入、已有待办、没有匹配结果、加载/失败四种现场。需求与文件如何开始一项工作、如何继续既有项，须在可见设计中说明，不靠额外说明文章。不得为首页新增无实际用途的仪表盘、统计卡或第二套聊天实现。

### 2. 一致的工作区骨架

工作项与流水线使用一致的页头、Tab 层级、内容区和辅助面板。右侧面板的拖拽、宽度记忆、开合、滚动与窄屏规则应来自同一实现。任务内容和操作可以不同，不能分别拼两套近似布局。

访问遵循[任务访问与导航合同](../../../docs/task-navigation-contract.md)：固定全局导航、位置与身份、对象视图及临时检查分别负责定位、切换和恢复。工作项与方法不构成父子层级；临时检查关闭回到原任务，完整方法编辑保留具名原任务入口，浏览器后退遍历真实历史，不以pushState模拟返回。撤销“各详情页头固定放返回入口”的旧取舍；不能只删除箭头而丢失任务连续性。现有共享组件与行为先复用，不加返回横栏、工作区标签平台或全局来源栈。NAV-01—12待实施验收。

### 3. 工作项是 AI 辅助推进业务的地方

工作项 Assistant 读取需求、文件、方法目录及具体版本合同，规范化可追踪输入，组合通用集合原语与固定方法调用，保存/检查流程，按授权执行并发布真实成果。用户不必先手动选择方法、复制技术 ID 或逐个搭节点。

界面以当前业务内容和下一步为中心。流程页默认展示实际处理关系与进度；手工添加节点、选择方法、配置端口等属于按需编辑，不能成为默认的两排工具栏。必要运行控制和错误应清楚可达，不能仅把全部旧按钮塞入一个巨大菜单。

画布与 Assistant 仍编辑同一 Definition；保留手工修改能力不等于在每个现场铺开所有编辑工具。工作项会话复用已有 Assistant/Thread/Composer/ModelSelector，输入直接可达，已有草稿与阅读位置保持。

### 4. 稳定区域与动态成果分开

主 Tab 仍为成果、流程、输入、记录。稳定框架负责身份、导航、来源、错误和人工确认；具体成果视图、列、标题及输入字段由实际工作推进产生的声明决定。原型继续使用有限 table/report 与方法 inputContract，不引入任意 UI/动作脚本平台。

CVE 示例应能声明仓库影响、改动安排、逐条审计交付等成果内部视图。应用不通过字段猜业务结论；交付绑定真实固定输出。用户从真实记录继续处理、补字段或明确建立业务子项，后端重读记录与来源。

### 5. 子项与记录回到正确的信息层级

子工作项只服务于确需独立跟踪的事情，不由 map/fanout 的输入条数自动创建。其入口属于业务范围或明确交付动作，不默认占据流程执行工具栏。

子项任务只有一处标题。真正没有子项时呈现简洁空态与必要入口，不铺搜索、状态下拉和零项分页；筛选后无结果时保留筛选与清除动作。非空列表才按规模出现搜索、选择、批量和分页。旧阶段成果/完成依据交接仍需有按需入口。

记录是一条连续时间线，运行是其中的事件与固定来源。时间、内容、状态及来源动作在同一事件中组织，不再重复列“业务记录”“执行记录”。跨方法历史、旧依据与来源不能因合并展示丢失。

## 业务职责与保留能力

| 层次 | 负责 | 交接 |
| --- | --- | --- |
| 应用入口/框架 | 稳定首页、导航、统一工作区与返回上下文 | 进入当前工作项或明确方法 |
| WorkItem | 业务身份、独立材料、当前输入、交付与条件 | 多次执行和跨方法历史，人工完成/重开 |
| 工作项 Assistant | 理解需求、发现方法、组织处理及成果声明 | 调用与页面相同的正式命令，返回真实回执 |
| Work/Definition | 可复用方法及私有组合的确定语义 | 固定 call、集合变换、输入输出合同 |
| Run | 一次固定输入/版本的执行 | 实际结果、来源、等待、停止和恢复 |
| UI | 呈现任务、收集选择/补充/确认 | 不持有另一份正式业务状态，不编造结果 |

现有执行、来源、版本、条件、子项范围与交付合同继续保留，详细字段见 contracts.md。Run.completed 不自动结项；调用实例不等于业务子项。方法沉淀复制参数化流程和视图模板，不复制旧业务材料。

## 非目标与约束

不重写稳定运行器，不增加安全/权限、分布式调度、推荐市场、通用页面 DSL、数据库迁移或任意源码分析。旧布局可以删除，有价值的业务能力须重新安排可达位置，不按旧组件数量决定页面结构。

只在独立工作区 dynamic-flow-workitem-composition 实施。托管 4320/4321 与用户数据不作测试夹具。当前不提交、不推送、不部署；用户已恢复实施授权，但须按本track先完成业务与可见设计。

## 完成定义

首页、两个工作区和关键子任务的可见设计先成立，再实现代表页面、修正真实内容下的视觉，最后验证业务路线。每项要求与产物/审阅/证据的对应见 acceptance.md。已有源码、自动检查或内部审阅不能替代用户已否定的设计。

## 当前收敛结果（2026-10-29）

工作项保持薄：当前代表路径只有一个固定流水线调用。Assistant安排的不仅是图，还有用户能直接推动的成果视图、合同输入与固定操作；复杂处理留流水线。成果页呈现实际交付和待人处理任务，流程页用于检查。当前完成范围、真实模型与未测边界见delivery及interaction-review；旧图展示不再作为目标完成依据。
