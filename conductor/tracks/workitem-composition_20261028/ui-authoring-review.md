# 人与 Assistant 共编界面安排：实施与审阅

2026-10-29，K阶段完成，主代理独立执行。规范先于实施，见[当前合同](ui-authoring-spec.md)。产品在独立工作区，预览4330/4331；托管4320/4321未停止或重启。

## 用户路线与实际职责

成果中的“界面安排”进入同一主内容区，具名树显示视图、详情、动作及引用。用户在“结构”修改列/字段/分组/动作，在“描述”阅读或编辑组件声明；当前记录预览读取固定交付。选择一个具名详情后，既有Assistant显示该焦点，可按块修改。保存回到成果仍保留所选记录。

ItemUiPlan是唯一持久权威。具名模板存于templates，视图以detail引用；uiProgram从计划即时生成，既不另存源码版本，也不从任意JS反向推导。使用现成@openuidev/lang-core 1.0.2解析具名声明；适配器只接受注册组件、字面量与有限引用，补足完整消费/引用/循环/重复声明校验，拒绝SDK流式容错可能忽略的残缺内容。渲染继续走已有json-render和组件注册，不引入第二渲染器或业务计算引擎。

页面与Agent经同一normalize/patch/save服务，持有baseRevision和planId。更新前验证实际字段和固定方法；现有成果按原Run/output重绑，所有视图验证后一次保存。未变视图保留交付标识，旧快照保留在现有历史事件；不修改Definition、原Run、材料或完成条件，也不寻找一个“最新Run”顶替来源。没有可绑定成果时只安排计划。

## 实际看图与修正

先有design/ui-authoring.html及1440/1024设计，再实施并看实际页面。最终画面为[evidence/ui-authoring-real](evidence/ui-authoring-real)中的current-structure、current-source、current-record两尺寸图，final-visual.json记录只读检查。静态稿的窄屏会话隐藏仅为构图，实际1024沿用应用现成停靠输入，不以稿图代替实物。

逐屏发现并修正：原Textarea继承内容自适应导致描述区过高；改为固定高度内滚动，选中声明定位并保留一行上下文。编辑时原成果卸载导致勾选丢失；保持成果挂载并按workId/runId/output/rowKey维持store。更新未改视图时原交付标识变化；改为相等视图保留标识。结构/描述使用现有Tabs及TabsContent；选择、按钮、输入、详情和Assistant均复用项目组件。字段编辑拆出专用小组件，未增加通用页面搭建器。

最终1440描述区398px、1024为266px，两者均定位impact_detail，页面无异常。主代理查看了结构、描述及实际记录弹窗；这是实现者视觉审阅，用户审美接受尚未声明。

## 首版范围

声明键为ASCII，root保留入口；支持中文业务标题。Detail是顶层字段模板，List使用现有表格阅读方式；不能写任意函数、JS、注释、尾随逗号、watcher或客户端业务运算。结构面编辑已有视图/详情/动作；根输入任务可在描述中编辑。固定方法别名解析到明确版本，不隐式选最新。冲突或未保存草稿需明确处理，不自动合并。

业务处理仍在流水线，工作项只作薄衔接。所有漏洞与证据均为明确虚构的演示，不能据此宣称真实仓库安全审计完成；一告警多范围、超大批量、移动端、任意UI布局和用户视觉接受不在本轮验收。
