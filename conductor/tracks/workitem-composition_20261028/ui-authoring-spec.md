# 工作项界面安排共编规范

2026-10-29，本阶段实施合同。依据当前visual-composition-research与用户明确授权，主代理独立实施，产品代码仅在独立工作区。本文为当前实现合同；K阶段已完成实施和分层验证，具体证据与未测边界见track的ui-authoring-review。

## 目标与职责

用户能够读懂并编辑列表、详情和操作的安排，选择具名片段与工作项Assistant协作修改。工作项衔接方法、输入与交付，并可保留必要的输入构造、逐项分发、匹配分路和结果汇合；复杂领域处理封装在可复用流水线，沿用同一运行器。列表渲染不运行fanout，表单不等于wait，改标签不运行方法，人工review不等于结项。

## 一份权威及有限表达

现有ItemUiPlan继续是唯一持久权威，增加视图稳定name、具名详情templates及视图对模板的detail引用。模板具有可选业务标题，负责顶层字段/标签，可供多个视图引用；视图自己的列和动作仍使用现有合同。未使用模板时可保留视图内details字段，二者不可同时出现。交付只保存解析后的视图快照，不能让旧按钮偷换方法。

可读文本采用OpenUI的具名声明/组件调用子集，使用现成lang-core解析；不引入其渲染器、Query/Mutation执行器或客户端业务计算。完整语句使用有限组件：Workspace、List/Table、Groups、Report、Detail、InputTask、Continue/Input/Review、Method。参数以具名配置对象表达，避免难理解的位置参数。List是当前记录集合的表格阅读方式；不冒称新增任意行模板。Detail是具名字段模板，作用于所选实际记录，相当于用户所说的detail(it)。首版不接受任意函数定义、JS、watcher、状态赋值或未注册动作。

示意（具体格式由同源formatter生成）：

```text
root = Workspace({navigation: "tabs", views: [impact], inputs: []})
impact = Groups({title: "仓库影响", output: "impact", rowKey: "id", groupBy: "repository", columns: [{field: "cve", label: "问题"}], detail: impactDetail})
impactDetail = Detail({fields: [{field: "baseline", label: "适用版本"}, {field: "reason", label: "判断依据"}]})
```

方法引用在文本中使用服务端提供的可读固定版本别名；别名解析为既有workId/definitionId/inputPort，不按标题偷偷采用最新版本。完整方法目录可查看及选择，不要求用户手写ID。描述不嵌入业务记录值。

人类文本和Agent补丁均解析成同一ItemUiPlan并调用同一保存服务；formatter从该模型生成文本，不另存一份源码权威。解析错误/未支持语义拒绝保存，并定位声明；不接受SDK容错后丢参数/丢节点的残缺结果。

## 共编与保存

以baseRevision及当前planId检查编辑起点。更新具名视图或详情模板是局部操作，未涉及的块保持原样；Agent工具读取同一目录、文本、块和错误。页面选择的块随请求成为uiFocus，服务端校验它仍属于当前计划；不能仅凭聊天文字猜目标。未保存草稿保留，避免轮询覆盖；冲突不覆盖他人保存。离开编辑面可取消草稿，不触发业务执行。

保存界面安排不改Definition/Run/输入/条件。若已有同定义的交付，新的展示方案按原输出和固定Run重新绑定，校验实际字段及全部视图后原子保存；没有可绑定成果的视图保留为计划，绝不填假值或启动Run。旧Run不变。新增或改绑输出必须明确且可读；绑定失败不保存计划前缀。

## 页面设计

稳定成果/流程/输入/记录四个Tab与WorkspaceFrame不变。成果导航处提供一个轻量“界面安排”入口，进入同一主内容区，Assistant仍在既有侧栏/停靠输入，不增加第三侧栏。编辑面只有具名结构、当前块编辑及可读描述两种表示；结构树用缩进/图标/选中态表达视图、详情、操作及引用。字段复用Input/NativeSelect/Table，描述复用Textarea，不新建代码IDE。

选中视图后可改标题、字段和分组；选中详情可增删字段、改标签，并看出被哪些视图引用。动作仍是已注册处理入口，能看到绑定方法及版本。用户可以切换描述直接编辑和检查，保存错误留在编辑面；返回成果看到真实结果及新安排。标题/字段/动作与页面定位可相互指认，不能只给一大段JSON。描述按语义分行并使用固定高度内滚动，选中块定位其声明；成果面保持挂载，按固定数据来源保存选择和阅读位置。

Agent会话展示当前关注的界面块；用户能从该处要求局部修改。编辑尚未保存时沿用既有脏草稿保护，先保存或取消再让Agent写入，不创建另一套会话。

## 模块最小合同

- shared：模板/视图schema、纯解析/格式化/解析模板函数、具名块补丁；不执行业务。
- work-items：现有校验、修订锁和交付解析；保存/局部补丁与页面和Agent同源。
- assistant：读取可读安排和焦点、检查/保存描述、局部更新具名块；保存/调用版本实际回执为准。
- client：现有编辑控件、具名结构、可读描述、局部错误与实际预览；不复制领域判断。

## 验收

A. 一个固定call的工作项，已有真实影响/改动/逐条交付/完成输出。用户能读出数据→列表→详情→补输入动作→固定方法的关系。
B. 用户改一列标签并保存，真实成果同步，Run数量、固定来源、方法版本、输入和完成条件不变。
C. 用户选择详情让真实Assistant加一个依据字段，工具局部修改；无关视图/方法保持，页面显示实际字段。
D. 文本与结构往返、共享模板、缺失引用/字段/方法、非法表达、过期修订、失败保留草稿均有实际验证。
E. 两尺寸实际看图，复用共同骨架和控件，不堆说明；模块、HTTP、模型fixture、真实模型与视觉分别报告。

原型不建设任意页面DSL、完整低代码平台、第二运行器或CVE通用源码分支。
声明键使用ASCII字母/下划线并保留root入口，业务标题和标签支持中文。首版文本不接受注释、尾随逗号及任意函数定义；Detail为字段模板引用，List为记录表格方式。新建根输入任务可在描述中编辑，当前结构面重点支持视图、详情和已有动作。运行中的wait/signal及子项仍沿已有专门入口，不借界面编辑新增调度语义。

来源卡片属于应用稳定底座：收展、去重、固定引用及跳转由应用负责。Assistant通过同一视图的columns/details声明业务字段和标签，卡片读取这些字段形成摘要，不另存来源布局或由模型生成来源身份。多来源在页内展开，复用现有材料卡片外观。

## 推进状态与会话

界面方案不只声明Tab，还通过已有InputTask/Continue/Input/Review让用户实际推进。运行前展示方案及实际合同输入，成功后显式绑定，业务视图呈现真实缺口并提供相应动作，随后人工核对条件。缺失/失配方案可在成果面请求当前Assistant会话完善。下一步仅计算当前计划/定义的已绑定成果，旧交付继续可读并标记“此前”；无法由声明判断的业务缺口不猜测。切换或新建Assistant会话不改变这份权威，所有线程通过相同保存/输入/运行/验收服务协作，不各自维护UI副本。

## 明确导航及页面职责

Workspace.navigation显式选择tabs或select，views数组决定顺序。Assistant依据任务选择，人的结构编辑器与描述编辑修改同一字段；前端不以4/5个视图阈值切换。当前仅两种现成导航，没有任意布局系统；旧记录缺省按tabs读取，新模型工具schema要求明确声明navigation。formatter总输出该属性，未知值拒绝。保存导航与保存其它展示一样，只重绑固定Run，不改定义/材料/条件。

inputs是模型声明的输入任务，固定在输入页呈现；成果面不重复保存状态。PlannedWork只在尚未绑定当前成果/输入需要重跑时呈现实际执行与绑定动作。成果中的缺口、下一步和review由显式数据视图/动作表达，通用外壳不据when/review拼进展条或核对捷径。

Detail.title决定记录详情标题；resolvedUiView将其冻结为presentation.detailTitle，字段仍来自同一Detail.fields。无显式标题时使用该视图的业务名称，记录身份单独展示。现有view.actions也可对详情当前单条记录执行，提交同一服务/合同，不改变表格原勾选。来源、完成依据、子工作项与比较是应用能力，来源独立，其余收在更多菜单，不能把这些固定工具说成模型设计的业务步骤。
