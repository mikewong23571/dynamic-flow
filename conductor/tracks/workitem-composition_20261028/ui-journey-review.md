## 结论与阻断

已读根/src/client 指南、DESIGN-NOTES、ui/README、持续工作项故事、设计相关合同、App/Management/Assistant 和工作项实际入口，并独立审阅 `ui-framework-v2.md`、`frontend-v2.md`。

重建前实际阻断：

1. `WorkItemDetail` 声明 `onOpen` 却未消费，没有子项/范围/批次入口。旧 `ItemRelations` 等文件存在不能证明用户能执行分治。
2. 完成条件入口散落成果/记录，成果无交付时不显示入口；要通过记录跳回成果才能核对。验收应独立于交付、有无流程和当前 Tab。
3. 简化 `canComplete` 强制自身条件非空，拒绝“无自身条件、全部子项已确认”的结构父项；同时未呈现子项范围阻塞。服务端能拒绝结项不等于用户能理解和处理阻塞。
4. 记录只列私有 `work.runs`，不能覆盖 WorkItem 跨方法 `item.runs`；旧方法绑定项目、来源、历史固定运行不能被新私有流程遮蔽。
5. 成果只有来源/记录接续，旧精确引用依据、比较、候选建子项没有在 composition 实际入口接通；共享 RunInspector 存在不等于这些工作项动作存在。
6. 输入把文件名、提取材料、接续值重复铺开，缺少资料身份与本轮采用的关系；不可按同名推断同一身份。
7. 1024 仅“打开 Assistant”，1440 长会话未保证 Composer 在视口内。后端 assistant 动作能自行初始化私有 work，所以问题是输入可达性与布局，不能误报为必须先点击初始化。
8. 流程可处于等待，但详情没有明确的原因/截止/匹配事件提交任务；查看执行和停止不能替代发送事件。

已把 1–8 中的能力迁移风险发给 root 与 UI agent。框架文档已覆盖上述落点，最终是否完成仍以实施后真实路径为准。

## 最小任务结构

| 位置 | 用户在做什么 | 必要入口与结果 |
| --- | --- | --- |
| 工作项列表 | 找到要继续的事情 | 一个搜索、一个带全局数量的状态筛选体系、稳定行序/分页；标题进入详情；业务状态与运行状态有各自明确列义 |
| 创建 | 登记要做的事并带入需求 | 标题/目标、文件或文字直接可加；编号/条件/方法按需；无方法、无条件可创建；创建后进入同一工作项并直接输入 AI |
| 详情页头与导航 | 确认身份和位置 | 返回、标题、一个业务状态、目标详情；成果/流程/输入/记录；固定完成条件入口；子项返回父项，列表返回保留过滤和滚动 |
| 成果 | 阅读本轮实际交付并决定下一步 | 交付切换与固定来源；表格查看/查找/排序/分页/选择；精确来源；继续处理、引用依据、明确候选建项按实际内容出现 |
| 流程 | 检查/修改处理方法并运行 | 真实依赖图、就近保存/放弃、一次运行或停止/恢复入口；选中才配置；等待原因/截止/事件任务；保存为公用方法 |
| 输入 | 看资料并准备本轮输入 | 上传/补材料、统一阅读器、明确材料身份与表示、本轮是否采用；声明字段填写与修订；来源和旧修订可查 |
| 子工作项任务面 | 划分业务身份与范围 | 流程工具行固定“子工作项 N”，无子项也可添加；直属/范围待办/排除、搜索/分页、明确批量与暂停、子项成果继续；不是 call 实例树 |
| 完成条件任务 | 人工核对业务完成 | 定义保存、精确引用/文字依据、人工勾选、范围阻塞；显式结项、带原因重开；任何 Tab 与无交付状态可达 |
| 记录 | 查发生过什么及当时证据 | 一份业务时间线与跨方法固定运行入口；旧输入、旧定义、旧条件保持当时事实 |
| Assistant | 在当前事情中表达与修改 | 同一个现有 Assistant/Thread/Composer；空项可写、长消息不挤掉输入；错误/停止/重试如实显示；不自动发送预置长请求 |

成果表的“记录”是同一交付中的稳定记录身份；子项是独立业务工作身份；调用节点是方法执行关系。三者不因数量或数组结构自动互换。通用界面不出现固定 CVE 处置字段、补证/整改分类或业务推断。

## 能力迁移的具体反例

### 无条件结构父项

最小输入：父项无自身条件，有两个已结项且在范围内的子项。

预期：完成条件任务显示子项 2/2 和可检查的完成依据，人工确认整项。反例：`criteria.length > 0` 作为唯一门槛使此项永远不可结。另一个子项重开时，父项要显示真实阻塞和入口，不能只把按钮禁用或等服务器报错。影响分治故事 6、H10。

### 精确成果作为依据

最小输入：一个运行的两份产物，用户正检查第二份；工作项有一个已保存条件。

预期：明确把第二份实际来源加入该条件，保留实例/产物身份，重复加入不重复记账；引用不自动勾选、不自动结项。反例：只复制报告文字或只链接整个 Run，丢失精确依据；或者新成果页根本找不到引用入口。影响 H10、就地验收合同。

### 跨方法历史

最小输入：旧公用方法有一轮成果，新私有流程有另一轮，二者属于同一 WorkItem。

预期：记录中都能进入固定 Run；当前编辑不会改写旧输入或定义。反例：仅遍历私有 `work.runs`，历史第一轮消失。影响 H3/H9。

### 资料身份与表示

最小输入：上传一个文件形成材料 M；接续值 I 明确引用 M；另有同名但无来源的值 J。

预期：M 的原文/提取表示/本轮采用在同一身份行组织；I 可归入明确关联，J 保持独立；修订保留来源与前版本。反例：文件 chip + 材料卡 + adopted 输入各占一块，或者按同名把 J 错并入 M。影响 H1/H3/H9。

### 记录接续的失败

最小输入：31 条记录跨两页，选择稳定 ID F01 与 F27，切 Tab、轮询、排序后进入后续方法；首次请求使用过期交付/修订失败。

预期：两条身份和原选择保留，错误在当前任务内可见，确认重试后后端实际只消费这两条；来源从保存交付重读。反例：按行下标继续、轮询清空选择、错误后关闭弹窗或自动启动不明确方法。影响工作项整体成果故事 8。

### 等待与恢复

最小输入：等待事件节点，含原因与截止。

预期：流程可见原因/截止，用户提交事件 ID 与 payload 后同次 Run 继续；不匹配消息失败可见。中断恢复、停止和发送事件各自有明确动作。反例：只展示“等待”并提供“停止”，用户无法推进。影响 H6/H8。
