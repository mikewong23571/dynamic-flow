# 生命周期验收设计

这些用例以工作项的持续身份和业务进展为断言，不以节点完成数量推断业务完成。

| 路线                  | 自动化证据                                      | 关键反例                                                                                                                     |
| --------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| L1 独立工作项共用方法 | lifecycle-integration 第一例                    | 两项材料互不串入，方法样例不进入工作项；运行完成仍 open；GET 不产生进展                                                      |
| L2 外部事件跨重启     | lifecycle-integration 第二例                    | close 后同一真实临时目录重建应用；错误事件不唤醒，相同消息幂等、ID 冲突拒绝；已完成 Agent 调用次数不增加；补证据不倒灌旧运行 |
| L3 到期与停止         | lifecycle-integration 第三例                    | 关闭期间过期，重建继续原 runId；停止后迟到消息及定时器均不能提交后续进展                                                     |
| L4 失败与方法演进     | lifecycle-integration 第四例                    | 输出 schema 失败不提交里程碑；换方法仍同一工作项；旧运行对象深比较不变；preview 不写业务对象                                 |
| L5 依据结项与重开     | lifecycle-integration 第一例、workitems.spec.ts | 未满足或无依据拒绝；结项重开保留历史和身份；页面与 HTTP 一致                                                                 |

HTTP 集成用 `createApplication({dataRoot, executeNode})`：HTTP 路由、文件存储、Schema 校验、调度、业务更新和恢复都是真实模块。只将 Agent 的生成结果替换为确定性回调，以稳定验证边界；不能据此宣称真实模型的判断质量已经验收。

浏览器测试通过 UI 创建、推进、提交事件、填写条件依据、结项与重开。在 1440×900 和 1024×768 检查操作、滚动边界、页面错误以及外部 HTTP 一致性。方法通过 HTTP 创建为内置 identity → 里程碑 → 等待 → 里程碑，无模型替身也无模型调用。浏览器刷新只证明页面重开，进程重启由根任务另做证据。

应用重建测试证明文件恢复接线；真实服务进程重启、跨天可控时钟、模型端点调用、视觉品味均需各自证据，不能由这组测试替代。
