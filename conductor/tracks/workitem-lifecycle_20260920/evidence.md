- 初始去重仅限 Run，旧事件重投能唤醒新运行：改为工作项全部跨方法历史去重，补真实 HTTP 回归。
- 局部重试丢掉 workItem，同名 M01 会指向方法示例：冻结上下文随重试/结果续做/比较继承，补修前失败、修后通过的回归。
- 模型与运行器两套 Schema 检查含义不同：统一使用 Ajv；未知 keyword/format 明确失败，禁止忽略拼错约束。
- 控制节点的整批 Schema 被错当成单值端口约束，分流输出约束也曾未执行：等待/里程碑按元素推断透传端口，Branch 分流前检查实际值，两个修前失败/修后通过的回归关闭。
- 定时测试把中间 running 当作终态：改为只读等待真正终态，不盲目延长 sleep。
- 已结项仍显示可补证据：按钮与服务端状态规则同步；历史依据可展开查看。

## 原型边界

- 单进程、本地文件；只恢复声明式节点结果与等待，不恢复任意 JS 调用栈。未知外部调用需显式继续，可能重做，不保证外部副作用恰好一次。
- 独立节点并发最多4，逐项并发1–8。Ajv draft-07 为实际调用契约；静态只检查确定的顶层类型冲突，不是完整类型证明。严格 reduce、独立 filter、全图端口类型推导未实现。
- 工作项正式启动当前要求单一材料输入端口；目标创建时确定。完成依据由用户明确确认，不是自动事实认证。工作项列表为搜索/状态筛选，方法工作库另有分页与归档。
- 事件发送面向已经进入等待的当前运行；没有提前事件收件箱或周期调度平台。不同工作项/不同修订的结果需要分别续做。
- 跨天/月通过持久绝对期限、受控时间及真实短期限重启验证，没有等待真实45天或做生产耐久/负载测试。
