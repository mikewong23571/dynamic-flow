# 工作项内检查成果与推进业务

2026-10-22。用户已要求解决详情信息架构问题，强调前端应提供操作与信息处理能力，并适用于不同流水线。沿用本仓现有 tracks 目录与单进程应用，不迁移任务工具。

## 产品目标

工作项是持续处理业务的入口。用户可在其中选择某轮推进、某个环节、某份产物，检查实际输入与来源，比较成果，并将明确选择的成果用于证据或完成条件。查看过程保留业务身份和当前位置。

用户路线：打开工作项 → 看实际执行与已有成果 → 选择环节/成果 → 检查内容、追溯输入 → 返回原成果 → 补证据或确认条件。业务历史围绕各轮推进组织，完整报告按需展开。

## 最小输入、输出与错误

输入为现有 WorkItemView、关联 Work 的 Snapshot、各轮固定 Definition/Run、NodeResult、输入材料和 sourceResultIds；不新增业务状态或猜测业务字段。输出为可交互的轮次/环节/实例选择、单份成果检查、输入来源导航、字段比较及显式业务动作。源快照读取失败显示错误与重试，保留已取得内容；不存在的指定节点/实例明确提示，不静默替换为别的成果。模型报告不等于产物成功，Run 完成不自动结项。

## 修改范围

- client/features/work-items：重组详情、执行/成果检查、按轮次组织记录；就近实现实际所需的快照读取与导航。
- client/features/results：复用结构化值查看组件；提供集合查找/排序/行检查、嵌套展开与原文查看，不按业务类型硬编码。
- client/app/App.tsx：离开工作项查看方法时保留其组件状态，并提供直接返回入口。
- docs 与就近 AGENTS、正式浏览器测试：同步产品行为和证据。

保留现有业务 API、定义语义、用户数据、模型设置。避免 CVE 专用页面、自动推断业务结论、布局 DSL、通用插件/展示平台。

## 验收

1. 至少两种不同内容的流水线使用同一套查看能力：结构化集合与文本报告，且有跨方法历史。
2. 从报告来源打开精确节点/实例，显示人可读的轮次/环节身份；旧的取消运行与当前运行清楚区分。
3. 产物 → 实际上游结果/冻结材料 → 返回，保持选择；查看方法后一步返回原工作项，保留表单和选中成果。
4. 集合可搜索、排序和打开单行；嵌套长内容不默认铺满页面；比较只报告真实字段差异，不推断业务含义。
5. 用户显式选择成果可补为证据或引用到完成条件，保持原 Run 不变，且不自动确认条件或结项。
6. 空内容、无运行、执行中、失败/取消、快照读取失败、旧报告与未保存表单均如实处理。
7. 本地 Playwright 检查 1440×900、1024×768，真实 CVE 工作项只读检查；写入验证使用独立临时数据。
