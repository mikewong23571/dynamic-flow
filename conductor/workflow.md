# Project Workflow

本文件从 Conductor 默认 workflow 模板复制后，按用户明确的原型范围与“先初始化、后选型”顺序精简。当前已有组件接入 example，不代表正式应用已经实现。

## 工作原则

1. 优先完整、可用的用户操作闭环，再补局部能力。
2. 保持实现简单、可解释、可局部修改；使用现成组件而非重建通用基础设施。
3. 实现任务在对应 track 的 plan.md 中追踪；技术决定在 tech-stack.md 中记录。
4. 核心业务规则和缺陷修复采用有意义的测试，优先 Red → Green → Refactor。
5. 前端必须同时验证交互、真实内容与视觉一致性。
6. 安全、权限、隔离、生产治理及分布式运维不属于原型计划与验收范围。
7. 用户当前指示优先；已授权范围内持续推进，不为例行、可逆工作反复要求确认。

## 当前阶段

用户已授权并完成组件接入 Spike。依赖与示例用于选型，正式实现仍须单独建 track；不因为实验安装了某库就自动采用，也不生成大规模 monorepo 骨架。

## 每项任务

1. 读取产品定义、产品指南、技术栈和当前 track；明确可观察的用户结果。
2. 在 plan.md 中将任务从 `[ ]` 标为 `[~]`。
3. 核心业务行为先写最小有效测试并看到预期失败，再实现。例如版本绑定、样本选择、采用方法与保留结果的区别。
4. 使用最少的必要代码实现；优先组合已有组件。根据项目实际采用的工具运行相关检查。
5. 对纯排版、文案、文档等低影响可逆修改，不编写镜像实现的单元测试；采用阅读、浏览器或截图检查。
6. 结果通过后才标为 `[x]`。记录改动理由、验证结果、必要限制与对应提交。
7. 提交范围聚焦当前工作；避免把用户的其他未提交文件混入提交。

## 前端实施顺序

1. 描述当前用户任务、对象、状态和主要动作。
2. 查看相关成熟产品和所选设计体系的具体实例，记录少量参考与采用理由。
3. 从已有控件体系选择布局与操作方式；需要新模式时明确原因。
4. 用真实样本实现代表性的完整工作区，包含相关空、加载、成功和失败状态。
5. 在浏览器中实际操作，并查看截图；检查主次、密度、文字、控件一致性、阅读位置与窗口变化。
6. 先修正代表页面，再把模式复用到其他页面。不得把占位按钮或模拟事件称为真实功能完成。

## 验证与完成标准

- 当前任务的真实用户路径能完成，关键操作有实际结果。
- 相关测试与已配置的类型、构建、静态检查通过；不编造尚不存在的命令。
- 无统一覆盖率百分比门槛，也不要求每个文件配一个测试；优先覆盖有意义的业务边界。
- 前端改动完成浏览器操作与必要视觉检查，不能仅靠测试通过或代码阅读验收。
- 产品状态、候选状态、运行状态准确区分；记录不支持的部分。
- 修改保持简单，组件与业务概念对应；说明实际必要的实现理由。
- 文档与真实实现一致，不把计划、库文档核对或 mock 演示当作集成通过。

## 阶段检查

完成一条纵向用户路径后，运行一次相关自动检查与完整交互验证。通过后不无目的地扩大测试范围。

如失败，定位原因并修复；只有缺少必要用户输入、外部条件或发生范围冲突时才请求帮助。记录未通过事项，不把局部成功称为整个产品完成。

阶段记录使用当前 track 的 plan.md：写明已完成行为、实际命令与结果、浏览器证据以及提交。仅当用户明确要求验收确认时，把该确认作为阶段门槛。

## 选型与变更

选型记录包含：具体需求、采用方案、理由、使用边界。候选与最终决定分别标注。

若实现时发现选型不适用，先说明具体原因，更新 tech-stack.md 与任务范围。重要产品交互或关键组件替换由用户参与决定；局部实现细节在既定范围内直接处理。

## 风格指南适用范围

conductor/code_styleguides/ 下的 general、typescript、html-css 原样复制自 Conductor 现有资产，作为参考，不因此自动安装 gts 等工具。

应用代码尽量遵循指南；框架入口或 Method 协议需要 default export 时允许使用。HTML 指南的大小写与文件组织要求按 React/TSX 实际语义应用，不改坏组件名，也不要求为遵守传统 HTML 文件划分而拆散组件。具体格式以以后选定的自动格式化工具为准，不为了模板偏好增加开发成本。

## 开发命令

从仓库根运行：`pnpm install --frozen-lockfile`、`pnpm dev`、`pnpm test`、`pnpm typecheck`、`pnpm build`、`pnpm format:check`、`pnpm test:browser`。首次浏览器检查先运行 `pnpm exec playwright install chromium`。

示例服务为 4317/4318；复跑说明和能力边界见 `examples/component-spike/README.md`。检查命令均为单次执行。

## 提交与文档

提交信息格式：`<type>(<scope>): <description>`。按可解释的工作单元提交，不机械地每个小步骤拆多个提交。

产品代码变更与必要文档保持同步，任务摘要记录在 track 中；不强制附加 Git Notes 或额外审计基础设施。

当前初始化提交使用：`conductor(setup): Initialize project context and standards`。

## 后续能力

仅在当前任务确有需要时新增技能或基础设施；本次检查的技能目录中没有需要安装的匹配项。不要为可能的未来需求预先搭建部署、鉴权、隔离或遥测平台。
