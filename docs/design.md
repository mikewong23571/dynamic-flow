# Dynamic Workflow Workbench — 产品与技术设计 v5

更新：2026-09-20。本轮新增 [管理页与函数式 IR](../conductor/tracks/functional-ir-management_20260920/index.md)，实现与验收状态分开。当前基线从一次材料加工扩展为业务工作的持续推进，替代 v3 的“Work 即业务任务、顺序执行、重启仅标中断”假设。[原始 v2](<./archive/Dynamic Workflow Workbench — 产品与技术设计 v2.md>) 原样归档。本文件记录实现边界；产品验收结论由 [本轮证据](../conductor/tracks/workitem-lifecycle_20260920/evidence.md) 汇总，不能用模块实现或类型检查代替。

## 1. 产品与范围

用户登记需要持续推进的工作项，选择处理方法；通过画布与 Assistant 建立和修改方法，通过执行取得证据、记录业务进展、等待外部消息或到期，再继续同一件事。管理者看到阶段、依据、等待原因、下一触发和最近业务进展，而不只看到节点计数。

“调查一个 CVE 对产品 A 的影响，等待修复公告，补充证据并完成验证”是生命周期验收样例；产品不内置 CVE 判断规则。原有反馈分类、样本比较与报告生成作为方法编辑和数据处理能力继续保留。

原型优先可用、用户友好、实现简单、容易指导修改。安全、权限、隔离、多租户、分布式部署与生产治理不属于范围。跨时间等待与恢复是已授权用户故事需要的功能，不因“原型”而省略；也不因此建设通用执行平台。

## 2. 三个生命周期，三个明确对象

| 对象                  | 负责什么                                                         | 生命周期与关系                                               |
| --------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| Work / 方法工作区     | 方法标题、目标说明、样例材料、定义版本、编辑会话、布局及运行记录 | 保留原有编辑与工作库功能；不是业务工作的唯一身份             |
| WorkItem / 业务工作项 | 业务编号、标题、目标、完成条件及依据、独立证据、阶段、摘要、历史 | 可经历多次运行并切换方法；身份与过去证据持续存在             |
| Run / 执行            | 固定方法版本、输入与工作项修订、实例结果、等待、事件与终态       | 运行成功不自动结项；工作项通过 workId + runId 关联跨方法历史 |

Definition 是不可变的工作流定义版本；NodeResult 记录一个节点实例的输入、输出、状态和来源。方法样例材料与工作项证据分开，工作项运行只使用启动时冻结的自身材料与目标。

业务状态为 open/completed；管理视图结合当前运行派生待推进、推进中、等待中、需处理、已结项。`progressAt` 来源于业务变更，不由运行心跳刷新。工作项有未决运行时不能静默切换方法或另起并行运行；不同工作项可使用同一方法同时推进。

## 3. 一份 IR，画布与 Agent 共同编辑

IR（Intermediate Representation，中间表示）是本应用有限、声明式的 JS 语义子集，以节点、参数、连接和输入输出表达处理过程。它保存为应用生成的 JS 模块对象；Node runtime 读取并执行明确语义，并非把任意画布 JSON 交给 JS 引擎即可运行。

- 人和 Assistant 修改同一份 Definition；节点由稳定 ID 关联，布局单独保存。
- 人通过画布、节点配置或自然语言修改，JS 只读查看。
- 不从任意源码反推图，不建设源码索引、AST 双向转换、闭包捕获或任意代码导入。
- 定义图与执行实例分开；一百条输入不复制一百个画布节点。
- 普通连线为无环依赖图；不提供任意回连、无限循环、递归子流程或完整 BPMN。

### 3.1 节点职责与组合运算

| 节点      | 当前语义                                                                         |
| --------- | -------------------------------------------------------------------------------- |
| Agent     | 任务和明确输入交给 Pi，返回有类型的结果；工具活动关联实例                        |
| Function  | 调用 identity / select-fields / merge / collect / join，或执行 expression 纯数据变换                             |
| Branch    | 有限字段条件，将输入路由到 matched / unmatched 端口                              |
| Milestone | 明确声明业务阶段与摘要；正式推进时记录输入证据与来源，再透传输入                 |
| Wait      | 保存事件名称、原因及可选相对截止时间；匹配事件或到期后继续，输出原输入与触发事件 |

Agent / Function 的 `operation` 区分 map、flatMap、aggregate：map 单项转换并保留数组值，flatMap 明确展开一层，aggregate 收齐本次输入后调用一次。并发是执行策略，不改变类型。已有 each/all 定义仍可读取；未设 operation 的旧普通函数维持历史透传方式，避免升级改写旧报告。

`inputSchema` / `expectedOutput` 描述单次调用的输入/返回值，运行前后通过 Ajv 校验。Map 为 T → R，FlatMap 为 T → R[]，Aggregate 为 T[] → R。schema 错误不能进入下游或成为业务进展依据。连接时只检查可以确定的顶层类型冲突，不声称实现任意 JSON Schema 子类型证明。

纯表达式增加 pipe / map / filter / flatMap / 有初值顺序 reduce，以及 match / let 的模式匹配和解构。它们表达节点内部的值变换，不改变节点调用与端口展开规则。画布配置使用结构化控件，细节见 [纯函数 IR](functional-ir.md)。完整端口类型推导及 JSON Schema 字段编辑器尚未实现。LLM 汇总不保证结合律，不能当作并行 reduce。

### 3.2 时间与业务影响是显式语义

```text
工作项固定输入
  → Map 调查材料
  → Milestone：记录调查进展与证据
  → Wait：等待公告，或三天后到期
  → Agent 复核（可接收 wait.event 的消息内容）
  → Milestone：记录复核结果
```

里程碑只在 workItem + full + commit 的正式运行中更新业务状态，以 runId + nodeId 去重。单节点试验、候选比较与普通方法预览不提交业务进展；预览等待直接透传并在事件输出标记 preview。预览不能作为真实事件已发生的证据。

里程碑记录阶段、摘要和输入来源，不自动宣告目标成立。结项需要用户逐条确认完成条件并填写依据；未满足条件或存在未决运行时拒绝结项。重开保留以前的结项和依据历史。

## 4. 运行与恢复

1. 执行前固定定义、显式输入、工作项修订和 effectMode；后续新增材料或修改方法不倒灌旧运行。
2. 就绪独立节点最多 4 个并行；逐项并发默认 1，可设置 1–8，输出仍按输入顺序与来源关联。
3. 实例在实际调用前后检查 schema；一项失败保留其它成功结果，依赖完整集合的下游阻断。空集合、空分支仍有明确完成语义。
4. Wait 与成功实例结果保存到 Run；等待释放运行资源，服务启动后重新安排持久等待与已到期任务。
5. 同一事件 ID 的相同消息重复提交不重复继续，冲突重用报错；停止后的事件与定时器不能启动后续步骤。
6. 进程在外部调用过程中退出时，无法确认的执行标为 interrupted，需显式恢复；已成功实例不重跑，不确定调用可能再次执行。
7. 停止中止活跃 Pi 请求并阻止后续调度，迟到响应不覆盖终态。SDK 的请求中止不等于远端计算必然已停止。

持久恢复限定在已声明图、实例结果和等待检查点，不恢复任意 JS 调用栈，也不承诺所有外部副作用恰好一次。当前为单进程本地文件方案；不包含生产级分布式调度、通用事件回放或任意外部动作连接器。

## 5. 用户操作与管理视图

侧栏“工作项”管理业务；“流水线”保留方法工作库的搜索、分页、标题、归档和恢复，未归档不再叫进行中。工作项列表支持搜索、状态筛选与分页，轮询保留已有行的位置，展示阶段/摘要、执行异常与等待、最近业务进展；详情提供证据、条件依据、方法、运行与历史。外部系统通过只读 HTTP 获取相同状态，通过显式动作提交事件，不必抓取页面或解析聊天。

方法画布仍是主要编辑入口。选中后编辑任务、组合运算、并发、schema、等待或里程碑；节点卡只显示必要摘要，结果实例按需展开。Geist 暗色和正式 shadcn/Radix 控件统一管理页页头、表格、搜索、分页、菜单与键盘标签页；旧工作区通过兼容入口复用按钮和对话框。字段密度与布局须由实际 1440/1024 操作和截图检查，测试通过不代替用户审美判断。

Assistant 固定请求中的方法版本、节点与样本上下文，工具真实修改后通过快照更新画布；模型“声称修改”不等于保存发生。工具日志和执行进度用于解释过程，不能取代工作项业务状态。

## 6. 方法演进、试验与证据

- 单节点试验使用明确样本输入，不捕获闭包；候选比较使用同一冻结输入和公共运行路径。
- 修改节点、运算或 schema 形成新定义；旧比较标记过期，旧结果按旧版本解释。
- 采用定义与保留产物是独立动作。显式选定旧/新结果后发起新的运行，保留来源；不自动拼接“最新结果”。
- 工作项补充证据、采用新方法再运行时保留同一业务 ID；跨方法历史记录完整的 workId/runId/definitionId。
- 新输入续做是新 Run；等待释放与中断后显式 resume 是同一 Run 的有限恢复，两者不可混称。

## 7. 模块与存储

一个 React/Vite 前端和 Node/Hono 后端，复用 React Flow、Radix、assistant-ui、Pi、Ajv、Markdown/GFM。方法快照通过 SSE 更新，工作项视图通过只读 HTTP 轮询；不新增通用前端状态平台。

- `data/<workId>/work.json`：方法元数据、样例材料、布局、运行（含检查点、等待、事件）、比较与消息。
- `data/<workId>/definitions/`：不可变 JS 定义。
- `data/work-items/<id>.json`：独立业务工作项、条件依据、证据与历史，按工作项串行原子替换。
- `data/model-settings.json`：工作台模型配置，优先于 `.env.local` 初值。

不同时维护文件和数据库两套权威状态。单进程文件方案的容量和多进程限制仍存在，真实反例出现时调整存储或运行时，不为维持骨架删掉故事。

模型设置支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 兼容端点及推理强度等参数。保存配置仅验证格式，不代表端点已验证；密钥不回显，不写入工作项。模型失败明确暴露，不切换假模型。

## 画布阅读与布局

画布复用 ELK 的分层布局和正交路由，使用实际节点尺寸与端口坐标，在固定端口顺序下减少交叉并绕开节点。首次没有保存位置时自动整理；已有流程通过“整理布局”主动调整，运行进度不触发布局。

默认概览展示节点摘要和端口数量；悬停、选中或“显示端口”展开名称。选中节点突出直接上下游，悬停/键盘聚焦端口只突出该端口的连接，并显示来源和目的。暂不增加没有执行语义的业务节点或分组体系。

位置、视口、显示端口选项及带几何签名的路由属于 ViewState，与 IR 分离。手动移动或改端口后旧路径失效，回退普通连接，主动整理重新规划。异步整理不得覆盖之后的拖动或定义修改。实现与两尺寸验证见 [画布布局验收](../conductor/tracks/canvas-layout_20260920/evidence.md)。
