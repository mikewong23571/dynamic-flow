## 本轮优化：问题驱动的动态工作流

2026-09-21。认知提升、方案取舍和第一性原理审查见 [问题驱动方案](semantic-workflow.md)。新增版本化问题认知、步骤合同、局部动态子图、有限步骤迭代和运行证据回用。沿用单一依赖图执行路径，不增加另一套 DSL 或平台。七个概念的具体映射与原型限制以该方案为准。动态子图和逐轮实例是 Run 事实，不改写原定义。

## 1. 产品与范围

用户登记需要持续推进的工作项，选择处理方法；通过画布与 Assistant 建立和修改方法，通过执行取得证据、记录业务进展、等待外部消息或到期，再继续同一件事。管理者看到阶段、依据、等待原因、下一触发和最近业务进展，而不只看到节点计数。

“调查一个 CVE 对产品 A 的影响，等待修复公告，补充证据并完成验证”是生命周期验收样例；产品不内置 CVE 判断规则。原有反馈分类、样本比较与报告生成作为方法编辑和数据处理能力继续保留。

原型优先可用、用户友好、实现简单、容易指导修改。安全、权限、隔离、多租户、分布式部署与生产治理不属于范围。跨时间等待与恢复是已授权用户故事需要的功能，不因“原型”而省略；也不因此建设通用执行平台。

## 2. 三个生命周期，三个明确对象

| 对象                  | 负责什么                                                         | 生命周期与关系                                               |
| --------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| Work / 方法工作区     | 方法标题、目标说明、样例材料、定义版本、编辑会话、布局及运行记录 | 保留原有编辑与工作库功能；不是业务工作的唯一身份             |
| WorkItem / 业务工作项 | 业务编号、标题、目标、完成条件及依据、独立证据、阶段、摘要、历史 | 可经历多次运行并切换方法；身份与过去证据持续存在             |
| Run / 执行            | 固定方法版本、输入与工作项修订、实例结果、等待、事件与终态       | 运行成功不自动结项；工作项通过 workId + runId 关联跨方法历史 |

Definition 是不可变的工作流定义版本；NodeResult 记录一个节点实例的输入、输出、状态和来源。方法样例材料与工作项证据分开，工作项运行使用启动时明确选定并冻结的材料、结构化输入或完成依据，不隐式复制父项或其它工作项的历史。

业务状态为 open/completed；管理视图结合当前运行派生待推进、推进中、等待中、需处理、已结项。真实执行/等待/失败优先于报告的业务阻碍；空闲工作项存在明确阻碍时显示需处理。`progressAt` 来源于业务变更，不由运行心跳或活动步骤切换刷新。工作项有未决运行时不能静默切换方法或另起并行运行；不同工作项可使用同一方法同时推进。

## 3. 一份 IR，画布与 Agent 共同编辑

IR（Intermediate Representation，中间表示）是本应用有限、声明式的 JS 语义子集，以节点、参数、连接和输入输出表达处理过程。它保存为应用生成的 JS 模块对象；Node runtime 读取并执行明确语义，并非把任意画布 JSON 交给 JS 引擎即可运行。

- 人和 Assistant 修改同一份 Definition；节点由稳定 ID 关联，布局单独保存。
- 人通过画布、节点配置或自然语言修改，JS 只读查看。
- 不从任意源码反推图，不建设源码索引、AST 双向转换、闭包捕获或任意代码导入。
- 定义图与执行实例分开；一百条输入不复制一百个画布节点。
- 普通连线为无环依赖图；不提供任意回连、无限循环、递归子流程或完整 BPMN。

### 3.1 节点职责与组合运算

| 节点      | 当前语义                                                                         |
| --------- | -------------------------------------------------------------------------------- |
| Agent     | 任务和明确输入交给 Pi，返回有类型的结果；工具活动关联实例                        |
| Function  | 调用 identity / select-fields / merge / collect / join，或执行 expression 纯数据变换                             |
| Branch    | 有限字段条件，将输入路由到 matched / unmatched 端口                              |
| Milestone | 明确声明业务阶段与摘要；正式推进时记录输入证据与来源，再透传输入                 |
| Wait      | 保存事件名称、原因及可选相对截止时间；匹配事件或到期后继续，输出原输入与触发事件 |
| Create-items / 建立子项 | 将明确候选保存为当前工作项的子项并返回回执；仅 full/commit 写入，preview 只展示候选 |

Agent / Function 的 `operation` 区分 map、flatMap、aggregate：map 单项转换并保留数组值，flatMap 明确展开一层，aggregate 收齐本次输入后调用一次。并发是执行策略，不改变类型。已有 each/all 定义仍可读取；未设 operation 的旧普通函数维持历史透传方式，避免升级改写旧报告。

`inputSchema` / `expectedOutput` 描述单次调用的输入/返回值，运行前后通过 Ajv 校验。Map 为 T → R，FlatMap 为 T → R[]，Aggregate 为 T[] → R。schema 错误不能进入下游或成为业务进展依据。连接时只检查可以确定的顶层类型冲突，不声称实现任意 JSON Schema 子类型证明。

纯表达式增加 pipe / map / filter / flatMap / 有初值顺序 reduce，以及 match / let 的模式匹配和解构。它们表达节点内部的值变换，不改变节点调用与端口展开规则。画布配置使用结构化控件，细节见 [纯函数 IR](functional-ir.md)。完整端口类型推导及 JSON Schema 字段编辑器尚未实现。LLM 汇总不保证结合律，不能当作并行 reduce。

### 3.2 时间与业务影响是显式语义

```text
工作项固定输入
  → Map 调查材料
  → Milestone：记录调查进展与证据
  → Wait：等待公告，或三天后到期
  → Agent 复核（可接收 wait.event 的消息内容）
  → Milestone：记录复核结果
```

里程碑只在 workItem + full + commit 的正式运行中更新业务状态，以 runId + nodeId 去重。单节点试验、候选比较与普通方法预览不提交业务进展；预览等待直接透传并在事件输出标记 preview。预览不能作为真实事件已发生的证据。

里程碑记录阶段、摘要和输入来源，不自动宣告目标成立。结项需要用户逐条确认完成条件并填写依据；未满足条件或存在未决运行时拒绝结项。重开保留以前的结项和依据历史。

正式工作项的普通 Agent 执行还可调用 `report_progress`，将阶段、摘要、下一步、业务阻碍和材料引用提交给同一 work-items 保存路径。报告关联固定执行身份，保存在既有业务历史中；它是 Agent 声明的进展，区别于里程碑和用户确认。节点后续失败不会把报告抹掉，也不会使报告成为验证成功的事实。作者、动态规划与 preview 不提供此工具；停止和旧运行的迟到报告被拒绝。外部报告通过现有 actions 提交，无运行来源时需当前 revision 且工作项无未决运行。复用历史 ID 去重与原子文件保存，不新增进展实体、状态机或事件平台。

`nextAction`、`blocker` 是工作项的可选文本；业务阶段与摘要仍沿用既有字段。新运行、换方法、结项、重开及后续里程碑清除失效的下一步与阻碍，旧值保存在报告历史。报告不创建 RunWait、不自动结项；没有报告时如实显示缺失。具体输入、错误与验证见 [进度 track](../conductor/tracks/workitem-progress_20261021/spec.md)。

## 4. 运行与恢复

1. 执行前固定定义、显式输入、工作项修订和 effectMode；后续新增材料或修改方法不倒灌旧运行。
2. 就绪独立节点最多 4 个并行；逐项并发默认 1，可设置 1–8，输出仍按输入顺序与来源关联。
3. 实例在实际调用前后检查 schema；一项失败保留其它成功结果，依赖完整集合的下游阻断。空集合、空分支仍有明确完成语义。
4. Wait 与成功实例结果保存到 Run；等待释放运行资源，服务启动后重新安排持久等待与已到期任务。
5. 同一事件 ID 的相同消息重复提交不重复继续，冲突重用报错；停止后的事件与定时器不能启动后续步骤。
6. 进程在外部调用过程中退出时，无法确认的执行标为 interrupted，需显式恢复；已成功实例不重跑，不确定调用可能再次执行。
7. 停止中止活跃 Pi 请求并阻止后续调度，迟到响应不覆盖终态。SDK 的请求中止不等于远端计算必然已停止。

持久恢复限定在已声明图、实例结果和等待检查点，不恢复任意 JS 调用栈，也不承诺所有外部副作用恰好一次。当前为单进程本地文件方案；不包含生产级分布式调度、通用事件回放或任意外部动作连接器。

## 5. 用户操作与管理视图

默认进入“首页”，左侧三个同级入口为首页、工作项、流水线：需求与文件可直接开始一项工作，下方继续最近未完成项；工作项入口提供全部工作项查询，流水线进入方法目录。“已打开的流水线”仍是本浏览器持久化切换区，关闭不归档、不停止。完整工作项列表提供搜索/状态筛选与分页，轮询保留已有行序；两种列表共用全宽内容布局，首页居中输入区单独处理。工作项固定成果/流程/输入/记录四面：成果导航来自交付声明，流程默认读图、主动进入手工编辑；子项在按需对话框内管理，记录合为一条时间线。工作项与流水线共用实际页头/导航/主区/可调宽侧栏；从工作项进入方法时在页头左侧返回原工作项并保留上下文。外部系统通过只读HTTP获取相同状态，通过显式动作提交事件。

方法画布仍是主要编辑入口。选中后编辑任务、组合运算、并发、schema、等待或里程碑；节点卡只显示必要摘要，结果实例按需展开。Geist 暗色和正式 shadcn/Radix 控件统一管理页页头、表格、搜索、分页、菜单与键盘标签页；旧工作区通过兼容入口复用按钮和对话框。字段密度与布局须由实际 1440/1024 操作和截图检查，测试通过不代替用户审美判断。

Assistant 固定请求中的方法版本、节点与样本上下文，工具真实修改后通过快照更新画布；模型“声称修改”不等于保存发生。工具日志和执行进度用于解释过程，不能取代工作项业务状态。

列表接口仍提供数量汇总：全部、未完成、已结项及四种未结项展示状态，界面在展开查找后可筛选、保留搜索并回到第一页。汇总基于同批服务端工作项视图在筛选前计算，不随搜索或分页缩小；`total` 继续是当前匹配数，`summary` 是全部工作项数量。未登记为 WorkItem 的普通 Work/Run/invoke 不计数。单项当前进展并列展示业务阶段、实际活动步骤、报告来源、等待/错误、阻碍与下一步；活动步骤从固定 Run 和展开子图只读派生，支持并行，不另存前端业务状态。Run 成功未结项显示明确提示，完成条件齐全时提示待结项确认。

## 6. 方法演进、试验与证据

- 单节点试验使用明确样本输入，不捕获闭包；候选比较使用同一冻结输入和公共运行路径。
- 修改节点、运算或 schema 形成新定义；旧比较标记过期，旧结果按旧版本解释。
- 采用定义与保留产物是独立动作。显式选定旧/新结果后发起新的运行，保留来源；不自动拼接“最新结果”。
- 工作项补充证据、采用新方法再运行时保留同一业务 ID；跨方法历史记录完整的 workId/runId/definitionId。
- 新输入续做是新 Run；等待释放与中断后显式 resume 是同一 Run 的有限恢复，两者不可混称。

## 7. 模块与存储

一个 React/Vite 前端和 Node/Hono 后端，复用 React Flow、Radix、assistant-ui、Pi、Ajv、Markdown/GFM。方法快照通过 SSE 更新，工作项视图通过只读 HTTP 轮询；不新增通用前端状态平台。

- `data/<workId>/work.json`：方法元数据、样例材料、布局、运行（含检查点、等待、事件）、比较与消息。
- `data/<workId>/definitions/`：不可变 JS 定义。
- `data/work-items/<id>.json`：独立业务工作项、父项关系、结构化交接、条件依据与历史；业务变更经单进程短队列串行，每个文件原子替换，不持锁等待模型。
- `models.toml`：模型目录和密钥（不提交）；`data/model-settings.json` 只保存全局默认选择。`.env.local` 不参与运行时回退；本轮按用户授权将其配置一次性导入目录。

不同时维护文件和数据库两套权威状态。单进程文件方案的容量和多进程限制仍存在，真实反例出现时调整存储或运行时，不为维持骨架删掉故事。

模型设置支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 兼容端点及推理强度等参数。保存配置仅验证格式，不代表端点已验证；密钥不回显，不写入工作项。模型失败明确暴露，不切换假模型。

## 画布阅读与布局

画布复用 ELK 的分层布局和正交路由，使用实际节点尺寸与端口坐标，在固定端口顺序下减少交叉并绕开节点。首次没有保存位置时自动整理；已有流程通过“整理布局”主动调整，运行进度不触发布局。

默认概览展示节点摘要和端口数量；悬停、选中或“显示端口”展开名称。选中节点突出直接上下游，悬停/键盘聚焦端口只突出该端口的连接，并显示来源和目的。暂不增加没有执行语义的业务节点或分组体系。

位置、视口、显示端口选项及带几何签名的路由属于 ViewState，与 IR 分离。手动移动或改端口后旧路径失效，回退普通连接，主动整理重新规划。异步整理不得覆盖之后的拖动或定义修改。实现与两尺寸验证见 [画布布局验收](../conductor/tracks/canvas-layout_20260920/evidence.md)。

## 明确选择的业务续做

WorkItem可无方法/条件创建。正式输入由准备动作选择实际材料或来源输出，经服务端读取并校验，固定Run.inputs、workItem材料和inputSources；历史Run不随新材料/版本改变。作者上下文是本次编辑的明确快照，与Work样例及Run输入分开。

工作项明确指定静态普通Agent/Function可做node/commit：只执行该节点，普通Agent可报告自己的当前进展；不自动结项、不提交未执行里程碑。其余node试验、retry、比较仍preview；里程碑full/commit规则不变。原始实例试验使用源Run实际result.input，比较两侧固定同一输入，不以分类输出冒充原文。


## 工作项分治与整体确认

一个工作项可以先独立处理，之后再建立子项，无需在创建时选择“聚合/执行”类型。子项仍是完整 WorkItem：有自己的目标、材料、条件与运行，同一个方法可由多个工作项复用。唯一 `parentId` 表示处理范围；关系排除保留原因和历史，不删除子项、不把未完成伪装成完成。

手工添加、成果候选清单和 `create-items` 节点共用建立动作。Agent理解材料并产生候选，应用负责保存身份及回执；普通数组输出不会自行建立工作项。手工候选引用固定输出，自动节点在首次写业务数据前保存自身输入引用。同源重试关联原子项，部分成功保留，失败项通过“重试未建立项”补建；通用运行重试仍是preview。父Run不递归启动或等待子项。

收到的结构化输入保存为独立条目与来源。准备页默认选未被替换的条目，用户可检查并修改；补充声明字段生成新修订并替换本次选择，旧值与旧Run不变。独立证据仍通过追加材料提交。精确成果引用包含输出端口与集合索引，用户通过页面选择，不填写技术ID；历史不精确引用不能猜测为第一项。

有效子项未完成时父项不能结项；子项均已完成且父项独立条件满足时，用户明确确认整体完成。无独立文字条件的父项可依据全部有效子项确认，不要求逐层生成报告。完成事件固定条件及子项完成事件引用；可选汇总读取这些已确认依据。后续重开不改写旧事件或旧Run。子项重开、新增或恢复纳入涉及已完成祖先时，页面一次展示受影响项并确认重开；已排除关系截断影响。

直属子项和范围内待办使用服务端摘要分页，详情按选定Run读取成果。批量处理复用单项准备与启动，明确固定各项方法、版本与输入后，由服务端持久保存批次并控制启动窗口（默认2个）；关闭页面后继续启动待处理项。等待和中断不占名额，中断不会自动重跑，显式恢复继续原Run并重新计数；恢复可能暂时超出窗口，期间不新增提交。暂停只停止后续启动，已启动Run继续；连续三项失败暂停批次。批次是启动编排，不替代各工作项的独立Run，也不是全局Agent并发硬限制。

完整页面故事及性能证据按[分治验收](../conductor/tracks/feature-workitem-decomposition_20261023/acceptance.md)记录；本地文件仍是唯一持久权威，不引入通用事项平台或数据库迁移。

## 本轮结果摘要

`Definition.summaryOutput` 可选，值是 `outputs` 中的输出名，例如 `summaryOutput: "overview"` 与 `outputs.overview: ["summarize", "output"]`。该节点必须是显式 `operation: "aggregate"` 的普通 Agent/Function，不可 repeat 或 dynamic。摘要作为普通节点产物随固定 Run 保存，没有单独的报告实体或可变摘要副本。

跨流水线展示使用 `src/shared/result-summary.ts` 的 `RunResultSummary`：必填 `title`（标题）、`summary`（业务摘要）、`scope`（本轮实际范围），可选 `metrics: {label, value: string | number}[]`、`limitations: string[]`、`nextAction: string`。文本必须非空，不接受其它字段。流水线决定业务意义和统计方法；UI 不从任意 JSON 字段、数组位置或节点名称猜测结论。运行器在节点自有 expectedOutput 之外校验共同 schema，违约使该环节真实失败，保留已有其它成果。

画布中普通整批处理节点可勾选“作为本轮结果摘要”，显式设置最终输出绑定及 expectedOutput；这不替用户生成节点实现。Assistant 的 update_flow 也接受同一声明。可确定的汇总用函数完成，不为界面格式另调用一次模型。CVE 源码核查模板在原记录集合之后新增函数，统计本轮核查记录总数及三种既有 conclusion 值，保留全部逐项目标依据；不自动汇总其它轮次。

新声明只影响使用该做法版本的新执行。历史运行按照原固定 Definition 读取；旧方法没有声明时展示实际成果分组。运行完成、摘要内容、工作项验收与最终结项是不同事实，摘要不修改工作项阶段、条件或状态。

## 待复核与后续问题闭环

`WorkItem.status` 仍只保存 open/completed；`effectiveStatus` 新增派生值 review（待复核），由 shared/workitem-status.ts 统一用于完整详情与摘要分页。当前推进意图的执行 completed 时进入 review，即使存在证据缺口；blocker 继续单独展示，不把复核项混入未推进或执行故障。queued/running/stopping、waiting 与执行失败保留各自优先级；重开或更换方法后旧执行不代表新一轮，未新执行时回到待推进（有业务阻碍时仍需处理）。只有用户确认条件与依据并显式结项，持久状态才改变。全局 summary 和当前范围 scopeSummary 独立统计 review，支持 status=review 筛选。

复核具体成果时，用户决定下一步，不按模型字段自动结项。下列是业务示例，不是通用界面的固定分类：

- 判断已有依据、不需后续处理：从“复核与跟进”引用固定成果作为验收依据，人工确认完成条件。
- 证据不足：建立“补充证据”子项，填写待确认问题和完成条件。
- 确认有影响：建立“影响整改”子项，明确处理与验证条件。

两种后续均复用既有 WorkItem、createChildren、receivedInputs、trackingKey 与范围结项校验，没有新增整改/复核实体或隐式执行。用户所选的单份输出通过 workId/runId/resultId/port/index 固定引用，并交接真实 JSON 原值与原始材料。相同来源与类型再次进入时展示既有子项，不因重复点击新增业务身份；不同目标可分别建立后续。未解决子项阻止原项结项，原项未结项继续阻止上级整批结项；后续解决并验收后，回到原项核对其条件与依据。补证后发现受影响，可以继续建立整改子项，不把“补证做完”直接解释为风险消除。

原成果和运行保持不变；新的核查依据、处理进展与结项决定写入对应工作项。模型的“证据不足/不受影响”只是待复核产物，不能自动转为人的确认。没有模型执行也可按实际人工证据推进子项，验收仍需真实依据。

## 验收证据收集与最终确认分开

逐项阅读时通过 citeCriterion 对明确条件追加 CriterionReference，精确到 workId/runId/definitionId/resultId/port/index，节点与实例使用真实来源；保存标签用于可读说明。串行重读当前业务记录并仅追加，保留其他条件、已有人工文字和 met；重复引用幂等。目标条件文字同时校验，防止删除/改名后把证据加到不同含义的条件。无新增证据实体、复核队列或一次性全量提交副本。

收集是已持久化的业务证据，勾选条件、保存其他草稿与最终结项是后续独立动作。成果检查留在原实例，顺序导航沿已有真实实例列表；不从是否引用推断“已复核全部目标”。未完成的补证/整改子项仍遵循既有结项阻塞规则。

### 子项阶段成果接续（2026-10-27）

父项可以在子项未结项时，明确选择范围内直属子项的已完成普通产物，作为下一段方法的输入。`ItemInputSelection.child-results` 固定 `itemId` 与精确 `sources`；来源必须属于该子项已关联的正式 Run，不能以预览、规划或未完成结果替代。中断或取消的 Run 中已经完成的普通产物可以选用。一个子项可以选择多轮产物，但同一样本的同节点多个版本仍需明确择一，不自动选择最新轮次或猜测业务去重规则。

每个所选子项形成一条 `InputItem`，其 JSON 值为 `ChildStageValue`：`{item:{id,key,title,goal,data},outputs:[{source:{workId,runId,resultId,port,index},value}...]}`。`item` 来自第一份所选来源 Run 的冻结身份；每份 `value` 保持原值，数组不自动展开。`Run.inputSources`、原文材料与来源结果 ID 同时固定，跨轮次同名材料以来源运行区分。下一段定义明确保持分组、展开或聚合；列表本身可以成为可继续传递的输出，不要求先生成摘要。`summaryOutput` 仍为可选展示合同。

界面在固定尺寸的选择区按子项、轮次和产物组选择，默认不勾选历史成果。每轮选一组，可逐份取消或查看完整原值；中间成果需主动显示。显示已选/未选子项、无可用成果及读取错误，不把产物计数当作业务覆盖证明。允许选择部分子项推进；子项和父项状态不因取用成果自动完成。切换方法保留当前查看的子项；生成方法的显式输入引用保存到方法作者上下文，供新方法首次准备执行时重新解析，而非复制浏览器值。

`completionInputs` 继续只提供固定的已结项完成依据。它与普通阶段成果是独立输入路线；父项最终结项仍检查纳入范围的子项和自身条件，不因阶段成果已可用而放宽。后续运行、补证、移出范围不改写已经启动的父项 Run；新的准备/启动重新验证当下范围和所选来源。

反例：某 CVE 旧轮次已核查 5 个仓库，续做仅核查余下 26 个。只取最新轮次会漏掉 5 份结论；必须明确选取旧轮次有效产物及续做产物。不能将同轮的明细、包含相同明细的报告和摘要一起默认汇入。验证见 `tests/child-stage-inputs.test.ts` 与 `tests/browser/child-stage-inputs.spec.ts`。

### 整体成果与按记录接续（2026-10-27）

`Definition.resultOutput` 可选绑定普通 aggregate 节点的最终 output，其值遵循 `shared/work-result-set.ts` 的 `WorkResultSet`：`{title,items:[{id,title,records:[{id,title,scope,finding,reason,actions,questions,source,detail}]}]}`。它是普通不可变运行产物，不是新的业务实体、摘要文字或结项事件。事项 ID 和记录 ID 分别全局唯一；每条记录保留原判断、限定范围、原值与来源，actions 可以同时包含 process/clarify，但仅在独立 disposition:{status:"decided",reason:"具体判定理由"} 时表示已确认待办；缺少 disposition 或 status=pending 均表示处置待判定。questions 保留原文，不因非空自动转为 clarify，也不能把源码排除判断推广为部署或扫描范围已经排除。应用只验证明确合同，不从任意 JSON 字段猜业务结论。

工作项默认结果页与方法成果页复用整体成果表：先看实际范围和剩余工作，再检查每个业务项的原判断及证据。子项执行状态属于子项页，已有整体成果时不再占据结果页前部。完整依据在固定尺寸弹窗按需查看。用户可以按工作类别或逐项勾选，原地进入下一段方法准备，不跳验收或自动建子项。

`ItemInputSelection.result.recordIds` 仅对固定定义明确声明的整体成果有效。服务端从真实源 Run 重读并校验记录，展开为逐条 `{item:{id,title},record:{...}}` 输入，保留业务身份、原值和批次产物的精确来源。空选、重复、缺失或未声明的来源拒绝启动；新执行不改变旧成果。生成后续方法与选已有方法使用同一选择，不隐含重跑核查，也不沿用可能不兼容的汇集方法。

具体反例：当前批次 20 个 CVE 共 211 个核查范围，源码判断为 6 受影响、159 不受影响、46 证据不足，但所有记录均保留未解决的扫描/部署问题。这不能直接推出需要处理6条或补证211条；当前仅有源码判断，后续处置仍待判定，不能把159条直接视为原扫描风险已排除。领域转换放在 `pipelines/cve/v2/batch-result.ts` 的普通纯表达式方法，应用内不硬编码 CVE 判断。三条未取得提交的记录明确呈现版本范围未知。`publish-batch-result.ts` 校验整个父项范围与选定核查清单及目标数后，复用 run 动作形成父项真实成果；不会调用模型或确认完成条件。

实际接续反例补充：部分历史fanout同一Run的不同实例共享sampleId，精确result引用和目标不同，不属于多个运行版本。版本冲突校验按样本键记录所属Run，同一Run可选多个实例，跨Run的同样本竞争版本仍拒绝。按整体记录续做只继承其source指向的原始产物材料；source必须来自整体Run已固定inputSources。新Run同时保留批次产物与原始引用，使后续可继续保留来源，而非把全批材料复制给每条记录。两项反例由batch-result夹具及原版本冲突用例验证。

2026-10-28修正：批次方法不再从conclusion/unknown机械生成actions，仅固定原判断和未知原文并标记disposition=pending。questions可以包含纯范围说明，与已确认补证不是同一个概念。显式判定为decided时需提供非空reason，可确认有process/clarify动作，也可确认无后续工作，即使仍保留范围说明。待判定不能被展示为零待办或无需后续。历史缺少disposition时保守展示待判定，按记录续做时在副本中清除未经判定的旧actions，并补上兼容说明；原Run和detail不改写。

2026-10-28结果阅读修正：整体成果的items继续保留业务身份与来源，页面将其中records直接平铺成可筛选的结果行，显示所属事项、范围、判断和理由。按筛选范围或勾选记录复用原recordIds接续，服务端仍逐条解析和冻结原始来源；页面的平铺不改写旧Run，也不把整批汇总对象当成每条下游输入。完整依据按单条查看。


## 工作项内的组合方法与成果声明（2026-10-28）

当前实现把工作项的私有处理方法保存在既有 `Work` 中，用 `ownerItemId` 与 `compositionWorkId` 关联；公开方法目录不列出私有方法。工作项负责业务身份、独立材料、明确采用的输入、交付与条件；Definition负责处理关系，Run负责固定版本的一次真实执行。没有另建工作项调度器。

`call` 节点固定 `workId/definitionId` 及具名输入输出，可整批调用或沿明确端口逐项调用。目标方法内仍由现有运行器执行，子运行保留父调用关系、实际输入和输出来源；停止、等待和恢复沿同一调用关系交接。`map/flatMap/reduce/collect/join` 沿用原有集合语义，`groupBy` 按明确字段路径分组，不隐式推理领域身份。执行依赖汇合仍使用原有DAG调度。

工作项Assistant读取方法目录、具体版本合同、材料与真实运行，通过同一保存/输入/运行/交付业务入口推进。原始材料直接引用；派生补输入必须明确材料来源。写入检查当前工作项修订，定义保存另检查草稿版本；错误返回可定位信息，失败不能以文字成功替代。Assistant不会因为完成一次运行而确认业务条件。

成果声明 `table/report/groups` 决定输出、标题、稳定记录编号、字段、分组与已注册动作，不携带业务数据。内容由服务端读取本项明确成功正式运行的固定输出，结构、引用和实际值分别校验。不同输出交付可以并存；后续运行不自动替换旧交付。用户选记录后，服务端重读绑定的交付与真实记录，再准备下一轮输入和来源，不能信任浏览器传回的正文。

保存为流水线复制参数化Definition与适用视图模板，不复制本项材料、运行、私有文件或业务身份；使用私有文件/私有调用须先提取输入。当前不自动识别任意任务文字或表达式中是否写死一次性业务常量，沉淀时仍需检查方法输入与具体定义。

页面已按[当前可见设计](../conductor/tracks/workitem-composition_20261028/design-review.md)实现工作台入口、共享实际骨架、四个主内容面、同一现有Assistant、固定完成条件任务与按需子项管理。首页提交需求/文件后请求规划，不自动正式运行。实际范围见[计划](../conductor/tracks/workitem-composition_20261028/plan.md)与[证据](../conductor/tracks/workitem-composition_20261028/evidence.md)，用户视觉接受另行记录。完整设计与研究见[元应用设计](workitem-meta-application-design.md)及[实施调研](workitem-meta-implementation-research.md)。


## 页面位置与浏览器历史（2026-10-29）

[任务访问与导航合同](task-navigation-contract.md)固定全局导航、位置与身份、对象视图及临时检查职责。独立预览已按合同改造，托管未部署；当前证据见[导航track](../conductor/tracks/feature-task-navigation_20261029/evidence.md)。方法与工作项是关联对象，标题不再用通用返回按钮模拟父层级。完整编辑保留具名原任务，实际Run归属独立呈现。

### 工作项的业务界面与薄衔接（2026-10-29）

WorkItem承担业务身份、材料/输入引用、当前交付、待用户补充及完成依据。复杂领域研究、核查和处理规则放在公用流水线；私有Definition保留必要的输入构造、固定call、按项分发、匹配分路和结果汇合，复用既有Run，不新增阶段或动作执行引擎。

`WorkItem.uiPlan`与工作项修订一同原子保存，关联明确Definition及planId；`Work.uiPlan`只携带可复用方法模板。有限views/inputs经共享schema及真实方法合同检查，不保存任意React/HTML或UI脚本。执行前显示安排的业务视图和实际合同输入；成功后publishUiPlan对全部视图/字段/编号校验，通过才一次绑定同一真实Run。修改定义使不匹配方案失效；旧Run和已有交付值保持固定。

json-render只承载RecordTable、RecordGroups、RecordDetail、Report、InputForm、ActionBar的确定性编译和/data只读、/draft及/selection受控绑定。前四者复用现有阅读器/表格，表单复用InputFields与统一控件，动作调用已有continue/addInput/run/criteria。没有通用页面DSL或任意HTTP动作。

动作只有继续、补输入、人工核对。前两者固定单输入方法版本；用户选择真实记录并按目标inputContract补声明字段，服务端重读原记录再准备新输入，execute=true只在明确点击提交后调用原运行入口。人工核对只进入既有完成条件任务。前提仅equals/empty/not-empty，客户端与服务端共用规则；输入修订或运行未结束会阻止旧交付直接核对。保存失败/版本冲突保留草稿与选择，运行失败不会伪装为新成果。运行成功、领域交付检查通过与用户明确结项分别成立。

Assistant可读取方法目录及界面模板，check_ui_plan、save_ui_plan、publish_ui_plan与页面共用服务；set_completion_requirements仅写未确认要求。具体领域行为和标签属于pipelines及方法声明，不进入通用src。假设批次推演、真实模型和实际UI证据见当前track的interaction-plan及evidence。

### 用户与Assistant共同编辑界面安排

当前合同见[共编规范](workitem-ui-authoring.md)。ItemUiPlan是唯一正式界面模型，具名视图引用具名详情模板；结构编辑、OpenUI子集可读描述和Agent块补丁都回到它。现成lang-core只解析，不引入第二渲染或Query/Mutation运行器。界面重绑仍使用当前交付的实际固定Run、输出和来源；展示修改不新增运行或输入，不修改判断/条件。前一安排及绑定元数据随界面历史事件保存，未涉及视图和固定数据来源的浏览状态保留。实际状态和限制见当前track的K阶段。


工作项成果的来源按需查看：单份直达，多份在正文内展开来源卡片，显示冻结步骤名和真实记录摘要；卡片复用材料卡片外观，不平铺编号查看按钮。来源依然固定work/run/result/port/index，来源的展示序号只用于阅读，不作为身份。

来源呈现是应用的稳定底座，Assistant负责业务视图/字段/标签；卡片读取同一声明，不另存模型自由生成的来源布局或身份。


工作项流程图中的call节点必须直接呈现实际流水线名称及固定版本，读取模式同样可见。名称按call的workId+definitionId解析，与步骤label分开；节点内查看入口展示该保存定义，缺失如实报错，不替换为当前草稿。预览只保存本地布局；进入流水线编辑沿既有工作区导航，不自动改写工作项固定调用。


工作项流程按原语呈现：call本身是流水线应用节点，以实际方法名为标题、固定版本为次信息，mode/operation显示逐项或整批应用；不在节点内再嵌套引用卡片。function/branch等节点按真实IR显示模式匹配、条件分路、多路收集、分组、归约等操作，业务label另作本次用途。expression.match变换值，branch按条件导出matched/unmatched，已存在具名端口可直接接不同去向，三者不能混同。

业务图常显实际端口，根outputs绑定的端口标记交付；业务别名读取同一定义的uiPlan或交付，不改变Handle ID和edges。逐项调用只保留一个应用节点，真实nodeTotals/results进度可进入既有执行实例检查。紧凑节点及层间距是视图布局参数，不进入Definition/运行语义；单纯绑定无需新增假计算节点。

## 工作项展示闭环与多会话（2026-10-29）

Assistant规划处理关系时同时安排业务视图、输入表单及合法动作。方法已有而uiPlan缺失/失配，页面显示明确完善入口并交给当前会话。成果页的持续状态来自真实Run、当前输入及绑定；绑定后成果页只呈现声明视图与动作；action.when/review仅用于动作前提，不由外壳推断待办、阶段或核对捷径。历史成果保留其固定来源和展示快照并标记“此前”，不重复贡献当前待办。没有通用完成率、自动业务结项或第二状态机。

同一WorkItem允许多个Assistant会话。Work.assistantConversations记录元数据，消息在原Work.messages用conversationId归属；main兼容旧消息和原Pi目录，新会话使用独立兄弟目录。新会话从当前工作项状态开始，不自动复制别的聊天；原会话可以继续。Definition、输入、uiPlan、Run、交付及完成条件始终共享，不随会话复制。请求验证会话归属，回复绑定原requestId/会话，仍按Work串行。新建不产生Run或修改条件。

界面只在Assistant标题栏提供新建/切换/历史，复用原Composer。草稿和选中会话仅在当前浏览器标签页sessionStorage保留；消息和Pi历史由服务端持久保存。首版不提供删除、分叉、跨会话摘要或并发编辑。

工作项流程通过nativeLabels显示原生技术标识：call · map/aggregate、branch、collect等原语与真实输入/输出端口。业务标题及计划交付名称独立；uiPlan交付标题不得覆盖matched/unmatched/output等接口名。此规则仅适用于工作项流程及其步骤说明，普通流水线展示不改。

## 明确的导航与详情操作（2026-10-29）

ItemUiPlan.navigation以tabs/select明确声明导航，顺序沿views；Workspace可读描述、结构编辑、Assistant工具和composition-ui保存同源。未声明的旧记录默认tabs，没有按数量的策略。ViewNavigation在未运行预览和已绑定成果中复用既有控件。

输入任务在输入页；成果绑定后移除通用输入保存条及review推导进展。业务问题如何被感知及推进，通过声明的数据视图/动作表达。普通执行/绑定与全局人工条件仍有固定入口，不将机器处理或模型文字当业务完成。

详情使用Detail.title和真实记录ID，字段/顺序由声明控制。标题随presentation.detailTitle及fields冻结，后续计划不改变旧交付。详情的业务动作复用view.actions与同一校验/服务，明确使用该详情的单记录ID，表格选择保持。来源及更多菜单中的依据、子项、比较由应用提供，不强制成为业务步骤；没有CVE专门字段、判断或按钮分支。

### 工作项的薄编排与页面数据

工作项保留需要用户理解或干预的业务交接，连续的数据整理、去重、汇合规则可以保存为有明确输入输出的普通方法，再通过固定版本的 call 连接。拆分不意味着增加 Agent：确定性处理仍用现有 function；方法调用与独立子工作项维持不同身份。无需为每次字段变换增加工作项根节点，也不通过画布折叠掩盖仍然复杂的定义。

页面工作区与执行真值分开：运行概要保留状态、实例与固定来源，较大值明确携带 contentUrl。列表传声明的可见字段及动作条件，详情按固定交付/记录编号读取原值。正文预览有界分页，完整下载由用户显式打开；业务验证、接续与 Assistant 读取仍使用完整服务器记录。导航只保留查询、页码、选择及草稿，离开的工作项释放数据面板。
