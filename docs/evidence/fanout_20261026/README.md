# 多目标核查的来源与汇集（2026-10-26）

## 反例与原因

工作项 CVE-2013-7459 的第3轮包含23个独立仓库核查实例，均已成功；最后将全部结论重写为Markdown的模型节点达到输出上限。逐目标值没有重复，但collect先合并了24条材料的来源，后续表达式flatMap每项都继承整个来源集合。UI只显示节点名和全量材料编号，无法辨别实例。

普通表达式flatMap继承调用来源是现有合同，不能凭业务字段猜测精确血缘。本次修正具体方法接线，不引入通用表达式来源追踪或新的运行算子，也不改写历史运行。

## 改动

- `pipelines/cve/v2/source-check.json`：共用事实与独立目标分别包装，现有join按本次共用事实键逐目标配对，再取出`{facts,target}`交给原verify。每次只继承实际参与配对的事实和目标材料；不是一份facts时明确失败。目标列表仍由显式输入决定，不推断候选范围。
- report改为已有aggregate/identity函数，完整保留逐目标结论、源码依据与unknown，返回数组供现有集合阅读器展示；不再调用模型重写。
- `RunSources`：按固定方法/运行/节点分组，大量来源按需展开，真实实例序号与现有选择器一致，附实际标量预览并精确定位。大量关联材料单独收纳；固定输入标题为第N项，材料编号在展开后保留。少量来源仍可直接点击，缺失来源如实显示。
