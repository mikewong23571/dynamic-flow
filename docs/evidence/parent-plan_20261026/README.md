# 父项处理安排与共享业务背景（2026-10-26）

## 具体反例与修复

只读核查当前 SCC 首批批次发现：父项未绑定流水线，但已有 20 个直属子项，子项使用“仓库漏洞核查”和“漏洞事实研究”两种方法。此前原型只根据本项 workflowId 展示方案，因此父项被误报为未设置方法；其没有直接 Run 也被显示为整批“尚未执行”。失效假设是“工作项的处理安排等于它直接关联的流水线”。

用户随后确认：点击“查看处理方案”后，业务阻碍、下一步、外部报告来源突然消失。相关内容实际上仍在共享区域，原型的强制滚动将其移出了视野；按页签恢复旧滚动位置也可能造成同类跳转。

修复结果：

- 父项方案展示当前范围内的直属子项分工，列出标题、编号、阶段、实际使用的方法和业务状态。可进入子项、查看实际方法、管理子项和检查父项完成条件。没有直接方法的父项不再显示整项没有处理方法；确实未分配方法的子项单独标明。
- 推进概览使用完整 scopeSummary，显示全范围子项总数、已结项、推进中及实际等待/需处理数量。父项另有执行时单独显示“本项执行”，不覆盖其等待/失败，也不把成功 Run 计为业务结项。
- 复用现有每 2 秒的子项查询轮询，方案分工按页读取；统计不随分页缩小。轮询保留当前页已有行顺序，父子返回保留方案分页。读取失败明确提示，保留上次内容，不推断为无子项。
- “查看处理方案”和手动页签切换只替换下方内容，不主动滚动或恢复另一页签的旧阅读位置；共享的业务阻碍、下一步与报告来源保持原位。明确的来源导航及父子返回仍沿用原有位置交接。

没有新增后端接口、持久方案模型或业务状态；未给真实父项绑定方法、改写任务数据或操作其运行。
