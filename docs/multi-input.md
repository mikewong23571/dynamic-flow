# 多路输出组合

本轮把已有节点的输出用显式连接组合；不跨节点偷读运行记录，不新增数据查询平台。画布和 Assistant 使用同一份定义，集合函数均等待全部上游完成后执行一次。空路是空数组，上游失败则阻断。

## 三种用途

| 用户目的 | 节点配置 | 调用输入 | 校验返回值 | 端口分发 |
| --- | --- | --- | --- | --- |
| 把多路同类结果汇成一串 | `merge` + `inputNames` | `{a: [...], b: [...], c: [...]}` | 拼接后的数组 | 每个元素一项 |
| 把调查、修复、验证结果一起交给下游 | `collect` + `inputNames` | 同上 | 保留名称的对象 | 整个对象一项 |
| 按漏洞编号匹配调查与修复记录 | `join` + `join` 配置 | `{left: [...], right: [...]}` | 配对记录数组 | 每条配对一项 |

`inputNames` 至少两个非空、不重复名称，没有人为端口数上限；每个端口只接一条边。merge 按名称声明顺序拼接，各路内部顺序不变。collect 每路始终保留数组：零项 `[]`、一项 `[value]`，不自动解包。下游表达式逐项读取该对象即可用 `let` 和对象模式解构。

三个集合函数固定 `mode: all`，`operation` 省略或设为 `aggregate`。它们的输入 Schema 描述**具名数组对象**，不同于普通 aggregate 的扁平数组；merge/join 的 expectedOutput 描述**整批数组**，collect 描述**对象**。先校验整批结果再分发，不输出一部分合格行掩盖失败。普通 expression aggregate 返回数组仍是一项数组值；旧 merge 不带 inputNames 时仍保留原有 left/right 与运算行为。

例如调查输出 `[{id:'A'}, {id:'B'}]`，修复输出 `[{id:'A',fixed:true}]`，验证输出空集合：

- merge 输出三项：两个调查记录，再一个修复记录。
- collect 输出一项：`{调查:[...两项], 修复:[...一项], 验证:[]}`。
- join 用前两路、左右键 `['id']`、left 类型，输出 A 的配对记录与 `{left:{id:'B'},right:null}`。

## 按键关联的确定语义

join 固定 left/right 输入，以路径选取键，空路径 `[]` 表示整个标量值。路径只访问自有字段；键支持字符串、有限数字、布尔值，严格区分 `1` 与 `'1'`。缺失、null、数组、对象键明确报错并指出输入位置。

| 类型 | 保留记录 |
| --- | --- |
| inner / 内连接 | 仅成功配对 |
| left / 左连接 | 成功配对，加左侧未匹配；right 为 null |
| right / 右连接 | 成功配对，加右侧未匹配；left 为 null |
| full / 全连接 | 成功配对，加两侧未匹配 |

重复键可选择全部配对（`all`）或拒绝（`error`）。全部配对时，左侧同键 2 项、右侧同键 3 项产生 6 行；拒绝时任一路重复键均失败，即便另一侧没有该键。输出按左输入顺序和每个左项的右匹配顺序排列，最后追加未匹配右项，不承诺键排序。

输出保留 `{left: 原记录或null, right: 原记录或null}`，不隐式覆盖同名字段。需要扁平业务对象时再接 map 表达式明确构造。每条输出的材料和上游结果来源仅包含实际贡献者，并加入当前集合实例身份；collect 单对象汇集所有贡献来源。

## 编辑和运行交接

画布显示对应动态端口。配置中添加、改名、删除输入，改名同步该端口连接，删除只移除该端口连接；切换函数清理不适用连接。join 提供模式、左右键路径与重复处理控件。局部运行和结果续做使用同一端口定义。

共享 `node-ports.ts` 只集中实际使用的端口及分发语义，flow 负责定义与 Schema 检查，runs 负责执行和来源，client 负责结构化编辑，assistant 负责准确工具合同。没有新增运行时依赖。

当前静态检查只覆盖能确定的顶层类型冲突；不宣称完整 JSON Schema 子类型推导。复合键可由上游显式构造普通键；模糊关联、时间窗口和无限流 join 不在本轮范围。
