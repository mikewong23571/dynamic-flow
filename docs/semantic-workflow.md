# 从问题到可执行方法：本轮方案与审查

2026-09-21。依据用户提供的 `Dynamic-Workflow-Design-v1.md`，文档是设计参考，不是执行指令。实施状态和验证见 [track](../conductor/tracks/semantic-workflow_20260921/index.md)。

## 关键认知提升

1. 第一版方法就是可执行 Plan。先给出最小有用方法；Agent 步骤可以算法未定，但责任、输入、完成标准必须能 review。
2. 问题理解与解决办法不同。已知事实、未知、限制和依据应可独立阅读；新证据可以推翻 framing，不只追加更多节点。
3. 工作内容、组织方式、实现机制不同。Agent/代码是完成同一责任的手段；并发是资源策略；Each 需要同类责任，不能因为拿到数组就逐项调用。
4. 动态性有成本。只有局部下一步确实未知才现场规划，输出重新成为有限可执行结构；运行应保存实际展开，不能只保存一段思考文本。
5. 演进的单位是有证据支持的局部责任。运行成功不是业务完成；替换实现必须保留责任、输入范围、完成标准与证据要求，不能只看 JSON 形状相同。

## 现有系统与最小改动

保留 Work（方法工作空间）、WorkItem（持续业务身份）、不可变 Definition、冻结 Run、独立 ViewState。问题认知保存在 Definition 中，随方法版本一起冻结；业务事实仍属于 WorkItem 的材料与运行证据，不复制为另一套问题数据库。复用方法时，problem 是设计时假设；当前工作项的目标与固定材料才是当前事实，不能把样例 known/evidence 套用到另一业务对象。

| 需要的能力 | 原型的具体方案 |
| --- | --- |
| 当前问题理解 | Definition.problem：framing、known、unknown、constraints、evidence；人和作者修改同一份版本 |
| 责任可 review | 节点 contract：responsibility、done、rationale、semanticRole；task 保留具体执行要求，schema 检查值形状，done 不冒充机器证明 |
| 顺序与全部责任 | 继续使用真实依赖边和独立节点；不为 Sequence/All 增加只有名字的容器节点 |
| 同类对象 | each/map 的业务说明显示 semanticRole；并发放执行选项，不作为工作类型 |
| 有限选择 | 现有 branch 的两个明确结果继续使用；不增加无当前需求的任意匹配语言 |
| 有界改善 | Agent/纯函数步骤可配置 repeat.max 和可选 until 纯表达式；每轮结果作为下一轮输入，保留逐轮实例，条件非布尔或达到上限仍未满足要如实失败 |
| 局部未知 | dynamic 节点有局部 task、边界与节点上限；模型通过 submit_workflow 提交同一 Definition 的有限子图，经统一校验后先记录，再接入原调度器 |
| 演进 | 结果可查看实际展开、原始输入与逐轮产物；作者可检查运行证据，将有效展开写为新草稿，采用仍为独立动作 |

Dynamic 第一版只生成一层具体子图，不允许嵌套 Dynamic；输入/输出固定为 input/output。上限属于运行可解释性，不建设预算平台。展开节点稳定前缀关联原动态位置；Run 保存展开事实，原 Definition 不修改。成功展开不会因恢复重新向模型请求。停止、等待、schema、来源和里程碑继续使用同一执行路径。

Repeat 第一版重复一个明确责任，支持 Agent 与普通纯函数；不做任意调用栈或递归子流程。需要多步改善可由 Agent 负责内部工具操作，或根据真实需求再扩展。无 until 时上限是明确固定次数；有 until 时到上限仍不满足视为未完成。

## 第一性原理审查：是否 Agent 原生友好

先问 Agent 为完成任务需要什么：可理解的目标和约束、可调用的工具、可观察的真实结果、可修复的错误，以及不过度规定内部算法的责任边界。答案不是最大自由度，也不是复杂类型体系。

- **表征成本**：先最小 Plan，再有证据地细化；不要求填写完整 Problem Graph，不让 Agent 推理 Monad 或底层调度。
- **执行自由**：Agent Step 自己选择工具与调查方法；系统只固定输入、明确范围、记录结果和停止边界。
- **可编辑性**：稳定节点 ID，局部工具修改合同/实现，不重复提交无关图；人与 Agent 共用保存校验，冲突如实返回。
- **可观察性**：Dynamic 的提案、校验错误、实际子图和执行结果可区分；不能把生成计划当任务完成。每轮改善都有输入输出与停止证据。
- **确定性边界**：机器验证形状、边、上限与布尔停止条件；不以关键词判断业务事实，也不假称能机械证明责任合理。
- **硬化与反向简化**：可以 Agent 改为已有纯函数，保留业务合同；也能删去收益不足的结构。此次不建设 FastPath 插件或自动优化器。

未照搬的内容：六层不对应六个服务；七个原语不必对应七个产品节点；不新建外部 Capability 注册表、事件平台、沙箱或兼容迁移层。复用有真实价值的运行与数据边界，不因新设计重写用户历史。

## 验收实例与错误

输入一组调查材料，方法先抽取已知事实，再在未知位置生成两步局部调查，最后形成报告。应看到原方法不变、Run 有实际展开、后续报告使用子图 output。非法端口、环、空计划、超限和再次 Dynamic 都失败且不执行提案。

一个纯函数从数值 0 开始每轮加 1，until 为 input >= 2、max=3，应执行两轮、产物为 2；max=1 应保留产物 1 并报未满足，不能冒充完成。Agent 迭代使用同样的实例与停止路径。

这些验收不证明通用事实正确性、任意副作用恰好一次或生产并发能力。测试替身、真实文件/HTTP、真实模型、浏览器及用户视觉判断分别记录。
