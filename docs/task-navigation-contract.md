# 任务访问与导航合同

2026-10-29。**当前业务规范；已在独立预览实施。** 访问合同由[导航优化track](../conductor/tracks/feature-task-navigation_20261029/index.md)承接，实际差异、验收与限制见其[evidence](../conductor/tracks/feature-task-navigation_20261029/evidence.md)。托管实例未部署。本文取代旧设计中“各详情页头固定放返回入口”的决定；历史测试不替代当前证据。此前合同文档落地过程见[上游记录](../conductor/tracks/workitem-composition_20261028/task-navigation-contract.md)。

## 业务目标与对象边界

用户查看方法、执行和依据后，应能继续原来的业务工作，保留处理范围、所选记录、草稿和阅读位置。导航帮助定位、检查和切换工作；采用方法、运行、补输入、确认条件和结项仍是明确的业务动作。

- 工作项 `WorkItem` 是持续业务工作空间；流水线 `Work` 是独立、可复用的方法工作空间。调用是关联关系，不把流水线变成工作项的下级页面。
- `Run` 固定方法版本、输入和可选工作项身份；产物固定生产它的运行/结果/端口/索引。浏览路径不能改变这些归属。
- 首页与全局工作项列表只展示顶层项；搜索、状态数量、总数和分页使用同一范围。子项留在父项管理，保留独立身份和直接地址；排除范围不会自动变成顶层项。父项展示现有直属子项完成进度。
- 列表是寻找工作对象的集合视图；工作项的成果/流程/输入/记录，以及同一执行的成果/过程/输入，属于对象的内容视图。打开视图不等于进入新的业务实体。
- 来源图可以跨方法、跨运行；面包屑只用于真实层级。不能把访问顺序或引用关系画成归属层级。

## 固定页面骨架与声明业务界面

| 层次 | 回答的问题 | 负责方 |
| --- | --- | --- |
| 全局导航 | 去哪里开始、寻找或切换工作 | 应用固定的首页、工作项、流水线入口 |
| 位置与身份 | 当前是什么对象、处于什么范围 | 应用页头；业务名称、编号、状态及明确关联链接 |
| 当前对象的视图 | 查看当前对象的哪个方面 | 应用固定内容页签；工作项业务视图内部由同一 `ItemUiPlan` 声明 |
| 工作内容与动作 | 看哪些值、如何补充和推进 | 固定成果、模型声明及共享业务服务 |
| 临时检查 | 为当前任务查看什么补充信息 | 现有详情弹窗、固定方法预览或运行检查区域 |

导航和辅助信息保持次要视觉权重。常驻页头不再重复增加来源返回条；同一结果区的总览、运行选择和内容视图在进入详情后仍可达。明确目的地链接显示对象名称；图标不能独自承担可变目标的说明。

应用固定骨架不交给 LLM 任意改写。Assistant 继续声明业务视图、`navigation=tabs/select`、字段、详情和合法动作，调用应用提供的明确对象入口；不能替换全局路由、编造来源或借导航提交业务。具体声明合同见[界面安排共编](workitem-ui-authoring.md)。

Assistant可读取当前工作项、所选会话/视图/记录、实际方法目录与固定版本合同；其输出仍通过既有声明校验和业务命令执行。来处仅辅助理解用户正在继续哪项工作，不能作为产物归属或业务授权。页面定位和恢复由应用完成，不要求每次打开、关闭或后退都让模型重新规划；本合同不新增导航工具协议。

## 每条访问路径必须写清的六项

这是设计与验收清单，不要求新增导航实体、协议服务或通用配置引擎。

| 项目 | 最小约定 |
| --- | --- |
| 用户意图 | 继续工作、临时检查、深入编辑、切换对象、切换视图或历史后退 |
| 目标身份 | 工作项/流水线 ID；检查历史时带固定 Definition/Run，必要时带结果、端口、索引和记录 ID |
| 任务上下文 | 原工作项和阅读位置；访问来处与执行真实归属分别记录 |
| 打开方式 | 当前对象内切换、现有临时检查容器，或完整对象工作区 |
| 恢复约定 | 关闭或再次进入后保留什么；目标消失时如何明确报错及恢复焦点 |
| 业务影响 | 仅导航无业务写入；其它影响必须由命名清楚的独立动作执行 |

## 访问路径矩阵

| 路径 | 打开和定位 | 继续任务及保留内容 |
| --- | --- | --- |
| 首页/列表 → 工作项 | 完整工作项工作区，显示业务身份 | 列表入口始终可达，原筛选、页码和滚动保留 |
| 工作项 → 记录/材料/固定方法定义 | 临时检查，不替换业务工作区 | 关闭恢复原视图、记录勾选、滚动与焦点 |
| 固定方法预览 → 编辑流水线 | 独立方法工作区，明确编辑版本；保留原工作项名称链接 | 通过明确对象链接继续原工作项；导航不采用新方法版本 |
| 流水线 → 其它流水线 | 通过目录/已打开对象入口明确切换 | 各方法本地编辑草稿和选择按对象隔离 |
| 运行记录/成果集合 → 指定执行或产物 | 在结果区选择，显示固定执行身份 | 运行记录、成果视图及当前执行选择保持可达，不依赖“查看总览”返回按钮 |
| 当前成果 → 来源 | 固定来源身份，在现有检查容器中阅读 | 来源轨迹可查看；关闭恢复原成果，避免递归叠加弹窗 |
| 同一对象内切换视图 | 保持对象身份，切换所需内容 | 选中记录和草稿不因视图切换被清空，不自动运行 |
| 浏览器历史后退/前进 | 恢复真实上一处/下一处有意义的位置 | 无业务副作用；不套用另一套“父入口”猜测规则 |

临时检查初始状态提供关闭；确有内部嵌套检查时，局部历史只作用于这个容器，并明确对象与来源。复杂方法编辑和密集执行检查可使用完整工作空间，不强迫所有内容塞进弹窗，也不增加第三个常驻侧栏。

## 来处、归属和历史分别处理

从工作项 A 打开方法 M，原任务链接指向 A 的明确位置；它不代表 M 归属于 A。若随后查看属于工作项 B 的运行，运行内容必须显示 B 的真实归属，不能因 `fromItem=A` 改成 A 的结果。继续 A 的入口仍可指向 A，名称需表达“原任务”，不同时把 A/B 都称作当前业务对象。

直接打开方法或从方法目录进入时，没有原工作项就不生成这类链接。直接打开固定运行时，业务归属读取该运行的冻结记录，不靠上一次访问推断。

点击具名对象链接是一次正常导航，写入浏览器历史；浏览器后退回到此前页面是合理行为。真正的历史后退使用历史遍历，不通过 `pushState` 假装退回。重复地址和后台轮询不增加历史，输入每个字符、悬停和勾选不构成浏览历史。第一条应用历史仍允许退出应用。

`flowcraftParents` 不再作为目标设计中的通用返回规则。迁移时保留明确对象上下文和原生 History API，不另外建设工作区标签管理器、全局来源栈或会话导航服务。

## 状态恢复和错误合同

| 范围 | 必须保留或明确呈现 |
| --- | --- |
| 同一浏览器标签页的普通往返 | 列表查询/排序/页码/滚动；工作项主视图、业务视图、记录选择；方法编辑草稿和选择；原有 Assistant 会话及各自草稿 |
| 临时检查开合 | 背景视图和选择、表单未提交状态；关闭恢复触发入口焦点；明确取消动作仍按原语义处理 |
| 刷新、直接链接 | URL 可识别的对象、主视图、指定运行；更细定位若写入链接，必须按精确引用恢复。未持久化表单不承诺跨刷新恢复，不能伪装成已保存 |
| 后台快照更新 | 固定运行与产物身份不变；有效选择及脏草稿保持，不把同名或相邻记录当成原记录 |
| 对象/版本/来源失效 | 就地显示具体缺失或读取错误，保留可恢复的原任务；不换成最新版本、最近执行或第一条记录 |

位置只保存必要 ID 和阅读参数，不把材料正文、模型消息、表单草稿或完整 UI 状态塞入 URL。运行/业务数据继续由既有服务保存；本地阅读状态不新增业务版本。

从方法工作区进入和离开都不能自动改写工作项的固定调用；采用新版本、补材料、启动执行、确认例外/条件、结项分别使用现有正式动作。打开页面和 `popstate` 不调用模型或这些业务命令。

## 代表性业务推演

用户在工作项 A 的仓库范围视图选中记录 R，查看固定方法 M/v1 与执行 r1：

1. 记录/固定定义检查在现有临时容器打开；关闭后仍在 A/R，原勾选不变。
2. 明确进入 M 的编辑工作区时，位置栏显示 M；原任务链接明确指向 A 的原视图。
3. 保存方法新草稿 v2 是独立编辑动作；点击 A 的链接只恢复阅读，A 的调用仍固定 v1，r1 的输入和产物不变。
4. 用户可以通过结果区常驻入口选择其它执行；归属和版本按所选运行显示。切换后不会将其它工作项材料带入 A。
5. 是否采用新版本、正式运行及人工验收，由用户/已授权 Assistant 通过明确业务动作决定。

CVE 只用于这条用户路线的样例。合同不识别漏洞字段、处置状态或仓库命名。

## 验收清单（NAV 为本文局部编号）

| 编号 / 用户路线 | 可观察结果 |
| --- | --- |
| NAV-01 从筛选后的列表进入和再次查看列表 | 筛选、页码、滚动和当前对象定位保持，不另造返回目标 |
| NAV-02 检查记录、材料和固定方法定义 | 关闭后背景选择不变；键盘关闭及焦点恢复有效 |
| NAV-03 从工作项编辑方法再继续原项 | 主视图/业务视图/记录/草稿保持；调用版本、材料、Run、条件不因访问变化 |
| NAV-04 从结果集合选择指定执行/产物 | 结果区导航常驻；运行/版本/实例身份明确，原列表位置可恢复 |
| NAV-05 历史后退和前进 | 遍历真实访问位置；不弹到隐藏父栈目标、不自动保存/采用/运行；轮询不增历史 |
| NAV-06 直接链接、刷新及首次进入 | 有 URL 身份按其恢复；无访问来处不编造原工作项；第一条历史可离开应用 |
| NAV-07 同一方法关联多个工作项 | 来处 A 与运行所属 B 可区分，不形成虚假上下级，不改材料归属 |
| NAV-08 固定版本/运行/来源缺失 | 明确错误，不替换成最新或其它对象；原任务仍可继续 |
| NAV-09 迟到快照、失效记录和未提交草稿 | 不串对象、不抹草稿；原记录消失不自动选中相邻记录 |
| NAV-10 1440/1024 与长标题 | 骨架一致、导航可达，无多层返回横条，不缩成难读字号；实际逐屏审阅 |
| NAV-11 只有导航时的业务不变性 | 对比 Definition、固定调用、Run、输入、材料、完成条件及状态，除本地阅读位置外无业务变化 |
| NAV-12 应用与 Assistant 的分工 | 模型能安排业务视图/动作；全局位置、来源身份、历史与恢复规则由应用固定 |

以上为规范，逐条实际验收见导航track。已按代表页面设计 → 实施 → 两尺寸视觉 → 定向功能推进；真实模型未重跑，本轮没有更改模型或业务界面声明协议。
