# 类型化数据流与函数组合

2026-09-20 用户补充方向：关注输出 schema，借鉴 Java 函数式思想。本文是后续实现约束，尚未落到运行器；不是已通过验收的能力。

## 已实现与缺口

当前 FlowNode 有 each/all，Agent 有可选 expectedOutput。assistant/validation.ts 手写校验了部分 JSON Schema 字段；没有通用端口数据契约、连接类型检查或真正并发。普通函数不统一经过输出 schema 校验。此现状不能称为完整的类型化数据流。

## 三个相互独立的维度

- 节点业务：Agent 任务或已有普通函数。
- 数据变换：逐项转换、集合展开、筛选、整批汇总；明确输入输出形状。
- 执行策略：按依赖就绪执行，逐项实例和独立路径允许有限并发；并发度不改变数据类型。

借鉴 Java 的 Function<T,R>、Predicate<T> 与 Stream<T> 的组合语义。T、R 表示业务数据类型，跨节点由 JSON Schema 描述。Stream<T> 在本应用仅类比“端口中的有限 T 集合”，不照搬 Java 的惰性执行、单次消费或线程池；分叉复用同一份固定上游结果。

| 操作 | 单次处理签名 | 端口数据变化 | 例子 |
| --- | --- | --- | --- |
| 逐项转换 map | T → R | T 集合 → R 集合 | 每条反馈生成一份分类结果 |
| 集合展开 flatMap | T → R[] | T 集合 → 展开的 R 集合 | 每篇文档提取多个问题 |
| 筛选 filter | T → boolean | T 集合 → T 子集 | 只保留主要分类为问题的反馈 |
| 整批汇总 aggregate | T[] → R | T 集合 → 一项 R | 多条分类结果生成一份报告 |
| 归约 reduce | (A, T) → A | T 集合 → 累积结果 A | 数量、分数求和等确定性计算 |

上述表格用于定义语义，并非要求立即实现完整 Stream API。先完成当前逐项分类与整批报告的类型契约及有限并发；flatMap/filter 按具体故事接入，reduce 只为确有用途的确定性处理提供。

map 返回一个数组时，结果是“一项数组值”；只有显式 flatMap 才展开。汇合 merge 是集合拼接，不等于按键 join 或 reduce。条件分流将材料路由到匹配/不匹配端口；并行分叉将同一输入交给不同任务，两者不可混用。

LLM 汇总不保证结合律或确定性，不能悄悄拆成树形并行归约。若需要分块总结，显式画出分块、逐块总结、最终汇总三个步骤，并重新评价结果质量。空输入的行为属于操作契约：map/flatMap 零调用；reduce 使用明确初始值或空结果规则；aggregate 需明确允许空集合还是提示无法生成报告。

## Schema 贯穿连接与执行

每个端口声明单项业务值的 schema，执行模式决定单次调用拿到 T 还是 T[]。单次返回结构与输出端口单项结构要明确对应，尤其是 flatMap 的 R[] 与 R。运行器来源编号、实例 ID、状态保留在记录外层，不要求模型手动构造运行记录。

沿用 JSON Schema 作为一个事实来源：驱动输入输出检查、模型结果要求、配置面板和样本查看。运行时校验优先复用 Ajv 等成熟库；具体方言和支持关键字需在接入时固定，未知关键字不能静默变成“已验证”。不继续扩展手写通用校验器，不额外建设 schema 注册平台。

1. **定义阶段**：校验 schema 本身；普通函数提供已知的输入输出契约，Agent 由用户/Agent 提出结果字段并保存到定义版本。
2. **连接阶段**：在明确支持的简单 schema 范围内检查上游输出是否满足下游输入，包括字段类型、必填保证、枚举和可空性。不能证明兼容时提示未确定，允许保存草稿，补全契约后才能声称可运行；不承诺任意 JSON Schema 的静态包含关系求解。
3. **执行阶段**：调用前检查实际输入，调用后检查实际输出；Agent 和普通函数同样适用。错误显示样本和字段路径，例如“第 2 条结果的 category 必须为 问题/需求/称赞”。失败不以 null 冒充成功；保留已有成功结果，依赖完整结果的汇总等待或阻断。
4. **变更阶段**：schema 是定义语义的一部分，修改后形成候选并使相关旧比较失效；旧运行按原 schema 展示，不用当前 schema 重解释历史结果。旧工作缺 schema 时明确标识待补全，不能伪造推断成功。

输入输出字段名称可通过样本辅助生成，但一个样本不保证必填、枚举或所有可能类型；推断结果在完成确认前是候选。

## 画布与用户操作

节点端口显示简短业务类型，例如“反馈 → 分类结果”；节点摘要显示“逐项 · 并发 4”或“整批汇总”。选中后查看字段表（名称、类型、必填、说明）和实际样本；高级 JSON Schema 按需展开。用户通过字段和样本理解连接，不需要编辑 JS 或 Java 泛型。

例如：反馈集合 → 逐项分类（反馈 → 分类结果）→ 整批生成报告（分类结果[] → Markdown 文本）。若分类 Agent 实际返回任意字符串，校验在分类实例失败处终止该输出进入下游，并给出可改字段或任务的入口。

## 最小验收反例

以下均为待实现/待验收，补充用户故事 B1/B2/B4、C1/C3、D1、E4。

- 正常三条反馈各输出符合 schema 的分类，汇总只接收三个已验证结果。
- 第二条缺必填 category 或返回字符串：定位该实例和字段，其它成功结果保留，完整汇总不执行。
- map 返回两个标签组成的数组时仍是一项；显式 flatMap 后才成为两个实例，来源都可追到原材料；空数组产生零项。
- 数字输出接到对象输入，在连线处提示冲突；输出字段可缺省但下游要求必填，也不能判为兼容。
- 两个输入耗时不同，实际并发计数大于 1 且不超过限制；结果按输入身份和顺序收集，停止后不启动等待任务。
- 同一输入分叉到两个独立任务均可执行，汇合等待双方；条件分流的空支路不导致挂起。
- 修改输出 schema 后旧比较过期；旧报告仍按原定义读取。
