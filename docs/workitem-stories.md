## 一、业务身份与目标

**H1 登记可持续追踪的工作项。** 管理者创建“CVE 示例 / 产品 A”的工作项，填写业务编号、目标、完成条件与证据材料，选择处理方法。另一项 CVE 可以使用同一方法；工作项拥有独立身份、材料和进展。CVE 只是验收内容，字段与阶段不得硬编码为漏洞专用逻辑。

**H2 取得业务进展总览。** 工作项页展示全部、未完成、已结项及待推进/推进中/等待中/需处理的全局数量，点击可筛选列表；搜索与分页不缩小全局统计口径。未完成包含所有未结项的事项，不只包含尚未开始的事项。列表支持搜索、状态筛选，展示阶段、进展摘要、等待原因、下次触发时间、最后业务进展时间和执行状态；详情集中展示实际活动步骤、最近成果及来源、业务阻碍和下一步，能进入证据、运行记录及对应流程。Run 成功但未结项与尚未执行可区分；不能用节点完成百分比代替业务完成情况。详情中的轮次/环节/实例选择、成果检查/比较/使用和来源返回见 [工作项工作空间](workitem-workspace.md)。进度增量的实现与本轮证据见 [工作项进度 track](../conductor/tracks/workitem-progress_20261021/index.md)。

## 二、执行与业务影响

**H3 按固定方法推进工作项。** 发起运行记录工作项输入快照和方法版本；中途追加证据或修改流程不改变旧运行；本轮工作项目标在创建时确定，不提供目标编辑入口。业务里程碑是显式 IR 节点，能够记录阶段、摘要和输入证据引用。Run 成功结束后，工作项仍可未完成。

**H4 区分试验与正式推进。** 单节点试运行与候选比较不得写工作项业务状态。正式工作项运行才允许提交里程碑；重复恢复同一个里程碑不会重复产生进展记录。

正式 full/commit 工作项的普通执行 Agent 还可通过 `report_progress` 报告阶段、摘要、下一步、业务阻碍和本项材料引用，无需先配置里程碑。报告记录来源与历史，仅表示 Agent 已报告，不自动确认完成条件或结项；即使随后输出校验失败，报告与执行失败也须分别可见。作者、动态规划、试运行、比较和 preview 不提供业务写入工具；重复报告不重复记账，停止或旧运行的迟到报告不得覆盖当前进展。业务阻碍不是持久等待，不自动停止或唤醒执行。

**H5 并行处理独立材料。** 逐项节点可设置有限并发，结果按输入顺序和来源关联；一项失败保留其它成功结果，依赖完整集合的下游阻断。输出 schema 是实际校验，不合格输出不能成为业务进展依据。

## 三、跨时间等待与继续

**H6 等待外部消息或到期。** 等待节点配置事件名称、原因和可选截止时间。进入等待后释放执行资源，管理者能看见等待什么；可通过界面或 HTTP 提交匹配事件继续同一次运行，错误事件不唤醒，事件 ID 在整个工作项及其跨方法历史内去重，旧消息不唤醒下一次运行。事件和接收时间可查。

**H7 重启后恢复等待。** 在等待状态关闭服务、重开，原运行仍在等待；已完成 Agent 不重复调用。离线期间到期的等待在启动后继续。域内以可控时间证明跨 45 天及长定时器分段语义，真实服务以短截止时间和进程重启证明恢复，不能用延时动画冒充持久等待。

**H8 如实处理中断与停止。** 活跃外部调用期间重启，已完成节点保留，未确定调用标记中断并允许显式恢复；不声称未知外部动作恰好一次。停止等待后，迟到事件和定时器不再推动后续里程碑。

## 四、方法演进与业务完成

**H9 用新证据和新方法继续原工作项。** 追加公告材料并修改/采用新方法，原工作项发起新运行；旧结果、版本、阶段历史仍可查。切换到另一个方法工作空间也保持同一个工作项 ID；活跃/等待运行期间不允许悄悄换方法。

**H10 按业务条件结项与重新打开。** 完成条件逐条记录满足情况及依据；有未满足条件时阻止结项。运行 completed 不自动结项。新证据推翻结论时可重开，保留此前结项记录。

**H11 从应用外观察和推动。** HTTP 按工作项 ID 或业务编号查询当前状态、关联运行与历史，列表返回全局数量汇总；可提交带事件 ID 的外部消息。外部进展记录复用工作项 actions 接口，提供报告 ID 和当前 revision，无运行来源的记录仅可在无未决运行时提交，显示为外部报告；来源运行须校验属于当前正式执行。观察无需抓页面或解析 Chat；仅查询不能启动运行或修改业务状态。

## 产品验收路线

L1：创建两个工作项共用一套方法 → 分别推进 → 管理总览准确且输入不串。
L2：取得阶段成果 → 等待事件 → 重启服务 → 补充公告/发送事件 → 同一次运行继续，已完成步骤不重跑。
L3：跨截止时间与离线重启 → 自动继续；另一项停止后事件不能唤醒。
L4：输出不合 schema → 正式进展不提交 → 修复方法/试验 → 用新证据重跑原工作项，旧记录不改写。
L5：确认完成条件及依据 → 结项 → 新证据到达后重开；外部 HTTP 看到一致状态。

不扩展权限、多租户、分布式部署、任意代码恢复、完整 BPMN、自动业务判断规则平台。目标是否满足由明示完成条件和证据决定，不采用节点计数或关键词分类。测试替身、真实模型调用、真实重启与浏览器分别报告。


## 分治、交接与整体确认

2026-10-23：在 H1–H11 / L1–L5 的生命周期上增加六条连续故事，详细输入、反例与页面验收见[分治故事](../conductor/tracks/feature-workitem-decomposition_20261023/acceptance.md)，实际结果见该track证据。

1. 先登记一个问题；调查发现两个独立范围后添加子项，带入各自线索。进入子项补充、返回父项，草稿和浏览位置保留。
2. 把报告交给整理方法；在候选清单修改真实有问题的条目，一次建立选中项。重复发现显示已有项，补充新材料由用户明确触发。
3. 已有结论的子项直接检查并确认；缺版本的子项只补对应结构化字段，再使用已有方法继续，旧成果和旧输入不改写。
4. 在方法中配置“建立子项”；试运行展示候选，正式运行保存子项与入口。部分失败只补建未成功项，父运行不替用户递归运行所有子项。
5. 季度范围有上千叶子项时，从范围待办筛选需要补材料的仓库，进入处理后返回原筛选；批量选一次方法，只处理确实缺输入的项。
6. 子项确认后直接检查整体依据并完成，需要报告才另行汇总。重开或移出范围保留旧确认与原因，不能以运行成功替代业务完成。

用户不需预先选择聚合/执行类型、填写父项ID或输出端口，也不需为取得子项身份重跑已完成的调查。是否合理以这些操作能否连贯完成为准。

7. 批次有 20 个尚未结项的 CVE 子项，每项已有阶段成果。父项从“使用子项成果继续处理”选择各项的具体轮次和产物，保留业务身份与原始 JSON，交给后续分类、补证或处理方法。某项断点续做只覆盖剩余目标时，可以合并旧轮次有效成果；明确未选项后也可以先处理部分子项。生成方法和选择已有方法使用同一份来源选择。阶段接续不确认完成条件，父项最终结项仍遵循原范围约束。

8. 管理者打开整批事项，直接得到本轮整体成果：每项原判断、依据及剩余工作。对确认需处理的记录整体推进，或选取部分记录进入后续方法；已有源码排除依据但仍缺扫描/部署事实的记录继续保留补证工作。同一记录可以需要处理和补证，不通过增加业务层级分派执行分支。阶段成果可以连续传递，人工验收与最终结项仍独立进行。


9. 新建一件事时只提供需求和文件。用户在页面直接对Assistant表达处理意图；Assistant读取材料和方法目录，将输入整理、集合变换与固定方法调用组成可检查的流程，实际执行并声明所需成果表格/报告。用户选择真实记录继续，必要时才建立独立子项；按真实依据核对条件。流程稳定后保存为公用方法及视图模板，第二件事以自己的材料复用。当前实施和分层验收见[工作项组合计划](../conductor/tracks/workitem-composition_20261028/plan.md)，不是新增业务状态机或任意UI编程平台。

## 界面安排共编

用户已有一批输入及固定方法交付时，可进入界面安排，读出数据输出、列表/分组、详情和业务动作之间的引用。用户修改一个字段标签后，原成果按新展示呈现，输入、方法、运行与条件不改变。选中具名详情与同一Assistant协作增加已有依据字段，未涉及视图保持；用户选择和草稿不因展示编辑或后台更新丢失。错误与版本冲突留在编辑任务中，实际结项仍按H1–H11及L5要求。具体合同见workitem-ui-authoring，当前验证以track为准。

## 同一工作项的会话与可见下一步

用户在工作项内新建会话讨论另一种处理意图，材料、方法、界面、成果及完成条件仍在；新会话不带旧聊天，原会话可以继续，切换或刷新不丢当前标签页内的草稿。一个会话回复时可查看其它历史，回复仍落在原处。

成果发布后，页面继续呈现当前方案能判定的待办和就近入口，用户补信息、运行并更新成果，旧成果标为此前。方法变化而界面尚未同步时有明确完善入口；操作请求进入当前会话。用户最终引用依据、逐项确认并主动结项，运行成功或模型回复不会代替该确认。当前分层证据见workitem-composition track的closure-and-conversations。
