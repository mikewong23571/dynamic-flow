# 持续推进业务工作：用户故事与验收

2026-09-20，新基线。第一批材料加工故事继续回归，但不能代表本组生命周期已经通过。本组已实现；分路线证据与适用边界见 [生命周期验收](../conductor/tracks/workitem-lifecycle_20260920/evidence.md)。

## 一、业务身份与目标

**H1 登记可持续追踪的工作项。** 管理者创建“CVE 示例 / 产品 A”的工作项，填写业务编号、目标、完成条件与证据材料，选择处理方法。另一项 CVE 可以使用同一方法；工作项拥有独立身份、材料和进展。CVE 只是验收内容，字段与阶段不得硬编码为漏洞专用逻辑。

**H2 取得业务进展总览。** 列表支持搜索、状态筛选，展示阶段、进展摘要、等待原因、下次触发时间、最后业务进展时间和执行状态；能进入证据、运行记录及对应流程。不能用节点完成百分比代替业务完成情况。

## 二、执行与业务影响

**H3 按固定方法推进工作项。** 发起运行记录工作项输入快照和方法版本；中途追加证据或修改流程不改变旧运行；本轮工作项目标在创建时确定，不提供目标编辑入口。业务里程碑是显式 IR 节点，能够记录阶段、摘要和输入证据引用。Run 成功结束后，工作项仍可未完成。

**H4 区分试验与正式推进。** 单节点试运行与候选比较不得写工作项业务状态。正式工作项运行才允许提交里程碑；重复恢复同一个里程碑不会重复产生进展记录。

**H5 并行处理独立材料。** 逐项节点可设置有限并发，结果按输入顺序和来源关联；一项失败保留其它成功结果，依赖完整集合的下游阻断。输出 schema 是实际校验，不合格输出不能成为业务进展依据。

## 三、跨时间等待与继续

**H6 等待外部消息或到期。** 等待节点配置事件名称、原因和可选截止时间。进入等待后释放执行资源，管理者能看见等待什么；可通过界面或 HTTP 提交匹配事件继续同一次运行，错误事件不唤醒，事件 ID 在整个工作项及其跨方法历史内去重，旧消息不唤醒下一次运行。事件和接收时间可查。

**H7 重启后恢复等待。** 在等待状态关闭服务、重开，原运行仍在等待；已完成 Agent 不重复调用。离线期间到期的等待在启动后继续。域内以可控时间证明跨 45 天及长定时器分段语义，真实服务以短截止时间和进程重启证明恢复，不能用延时动画冒充持久等待。

**H8 如实处理中断与停止。** 活跃外部调用期间重启，已完成节点保留，未确定调用标记中断并允许显式恢复；不声称未知外部动作恰好一次。停止等待后，迟到事件和定时器不再推动后续里程碑。

## 四、方法演进与业务完成

**H9 用新证据和新方法继续原工作项。** 追加公告材料并修改/采用新方法，原工作项发起新运行；旧结果、版本、阶段历史仍可查。切换到另一个方法工作空间也保持同一个工作项 ID；活跃/等待运行期间不允许悄悄换方法。

**H10 按业务条件结项与重新打开。** 完成条件逐条记录满足情况及依据；有未满足条件时阻止结项。运行 completed 不自动结项。新证据推翻结论时可重开，保留此前结项记录。

**H11 从应用外观察和推动。** HTTP 按工作项 ID 或业务编号查询当前状态、关联运行与历史，提交带事件 ID 的外部消息。观察无需抓页面或解析 Chat；仅查询不能启动运行或修改业务状态。

## 产品验收路线

L1：创建两个工作项共用一套方法 → 分别推进 → 管理总览准确且输入不串。
L2：取得阶段成果 → 等待事件 → 重启服务 → 补充公告/发送事件 → 同一次运行继续，已完成步骤不重跑。
L3：跨截止时间与离线重启 → 自动继续；另一项停止后事件不能唤醒。
L4：输出不合 schema → 正式进展不提交 → 修复方法/试验 → 用新证据重跑原工作项，旧记录不改写。
L5：确认完成条件及依据 → 结项 → 新证据到达后重开；外部 HTTP 看到一致状态。

不扩展权限、多租户、分布式部署、任意代码恢复、完整 BPMN、自动业务判断规则平台。目标是否满足由明示完成条件和证据决定，不采用节点计数或关键词分类。测试替身、真实模型调用、真实重启与浏览器分别报告。
