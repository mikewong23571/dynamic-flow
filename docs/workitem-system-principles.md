# 工作项系统准则

本文件定义系统建立者与工作项Assistant的责任边界。实际给模型的文本在src/server/assistant/workitem.ts的workItemSystemPrinciples，每轮位于systemPrompt最前；describe_capabilities返回同一文本。此处说明责任及机制，不另建规则引擎。

## 系统预设什么

系统预设稳定的业务对象与能力：工作项身份和历史、材料及来源、保存方法及真实执行、阶段产物和固定成果、用户交互及人工条件确认。应用维护这些事实和操作语义，不预设具体业务的字段、页面和处理顺序。

Assistant阅读本项目标、材料和进展，决定具体问题如何处理、用户需要了解和参与什么，再用实际能力建立方法与界面。OpenUI只是这套能力的描述和展示实现，assistant-ui负责聊天。

## 高层准则与机制

| 准则 | 系统承担 | Assistant承担 |
| --- | --- | --- |
| 以持续业务目标为中心 | 保持WorkItem身份，区分方法和一次Run | 选择足够聚焦的步骤；仅在存在独立业务责任时拆子项 |
| 事实唯一、职责清楚 | 保存输入/运行/来源，冻结历史；提供明确命令 | 从事实推理；业务处理进入方法，界面可按事实筛选/汇总并组织阅读与参与，不用聊天/界面变量制造事实 |
| 具体业务自主组织 | 提供可组合的读取、展示和动作能力 | 按当前工作决定数据、名称、呈现、操作；不照搬存储结构，也不为覆盖组件而堆页面 |
| 推进可感知、可参与 | 提供实际进展/产物及可调用业务动作，固定检查入口可达 | 把方法与观察/参与方式一起设计，让用户理解情况并在相关上下文行动 |
| 动作与结果闭环 | 命令验证修订/来源/前提，回执呈现失败与冲突；只读无写入 | 遵循已有授权，确认实际影响，诚实保留失败/等待/缺口 |
| 成果与业务完成分开 | 固定成果保留来源，完成条件和人确认分开持久化 | 不将生成界面、运行成功或发布当结项；未知不猜，能力不足明确说明 |

准则不要求所有工作展示一套状态卡、指标、表格或标签页，也不要求每次补充都新造流程。它约束业务语义和工作质量，具体阅读/操作组织交给Assistant。

## 怎样落到实现

系统提示给出准则和对象边界；describe_capabilities给出当前可用工具、IR与组件合同；业务服务保证命令前提和事实；Renderer承接程序。不能只写准则而让底层组件强制另一套流程，也不能为了实现某个页面把领域判断写回应用。

当前已接入准则文本及工具返回；2026-11-02对齐基础组合/就近任务/显式工具及外壳职责，实际证据见当前track的evidence/page-capabilities。机制实现不保证模型首版的界面质量。资料核对场景用于发现能力/约束是否合适，不作为先手写再要求模型模仿的标准页面。后续先检查系统边界是否足够，再让Assistant用真实工作组织方法和界面，并从实际使用结果修正系统。
