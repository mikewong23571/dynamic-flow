# 工作项中的成果检查与业务推进

当前性说明（2026-10-29）：本文保留早期工作项方案及来源/业务边界。下文旧页签、默认落点和返回布局不再作为界面结构要求；当前结构见[界面安排共编](workitem-ui-authoring.md)与[track实施记录](../conductor/tracks/workitem-composition_20261028/index.md)。访问和恢复以[新合同](task-navigation-contract.md)为准，导航改造与当前验收见[独立track](../conductor/tracks/feature-task-navigation_20261029/index.md)。

工作项详情承载同一件业务的持续处理。用户在工作项内选择轮次、环节和成果，查看输入与来源、比较实际输出，再把明确选择的成果用于证据或完成条件。更换处理方法后，旧轮次与成果仍属于原工作项。

## 默认看什么

页头保持工作项名称、业务状态和当前可用动作。下方直接展示实际执行位置、完整的业务阻碍与下一步，阻碍以细黄线强调，正文不折叠或截断。来源与时间作为元信息展示；“查看依据”在右侧打开报告详情，“查看工作目标”打开完整目标，方法查看与调整集中在“处理方案”页签。Agent 报告与实际产物分别呈现，报告保存不意味着产物已成功生成。

只有与当前阻碍及下一步对应的真实报告才提供来源入口。依据面板展示该报告的时间、来源、完整内容和引用材料；有材料引用时提供“查看相关材料”，可直接检查引用的实际材料；有固定运行来源时，可定位对应运行、环节和实例，并沿已有路径返回原视图。不根据报告文字推测子项或生成操作入口。打开面板后固定所选报告，后续轮询即使更新或清除当前阻碍，也不替换正在检查的报告；关闭后返回入口焦点，原入口已消失时返回推进概览。

父项存在当前范围内的直属子项时，推进概览显示子项总数、已结项、推进中及实际等待/需处理数量。父项没有直接执行时不显示“尚未执行”来概括整批工作；父项存在自己的执行时，单独标为“本项执行”，与子项进展并列保留。子项数量使用全范围统计，运行成功不自动计为业务结项。读取失败时明确显示失败并保留上次数据，不推断为没有子项。

内容分为子项、处理方案、成果与过程、证据材料、验收与结项、业务记录。默认进入成果与过程；有子项且没有已保存浏览位置时按现有规则进入子项，不要求先阅读历史或填写表单。

子项区域将标题和“添加子项 / 汇总成果”放在上行，搜索与范围筛选放在下行；范围与待办类型成组，控件高度一致并与列表边缘对齐。窄窗口下筛选组整体换到搜索下方，避免整页工具栏内边距造成嵌套缩进。

## 人工验收与结项

完成条件仍是工作项已有的业务数据，集中在“验收与结项”页签中编辑、引用成果、补充依据和保存。页签用验收图标与状态徽标标明确认进度；计为已确认的条件必须同时勾选满足并填写依据，不把执行成功当作验收通过。

推进概览固定显示人工验收待办，依次反映未保存修改、待核对条件、未结项子项、缺少验收条件和未结束执行。全部已保存条件有依据、范围内子项均已结项且当前执行已结束后，入口显示“检查并结项”。点击只进入验收页，不提交结项；进入后入口位置改为下方操作提示，保持页面结构稳定，避免重复导航。最终“结项”仍需用户在验收页明确点击，实际业务校验由服务端负责。尚未读到子项范围时不允许结项；有独立条件的父项也必须等范围内子项完成。

无独立条件且有子项的父项显示子项结项进度，最后由用户整体验收。已有工作项、完成条件、子项汇总与运行状态直接决定展示，不增加验收实体或持久状态。成果菜单中的“用于完成条件”等上下文动作保持原含义。

## 处理方案初步原型

详情右上角始终提供“查看处理方案”。点击该入口或手动切换页签只替换下方内容，不强制滚动，也不根据另一页签的旧阅读位置跳转；业务阻碍、下一步与报告来源保持在共享背景区。查看运行来源、返回原视图及父子导航仍保留既有的显式定位与阅读位置交接。“处理方案”直接投影已有方法或子项安排，没有独立的方案实体或存储。

父项已有子项时，方案展示“通过 N 个子项推进”、全范围推进汇总及分页分工表，逐项显示标题、编号、阶段、实际关联方法和业务状态。可以进入子项或查看真实方法，也可转到子项管理；人工验收使用共享背景区的待办入口。父项没有自己的流水线时，不再提示整项“尚未设置处理方法”；父项另有自己的方法时，与子项分工分开展示。移出范围的子项不计入当前汇总，未关联方法的子项独立标明；分页不缩小汇总口径，轮询尽量保持当前页已有行的位置，父子返回保留方案分页。

当前项有自己的方法时，方案展示方法名称、已有的问题认知、已知/未知、约束和依据，以及步骤的职责、安排理由、完成要求、后续关系和预期成果。未填写的语义字段不补写内容，节点排列不表示执行顺序，依赖关系以实际连接呈现。

默认查看流水线当前采用的版本，未采用时查看候选草稿；两者并存时可以切换查看。切换预览不采用版本，也不修改本轮输入。“编辑处理方案”进入现有画布；另有候选时明确标为“编辑候选做法”。编辑入口绑定当前工作项上下文，不自动选择证据、调用模型或改变流水线样例。保存后返回工作项，重新读取已保存做法；候选预览跟随新的候选版本，已采用版本保持原样。

“准备本轮输入”复用现有运行准备界面，版本、输入和范围仍需明确选择；“选择/更换处理方法”和“生成处理方法/新方法”复用既有流程。未设置方法、尚无步骤和读取失败均显示真实状态，失败可重试。原型在进入页签及从画布返回时刷新，不增加实时订阅或新的执行状态。

来源按固定方法、轮次和节点分组，同节点不同实例显示独立序号；大量上游实例和原始材料按需展开，展开后能检查实际标量预览并进入精确结果。固定输入以“第 N 项”区分，展开后显示继承的材料编号及实际内容，避免用相同的全量材料编号充当每个输入的标题。历史运行的粗粒度来源保持原样，不倒推或重写证据。

## 可读材料卡片

材料页、输入选择、报告引用和运行来源使用统一紧凑卡片：实际名称/仓库分支、两行内容摘要、次要引用编号、查看正文。宽区域按可用空间排列卡片，窄对话框保持单列；标题与摘要各保留两行，卡片等高，操作按钮对齐。点击“查看材料”使用统一材料阅读器检查正文，卡片不再页内展开，打开和关闭弹窗不改变背景卡片的位置、尺寸与阅读位置。阅读器外框固定为随视口收缩的960×720，标题/引用编号/字符数与查看方式工具栏固定，仅正文滚动；查看内容和原始数据各保留阅读位置。两种视图切换不改变弹窗框架，原始数据保留保存时的完整text，不重新格式化。内容与原文使用相同的左右边界和顶部起点；弹窗内文本不额外居中限宽，结构化首行不重复增加内边距。历史及报告引用也使用相同阅读器。关闭后返回原按钮焦点；在准备执行中打开材料详情也保留原材料选择。从详情进入引用来源会先关闭弹窗。选择框用可读名称与引用编号共同标识，不改变选择值或来源。旧文本材料用首行作为标题；已有JSON材料仅解析展示已有字段，完整对象使用现有结构化阅读器检查，不根据材料内容自动判定重要性或证据成立。

历史轮次默认只显示“本轮新增材料 · N 项”或“初始材料 · N 项”，展开后才构建卡片。轮次没有业务报告但已有成果时提示实际保留成果数量，不要求用户先检查材料。运行来源卡片使用固定快照；材料正文、业务引用和旧运行均保持原样。本轮是展示修正，未新增持久材料名称字段或编辑接口。

## 选择与检查成果

- 轮次以处理方法、开始时间和实际运行状态区分；取消的旧运行可直接识别。
- 环节卡片保持相同高度，标题顶对齐并保留两行空间，状态与成果标记位于同一底行。页面、执行容器、内容区使用统一主题的不同表面与边框，选中项使用蓝色背景和边框。环节使用固定定义中的业务名称，显示执行状态。声明为最终输出的环节标记“成果”；中间环节的输出同样可检查。
- 初次打开一轮时优先展示已经产生的最终成果；尚无最终成果时展示最近已完成环节，仍可点击当前执行位置检查活动环节。用户选定环节后不随新输出自动跳走。
- 一次检查一个环节实例。多条输入或多轮迭代可切换实例；明确指定的实例不存在时显示缺失，不替换为另一个结果。
- 未查看的标签页、折叠正文和工具内容在首次访问时才渲染，访问后保留检查状态。对象按字段组织，嵌套内容与长正文按需展开；集合每页 50 项，可查找全部条目、排序和打开条目；文本报告支持 Markdown；原始数据始终可查看。界面不猜测业务结论，也不绑定某一种流水线的字段。

## 追溯与返回

“输入与依据”显示该实例的固定输入，提供可点击的实际上游结果与材料引用。沿上游查看后可以返回原成果；已检查实例的标签页、展开内容和集合操作状态在本次工作项浏览中保留。

业务记录按每轮推进组织，显示固定输入与成果数量、相对上一轮新增的材料，并提供直接检查成果的入口。同一环节默认展示最近一条报告，更早报告按需展开；完整报告、条件快照与材料/方法/结项变更仍可查。从报告进入时定位它所属的固定运行、环节与实例，返回业务记录恢复阅读位置。

需要进入流水线工作区时，界面提供“在流水线中查看”，交接当前固定运行、环节及具体实例，并保留“返回工作项”。返回后保留工作项选择、所选成果、阅读位置和未保存的完成条件；离开工作项时停止其页面轮询。刷新整个应用不持久化这些临时浏览状态。

## 比较和使用成果

可以选择两份成果比较，包括同一工作项不同轮次或不同方法的成果。比较展示实际字段路径和值的差异，数组按原顺序对应；不自动判断哪份更正确或推断业务意义。

“补充为证据”在确认后，将所选实例的实际输出与来源作为一条新材料保存；旧 Run 不变。“用于完成条件”先选择目标条件，再引用该成果；用户自行确认内容、勾选满足并保存。两种动作都不自动结项。

执行中、等待、失败、取消、没有产物与读取失败分别显示。读取失败保留已取得内容并提供重试，不伪装成空结果或业务成功。

## 验证边界

最初实现与截图见 [工作项工作空间任务记录](../conductor/tracks/workitem-workspace_20261022/evidence.md)。结构化采购条目、文本周报、合同来件验证共同交互；真实 CVE 工作项提供现有模型产物的只读实看。界面行为验证与真实模型业务结论分别报告。

## 共享的运行检查

流水线运行结果与工作项成果使用相同的固定Run检查核心：实际参与的环节、执行实例、产物、固定输入与来源、执行记录。普通无工作项试验也使用此核心，不制造业务身份。当前Definition画布/Assistant仍用于编辑方法，不能替代历史Run的固定定义。

外层动作按上下文保留：工作项可补充证据、引用完成条件、比较成果；方法可选择/保留结果、用所选结果续做、重试、从结果改进及固化实际动态展开。“比较做法”对齐固定同输入两侧结果，“比较成果”检查已选成果的实际字段差异，两者不混同。复制单份文本得到原文，单份对象得到JSON，多份产物保留具名结构；业务补充证据的来源结构不变。

共享核心及最新状态/性能验证见[设计治理验收](../conductor/tracks/ui-design-consistency_20261022/evidence.md)。

“输入与依据”还可查看该Run冻结的运行依据（目标、事实、待确认、约束、来源）与所选环节要求。两入口使用相同的按需查看路径，后续编辑不会覆盖历史字段。动态节点直接通过实际环节导航检查；方法侧“保存为候选做法”保留原固化动作，主面不重复展开节点说明或连接文字串。

## 准备本次处理

工作项可先保存目标和材料，编号自动生成、方法与完成条件后补。运行流水线打开准备界面，明确方法、保存版本、实际材料/历史成果及完整流程或静态普通单步。输入按真实端口分配，结构化成果直接交接且保留跨方法来源；不兼容时保留选择，可带输入编辑方法再返回。生成处理方法进入已有Assistant，由用户发送请求；作者上下文不变成共用方法样例。

方法结果页以Run为主体，关联工作项显示当前业务状态；成果页按显式最终输出项展示。工作项仍保留跨方法推进历史。条件可后补/修订，文字变更使旧确认失效；引用成果保存精确来源，结项与重开不改旧依据。

多份端口产物的查看方式与单份一致：产物区顶部只保留一套“查看内容 / 原始数据”，紧邻页签左对齐，控制各已展开条目的显示。每条产物展开后直接显示正文，不再单独占用一行右对齐工具栏；未展开条目继续延迟渲染，切换模式和页签保留原展开状态。

## 先看本轮结果，再检查过程

“成果与过程”默认展示本轮概览：按固定定义的显式 summaryOutput 展示标题、摘要、范围、指标、限制与建议，再按真实最终输出分组成果卡片。未声明摘要的旧运行保留分组入口，不把某个 JSON 对象或最后一个目标当作整体结论。“查看成果”进入相应环节/实例，“查看过程”进入共享 RunInspector；来源深链接继续精确定位，返回概览不丢弃已查看内容。

上方“最新执行”和“最近记录的进展”属于工作项当前上下文；报告显示其真实记录时间，不能把旧摘要当作实时计数。选中历史轮次会显示历史提示与“查看最新结果”。方案页说明当前采用/候选与所查看轮次固定版本之间的区别。业务成功执行但尚未验收的项显示待复核，执行中、失败后的主入口分别指向进度或失败环节；准备新一轮仍经过明确输入选择。

业务历史展示报告摘要、固定版本、完整流程或实际单步骤，以及本轮 inputSources 指向的来源轮次。成果数与概览共用 finalArtifacts，按真实输出条目计数并区分集合内记录数，不用 NodeResult 数量代替产物数。运行产物只是已生成，不等于用户已选择保留或验收。

摘要契约见 [当前设计](design.md#本轮结果摘要)，本次验收见 [结果概览证据](evidence/result-summary_20261026/README.md)。

## 复核以后做什么

待复核使用独立紫色与清单图标；列表、全局筛选、直属子项筛选、父项范围卡片及详情由服务端同一派生状态驱动。父项的“整批推进概览”集中展示六类真实数量，点击卡片只筛选该计数对应的直属范围；范围内待办继续是独立的跨层视图；待复核且有证据缺口的项仍可通过“需补材料”待办筛出，状态与具体下一步不混同。父项没有本项流水线时，主动作指向待复核子项，不再重复展示生成方法和选择方法。共享背景与范围概览跨页签保留，短页签留出阅读空间，避免内容缩短导致滚动上限改变、背景跳动。

在成果详情的“复核与跟进”选择引用验收依据、建立补证子项或建立整改子项。跟进弹窗显示实际原值字段，允许编辑标题、目标和完成条件；提交后提供原项/后续项之间的入口，外框在编辑和回执间保持固定尺寸。新子项带入原成果的精确来源及真实内容；原项未解决的范围内子项会在验收时明确阻塞结项。重复进入展示已有后续，不创建重复待办。具体业务约束见 [当前设计](design.md#待复核与后续问题闭环)。

历史轮次只对比真实方法、版本和新增材料，不推断业务因果；明确 inputSources 继续链接实际引用的运行。旧 JSON 进展报告显示为缺少业务说明的结构化历史记录，原文仍可在依据和历史详情查看；新的 reportProgress 拒绝仅含 JSON 对象/数组的摘要，要求填写业务说明，已有同 ID 原样重试仍保持幂等。

两条正式 CVE 模板均提供显式函数摘要，不增加模型格式化调用；内建剖析及历史示例仍保留既有产物合同，历史 Run 不回填新摘要。作者默认给业务处理方法提供显式 summaryOutput。

2026-10-27 复核入口修正：“复核与跟进”先打开包含实际成果预览的选择弹窗，明确选择引用依据、建立补证子项或建立整改子项。单击入口不执行默认选项，取消保留原环节/实例；引用验收依据也在当前成果中完成，不切到验收页。

## 逐项收集证据，最后统一验收

成果工具区提供“证据对应条件”与“加入验收证据”。多条件需要先明确选择，只有一个条件时直接选中；在实例之间保留这一选择。引用即时追加到已保存条件，显示当前成果已加入，可直接用上一项/下一项继续检查；取消复核弹窗、添加引用或保存失败都保留当前环节、实例、页签和阅读位置。复核选择弹窗的证据选项与普通引用菜单使用同一就地动作。

添加证据只收集原运行/实例/端口/条目引用和可读来源说明，不自动确认条件、不结项，也不自动跳到下一项。一个成果可分别引用到多个条件，同一来源对同一条件重复引用不增加记录。用户主动进入“验收与结项”后，再核对累积依据并确认整项条件。已有未保存的依据或勾选保留；条件文字本身已修改但未保存时，不把引用悄悄追加到不同含义的条件。

服务端使用 citeCriterion 追加最新条件，不由前端提交整份旧条件覆盖；并行引用合并、旧响应防倒灌、离开工作项后的迟到响应不抢导航。错误如实留在当前成果旁并可重试。当前交付证据见 [就地收集验收证据](evidence/cite-in-place_20261027/README.md)。
