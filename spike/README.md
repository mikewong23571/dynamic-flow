# 用户故事驱动的项目骨架 Spike

**这里全部是伪代码和实现说明，不是可运行应用。** 更新：2026-09-20。

目标：说明怎样用少量直接功能承载 [19 个用户故事](../docs/user-stories.md)，先把模块之间的输入、结果和状态闭环推演清楚。以这些故事作为本轮推演基线，不把讨论稿擅自扩大为已批准的新功能。已有 [组件实验](../examples/component-spike/README.md) 保留技术证据；本目录不复用其视觉方案。

## 阅读顺序

## 整个项目的目录框架

下面目录已实际创建。它代表未来应用的最小组织方式，先放在 spike 内供讨论，不把占位文件加入现有应用构建。

```text
spike/
  README.md                    全局设计、职责、非功能要求、待办
  interfaces.md                函数级输入输出与调用关系
  iterations.md                伪代码推演发现的问题及修订
  src/
    README.md                  如何把此骨架变成应用
    client/
      README.md                工作区组件待办与验收
      workspace.pseudo.md      完整用户交互伪代码
    server/
      README.md                后端组装、功能待办与验收
      work.pseudo.md           工作、材料、结果选择、报告
      flow.pseudo.md           编辑、校验、采用与放弃
      runs.pseudo.md           节点执行、停止、重试
      assistant.pseudo.md      Pi 调用、生成/修改、端点配置
      trials.pseudo.md         样本比较，复用同一运行路径
      files.pseudo.md          本地保存与重开
    shared/
      README.md                少量共享记录的使用方式
      records.pseudo.md        界面与后端衔接所需字段
  data/
    README.md                  将来生成的本地工作文件布局
  tests/
    README.md                  如何测试和怎样记录验收
    fixtures.md                材料与可控异常
    cases.md                   28 个 Given/When/Then 场景
    walkthroughs.md            19 个故事到 T1–T8 的闭环推演
```

没有生成空的 package.json、类、服务层、适配器层或成套测试框架。正式实现时沿用已经选定的 React/Vite + Hono + Pi + 组件库，把伪代码逐项替换为实际功能；是否拆成更多文件由真实代码大小决定。

## 各模块的功能

| 模块 | 必须承担的功能 | 直接依赖 | 关键故事 |
| --- | --- | --- | --- |
| client/workspace | 输入材料、画布编辑、节点检查、对话、比较、采用与续做；共用上下文 | 后端具体操作、React Flow、assistant-ui、shadcn/ui | A–F |
| server/work | 创建工作、追加材料、选择/保留结果、输入预览、报告读取 | files、runs | A1、D1/D2、F2/F3/F4 |
| server/flow | 同一草稿的编辑与问题提示；采用/放弃；布局另存 | files | B1/B2/B4、E1/E4、F1 |
| server/runs | 固定输入与定义；按依赖执行；逐项、分支、合并；停止、失败与重试 | flow、assistant、files | C1–C3、E2、F2/F3 |
| server/assistant | 根据目标生成/修改实际定义；调用 Pi 执行节点；按配置接入模型 | flow、files、Pi SDK | A2、B3、C2 |
| server/trials | 固定同一组样本顺序运行两边、对齐结果、判断比较过期 | runs、files | E1–E4 |
| server/files | 少量本地文件读写、保存失败反馈、重开状态、推送已保存状态 | Node 文件能力 | F4、各模块的保存行为 |

shared 只是一张数据字段清单，不是额外服务。后端是一个进程，文件间直接调用；一次工作只执行一条运行/比较链，先不做后台任务平台。用几个具体函数管理不可变定义和结果来源，是为了满足用户故事中的“知道跑了哪一版”和“只重试指定材料”。

## 非功能设计：只处理原型当下需要的约束

| 要求 | 具体做法 | 怎样判断 |
| --- | --- | --- |
| 容易理解和改动 | 文件以实际功能命名；直接调用；无基类、依赖注入、插件协议、通用存储接口 | 修改分类节点交互或停止行为时，能从故事编号找到负责文件及用例 |
| 用户友好与视觉一致 | 画布为主，共享选中上下文；专业控件有统一语义；实际参考成熟界面后设计代表页面 | T8 的真实操作、截图与用户反馈；不把本伪代码当视觉方案 |
| 长操作有反馈 | 模型与节点执行异步返回 ID，显示真实进度/停止中/失败；编辑不被模型等待锁住 | P07/P08/P23；不虚设毫秒 SLA，不把动画当真实进度 |
| 状态可信 | 运行固定版本和输入，比较检查是否过期，保存成功才确认，失败保留已完成结果 | P07–P09、P13–P19、P22 |
| 可以分次完成 | 本地保存目标、草稿、采用版、结果、比较和视图；重启如实标记中断 | P21；不实现任意调用栈恢复 |
| 模型可替换 | 协议、Base URL、模型名、Key 通过已有 .env.local 配置；简单分支复用 SDK | P24 对三种协议与自定义地址逐项实测，不预设供应商兼容性 |
| 控制实现与运行成本 | 单节点样本试验；每个工作顺序执行；普通转换直接用 JS；不做缓存和自动优化平台 | P14/P28；先记真实调用与样本数量，不先建计费/监控体系 |

安全、权限、隔离、生产可用性、多人协作不是本轮非功能设计内容。当前只按一个本地进程、小规模材料组织；遇到真实容量问题后再决定数据库或并发机制。

## 从骨架到应用的待办顺序

这些复选框是**未来实现待办**，不是本轮伪代码任务的完成标记。

- [ ] 第一条纵向路径：创建工作 → 生成流程 → 画布查看 → 两节点实际执行 → 报告读取/复制 → 保存重开（T1、T7 基本路径）。
- [ ] 可修改与可控制：画布增删/连线/配置、Assistant 实改定义、配置错误、逐项/条件空分支、停止与失败重试（T2、T4、T6）。
- [ ] 试验到采用：同输入单节点比较、过期提示、独立采用/保留、显式选结果续做（T3、T5）。
- [ ] 完整验收：三种协议真实接入、保存失败/断线/重启边界；在统一视觉的完整工作区复走 T1–T8，记录证据。

每条路径先用相关测试明确成败，再替换对应伪代码。不要先把所有“层”建好再串功能；也不要把用户故事改成开发者必须在终端拼命令才能完成的演示。

## 本轮结论的边界

已形成可讨论的目录框架、功能/非功能设计、函数接口、测试设计及修订后的闭环推演。文档结构和覆盖检查可以实际运行；28 个业务场景目前只是设计推演，真实模型、运行时、文件故障和浏览器体验都仍待实现验证。不存在“伪代码测试全绿，所以产品已通过”的结论。
