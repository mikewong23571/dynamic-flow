# 验收材料与可控条件

这些是测试输入设计，不是实际模型返回记录。

| ID | 文本 | 预期用途 |
| --- | --- | --- |
| F01 | 界面很顺手，但导出报告经常失败，影响交付。 | 混合反馈；新要求优先归为问题，保留正反依据 |
| F02 | 希望支持批量导出，逐条操作太慢。 | 需求；可控失败与重试 |
| F03 | 搜索比以前快很多，团队很满意。 | 称赞；防止修改误伤 |
| F04 | 筛选后页码错乱，希望尽快修复。 | 新一轮材料，不得混入旧结果 |

定义样例（均为伪代码描述）：

- d1：classify(each Agent) → report(all Agent)，报告引用反馈编号。
- d2：仅改变 classify 的任务，要求混合反馈优先归入问题并保留双方依据。
- d3：classify → branch(category equals 问题) → 两侧 select-fields → merge(left,right) → report；选择只有称赞的输入制造空分支。
- 错误草稿：缺失 task、连到未知端口、删除仍被引用节点、产生回连、条件字段不存在。

模型替身需要的行为：正常结构结果；工具调用后回复；延迟返回；收到 abort 后结束；abort 后仍迟到的成功回调；F02 抛错；缺少必需输出字段；生成不可用流程。只在测试中显式选择替身，产品不因配置错误自动切换。

人工/真实模型对照不要求字面文本一致：检查 F01 的处理要求、F03 不受误伤、输出引用确实来自给定材料。若初次已正确分类，测试补充依据质量等明确改进目标，不伪造模型误判。
