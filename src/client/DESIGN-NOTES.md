## 实看的参考与具体取舍

- [React Flow 官方自定义节点实例](https://reactflow.dev/examples/nodes/custom-node)：实际用 Chromium 加载完整交互实例，查看节点、分流连接、缩放与背景网格，截图 [reactflow-official-reference.png](evidence/reactflow-official-reference.png)。采用职责节点与具名 handle；运行实例置于结果视图，不在材料数量增长时复制节点。自定义端口展示业务名称，协议 handle 保持原名。
- [Linear 2026 界面演进](https://linear.app/now/behind-the-latest-design-refresh)：阅读其位置栏和视图栏区分、导航退后与内容优先的具体方案。采用稳定的工作标题/运行操作顶栏，下面独立流程/运行/比较切换；辅助面板不替代主任务视图。没有复制品牌色或整套界面。
- [Primer Button](https://primer.style/product/components/button/)：核对主次操作与状态语义。主要动作使用实色按钮，次要动作描边，低频轻操作无底；禁用、停止处理中、失败有文本表达。采用 Radix Dialog 处理焦点、标题、关闭与模态背景；统一基础控件。
- [assistant-ui ExternalStoreRuntime](https://www.assistant-ui.com/docs/runtimes/custom/external-store)：实际使用外部保存的消息和状态接入会话组件，模型调用由后端完成。无文字的运行态显示生成/修改进行中，工具与错误来自快照。

## 持续工作项（2026-09-20）

本轮以 [H1–H11 生命周期故事](../../docs/workitem-stories.md) 扩充，不将旧运行完成解释为业务结项。参考 [Geist Table](https://vercel.com/geist/table) 的可比较列、独立空状态与窄列日期，以及 [Geist Badge](https://vercel.com/geist/badge) 的短状态标签；查看已有 Geist 暗色画布截图后沿用同一色彩、按钮和边框。

- `WorkItems` 是独立管理入口，业务阶段/摘要、等待与执行、最近业务进展各自成列；搜索与业务状态过滤来自 HTTP。窄屏将最近进展时间靠近标题，避免隐藏业务信息。
- `WorkItemDetail` 将目标、进展、条件依据、材料、历史组织在主栏；方法、当前执行、固定版本和跨方法运行记录放辅助栏。完成条件在本地编辑，轮询不覆盖未保存内容；更新失败保留表单。等待展示事件与截止，不展示虚假百分比。
- `WorkItemDialogs` 复用 Radix 模态；创建不复制方法样例材料，工作项自己的材料随运行冻结。详情中的运行链接携带方法 ID 和运行 ID，在该方法快照就绪后选择对应运行。
- `NodeInspector` 支持 Map / FlatMap / Aggregate、并发、单次输入/输出 schema，以及等待/里程碑的明确配置；`WorkflowCanvas` 只呈现运算摘要、事件名称/阶段，详细任务留在 Inspector。
- `Results` 可查看工作项固定输入修订、等待释放方式、接收事件 ID / 时间 / payload。运行成功与工作项结项分别呈现。

域内 `tests/client.test.ts` 7 项通过，`pnpm typecheck:app` 通过。新增真实 HTTP 浏览器路线由整体 track 记录；该记录不将类型检查当作持久恢复或用户视觉验收。

### 状态语言与工作区内容保留（2026-10-22追加）

执行状态、工作项状态和做法状态经`components/ui.tsx`的Badge入口统一为Lucide图标与无边框文字。完成/停止/等待/失败各有固定图形与语义色，关键业务状态仍明确显示“已结项/待推进”；轮次紧凑状态使用同一图形，title和屏幕阅读文本保留状态名。成果、版本等普通元信息保持中性无框标签，不伪装执行状态。环节、画布及流水线库不再手写另一套圆点/边框pill。

流程/运行结果/比较首次访问后保留局部状态；inactive页签不接收新的父级快照渲染，激活时恢复最新内容。缓存按当前Work挂载身份隔离，不跨方法复用结果。运行检查复用同一环节/实例导航与产物/输入/执行记录结构，默认实际最终成果，过程环节可明确选择；未访问实例、折叠输入和工具正文按需构建，比较共用ArtifactValue的集合检查能力。纯Value渲染独立在`features/results/Value.tsx`，避免结果页与结构化阅读器循环依赖。

### 同一运行的两种上下文

工作项和流水线内检查同一个固定Run时，内部构图和数据不再两套：共用RunInspector/RunArtifact及RunInspector.css。工作项外层保持业务概览、材料、条件、轮次、记录与业务使用动作；方法外层保持运行选择、当前定义画布/Assistant、重试/候选/保留/续做与动态固化。方法页业务上下文以可读标题为主，编号次要，修订与正式/试验语义另组展示；不把当前定义编辑与历史运行合成同一页面。

工作项跳转交接完整环节和实例位置；上游沿实际来源定位。核心不依赖伪造WorkItem，单节点试验仅显示实际参与环节。状态以图标+文字保留含义，画布进度数字不替代真实状态（title与辅助文本仍显示已完成/运行中）。

### 运行检查中的依据与文案

主工作面直接呈现实际环节、实例、状态和产物。运行冻结目标/事实/约束通过共享“输入与依据”里的“运行依据”查看，复用Dialog按需挂载；当前定义后续编辑不会替换这些字段。“环节要求”在相同页签按需展示该固定环节的职责、完成条件和任务，没有字段时不造空入口。

实际动态节点由已有导航检查；“保存为候选做法”放在相应父责任或生成环节的方法动作区，仍走freezeExpansion协议。成果比较以“字段 / 位置”表头和title表达对齐口径，主体保留实际差异。不要再用“本次固定的问题认知”等实现说明、重复节点长列表或连接文字串替代界面组织；真实报告、错误和必要空态帮助保持真实。


### 结果任务的层级

方法结果每次运行一行，工作项作为关联；“仅看成果”按显式最终输出分组浏览。两处进入同一运行成果页：上方切换最终成果分组，组内选择具体项，下方阅读内容；单份直接阅读。分组导航、实例选择、内容头及查看方式直接复用过程页组件，仅删去中间节点、输入与执行记录；完整过程由RunInspector承载。当前业务状态与执行状态分列，业务轮次跨方法编号保持同一身份。

标题、页签和展开行已经表达层级，不再叠面包屑。每个详情只保留当前任务需要的返回入口；成果进入过程只返回原成果，列表返回保留查询、分页和阅读位置。结果/成果占主内容宽度，回流程恢复编辑面板草稿；不要为了全站布局复用挤窄表格。

### 持续工作准备与结果主体

准备执行把方法、保存版本、实际输入和处理范围放在同一任务中。材料采用短行/明确勾选和按需正文；成果按真实来源选择，合同失败保留选择并能进入编辑。作者请求使用一次性预填，不覆盖正常输入光标。方法运行表一行对应一次执行，工作项只作为关联；成果名称来自显式输出名，来源步骤单列，查看过程才进入共享检查器。条件先保存定义，再引用成果和确认；修改定义不能沿用旧确认。

### 信息获取与操作位置（成果分组追加）

运行表只呈现成果数量与查看入口，不在表格嵌套实例列表或选择弹层。同Run成果页复用RunSelection和ArtifactPresentation；多份只增加既有分组导航与实例菜单，不改成侧栏或另一套正文构图。名称来自冻结定义，未知技术键回退真实步骤名，不能按CVE字段猜名称。序号和实际标量预览帮助选择，复杂内容进详情；长标量截断显示而非直接过滤。来源、引用和比较沿用同一实例编号。

步骤以紧凑导航与统一状态图标呈现，不再逐步骤重复“已完成/成果”两层卡片；实例选择按需打开足宽菜单。独立成果标题/来源/动作组成一处，低频动作收纳到“更多”，不在正文前重复模式工具条。工作项状态一行呈现，完成条件直接可达，结项靠近条件保存；目标/方法按需Dialog，真实进展摘要保留在业务记录。轮次使用选择器，引用通过明确菜单，操作按钮短而有可见边界；这些控件表达任务，不用说明段落代替层级。

### 工作项拆分与整体检查（2026-10-23）

工作项不要求创建时选择类型。已有子项的首次页面以子项列表为主体，无子项时保持成果/开始处理；用户主动选择页签后，轮询不抢走位置。直属子项、跨层待办、排除视图共用现有 Table/ListToolbar/ListPagination，不做嵌套树表。纯结构父项的进展位置显示子项完成数，确认入口仍在同一业务位置。

候选清单是明确的批量建项任务：目标/范围可编辑，已有材料按需展开，建立回执提供真实子项入口；采用较宽的既有 Dialog，清单局部滚动，保存动作留在同一任务面。普通产物使用拆分动作，明确候选及建项回执使用建立子项动作，不把任意数组默认视作待办。

输入准备优先接续已收到的值，缺少结构字段时直接编辑声明的业务字段；追加证据仍单独处理。拆分和汇总具有明确任务意图与方法选择，生成方法复用 Assistant 的一次性上下文，不让用户理解端口或候选协议才能继续。成果与来源阅读继续复用原检查器，精确引用会展开对应产物。
